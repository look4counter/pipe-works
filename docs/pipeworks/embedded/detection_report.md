# 감지 성능 리포트

`YoloDetectReport`와 `TensorRTReport`는 감지 경로의 병목 구간을 같은 기준으로 출력하는 Step입니다. 감지 단계 뒤에 추가합니다. `CudaAsync`를 사용하면 Report는 래퍼 바깥에 둡니다.

```python
from pipeworks.embedded import CudaAsync, YoloDetect, YoloDetectReport, TensorRTReport

pipeline.step(CudaAsync(YoloDetect(model_path), timeout_ms=20))
pipeline.step(YoloDetectReport())

# TensorRT 전처리·추론·후처리를 쓰는 파이프라인
pipeline.step(CudaAsync(
    TensorRTPreProcess(),
    TensorRTInference(engine_path, batch=True),
    TensorRTPostProcess(),
    timeout_ms=20,
))
pipeline.step(TensorRTReport())
```

위 두 구성은 각각의 감지 경로 예시입니다. TensorRT 전후처리 클래스는 `examples/step`에 있습니다. 생성자에 별도 옵션은 없으며 매 1초와 종료 시 출력합니다. 입력이 정체되어도 주기 출력합니다. 같은 실행 안의 같은 종류 감지는 합산하고 서로 다른 파이프라인 실행은 분리합니다.

| 구간 | 의미 |
| --- | --- |
| 전처리 | NV12 → RGB, 리사이즈, 패딩, YOLO 내부 자료형 변환 |
| 배치 큐 대기 | 요청 등록부터 작업자의 배치 수집 완료까지 |
| 입력 동기화 | 입력 준비 이벤트의 대기 또는 대기 등록 |
| 입력 결합 | 배치 입력을 만드는 `cat` 또는 `stack` |
| 모델 준비 | 모델·엔진 생성 및 TensorRT 바인딩·출력 할당 준비 |
| 모델 실행 | YOLO predictor의 모델 호출 또는 TensorRT 엔진 실행, NMS 제외 |
| 후처리 | NMS, 좌표 복원, 결과 객체 생성 |
| 출력 복사 | TensorRT 배치 결과의 요청별 `clone` |
| GPU 완료 대기 | 기존 코드가 GPU 완료를 기다리는 CPU 시간 |
| 기타 실행 비용 | 전체 CPU 시간에서 위 구간의 CPU 시간 합계를 제외한 나머지 |
| 전체 | 감지 작업자 시작부터 결과 완료까지의 CPU 시간 |

각 구간은 직전 출력 이후 약 1초와 최근 10초의 평균을 ms로 출력합니다. `n`은 해당 평균의 표본 수입니다. 기록 없는 구간은 `없음`입니다. GPU 이벤트가 아직 완료되지 않았으면 CPU 표본만 먼저 표시하고 이후 출력에서 GPU 시간을 표시합니다. 이벤트는 완료 여부를 확인한 뒤 읽으며 측정 때문에 새로운 동기화를 넣지 않습니다. Report가 없는 실행에서는 측정용 GPU 이벤트를 생성하지 않습니다. 최근 10초 기록은 최대 10000개 요청으로 제한됩니다.

CPU 시간은 함수 호출과 대기 등 실제 경과 시간이고 GPU 시간은 해당 스트림의 이벤트 사이 경과 시간입니다. 두 시간을 더하지 않습니다. GPU 완료 대기는 앞서 제출한 여러 구간 작업을 기다릴 수 있으므로, 그 수치가 크면 각 구간의 GPU 시간을 함께 확인합니다. CPU 모델 실행 시간이 작아도 GPU 완료 대기가 크면 모델이 실제로 빠르다고 단정할 수 없습니다.

공유 배치의 전처리·모델 실행·후처리는 배치 전체를 처리하는 시간입니다. 각 요청이 경험한 배치 지연으로 기록하며 요청별 평균을 비교하는 데 사용합니다. 모든 요청 시간을 더해 GPU 사용 시간이나 처리량당 비용으로 해석하지 않습니다. 초기 모델 생성·예열은 첫 표본을 크게 만들 수 있으므로 준비가 끝난 뒤 최근 평균을 비교합니다.

상태 건수는 `1s/10s` 순서로 표시합니다. `완료`는 감지 작업자의 결과 생성 완료, `간격 건너뜀`은 추론 간격 때문에 실행하지 않은 요청, `작업자 바쁨`은 CudaAsync가 새 작업을 받지 못한 입력, `타임아웃`은 호출자의 결과 대기 만료, `오류`는 실패입니다. 만료 때문에 TensorRT 후속 단계가 실행되지 않은 경우에는 `부분 종료`로 표시합니다. 타임아웃 후 작업자는 계속 실행될 수 있으므로 같은 요청에서 타임아웃과 완료 또는 부분 종료가 함께 기록될 수 있습니다. 이 건수를 합쳐 전체 입력 수로 사용하지 않습니다.

`전체`는 CudaAsync 호출자의 대기 시간이나 인코딩·송출 시간을 포함하지 않습니다. 전체 파이프라인 상태는 기존 `StreamReport`와 함께 확인합니다. 기존 StreamReport의 추론 시간은 YOLO에서는 NMS를 포함하고 TensorRT에서는 별도 후처리를 제외하는 기존 의미를 유지합니다. 두 모델의 순수 실행 성능은 새 Report의 `모델 실행` 항목으로 비교합니다.

전처리 GPU 시간이 크면 색상 변환·리사이즈를, 배치 큐 대기가 크면 배치 수집 설정과 작업자 부하를, 입력 결합·출력 복사가 크면 배치 크기 1에서의 복사를, 후처리 GPU/CPU 시간이 크면 NMS와 후보 박스 수를 살펴봅니다. 기타 실행 비용이 크면 모델 예열·내부 처리·작업자 전달 비용을 추가 조사할 수 있습니다.
