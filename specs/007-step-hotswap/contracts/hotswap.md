# 공개 계약: Step 등록과 실행 중 교체

## 등록

`Pipeline.step(step)`은 기존처럼 단계 인스턴스를 받아 파이프라인을 반환한다. 설정은 원래 단계의 클래스명으로 조회하고 적용한다. `src/pipeworks/embedded`에 정의된 Step은 그대로 등록하고, 사용자 Step은 `Hotswap`으로 감싸 등록한다.

`Pipeline.step(Hotswap(step))`도 사용할 수 있으며 중복으로 감싸지 않는다.

`Tap` 내부 Step에도 같은 자동 포장 규칙을 적용한다.

설정 객체는 `Hotswap`이 보관하고 내부 Step의 `configure()`에 전달한다. 코드 교체나 상류 변경으로 새 Step이 만들어지면 동일한 설정 객체를 다시 전달한다. 일반 Step에 `config` 속성을 보관할 의무는 없다.

## 교체

- Step 클래스가 정의된 파일의 내용이 바뀌면 다음 처리 경계에서 새 구현을 준비한다.
- 메인 실행 파일과 같은 디렉터리의 사용자 모듈을 참조하는 Step도 별도 실행 프로세스에서 교체할 수 있다.
- 새 파일의 구문 또는 클래스 준비가 실패하면 현재 구현으로 계속 처리한다.
- 입력을 소비하는 Step은 이전 구간의 입력 종료를 받고 남은 출력을 완료해야 한다.
- 첫 소스 Step은 이전 출력 경계에서 종료하고 새 구현으로 연결한다.
- 변경된 Step의 뒤쪽 Step은 세대 변경을 감지해 이전 구간을 마무리하고 다시 시작한다.

실행 중 `.step(...)` 목록의 추가·삭제·순서 변경은 자동 반영하지 않는다. 사용자 Step의 생성자 속성 구조를 변경하거나 외부 자원을 내부 상태로 보유하는 경우에는 자동 상태 이전을 보장하지 않는다.

사용자 Step의 `process()` 실행이 실패하면 마지막 정상 출력 이후 소비한 입력 컨텍스트의 최상위 속성을 복원해 원래 순서대로 반환하고 후속 입력을 다시 시작한 처리 구간에 전달한다. 상류 입력 오류는 이 복구 대상이 아니다.
