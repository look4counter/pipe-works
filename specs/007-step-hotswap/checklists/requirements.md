- [x] 사용자 코드의 `.step(...)` 계약을 명시했다.
- [x] 파일 변경 실패와 정상 전환의 인수 조건을 구분했다.
- [x] 소스 Step, 입력 소비 Step, 상태 있는 하류 Step의 경계를 명시했다.
- [x] 지원하지 않는 생성자 및 Step 구조 변경 범위를 기록했다.
- [x] 성공 기준을 모의 입력과 결과 순서로 검증할 수 있다.

- [x] 내장 Step의 자동 교체 제외와 명시적 래퍼 유지 기준을 명시했다.
- [x] 사용자 Step 오류 시 되돌릴 프레임 범위와 상류 오류 제외 기준을 명시했다.
- [x] 별도 프로세스에서 메인 파일과 사용자 패키지 Step의 교체 경로를 검증할 수 있다.
