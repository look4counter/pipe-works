# 조사: 현행 설정 전달 경계

기본 `Step.configure()`는 설정을 저장하지 않는다. 단계 구현체는 필요한 설정을 개별 속성에 저장한다. 사용자 정의 단계의 코드 교체 시 설정을 다시 적용하기 위해 `Hotswap`이 전달받은 객체를 별도로 보관한다. `PipelineContext`는 고정 필드가 없으므로 각 단계의 출력 계약에서 필요한 속성을 명시한다.
# 추가 조사: 실행 중 설정 변경

- 결정: 감시 기준은 파일 수정 시각 대신 내용 해시를 사용한다.
- 근거: 같은 내용으로 다시 저장했을 때 단계 재시작을 피하고, 빠르게 연속 저장한 변경도 구분한다.
- 결정: 설정 변경만 있을 때는 기존 인스턴스의 `configure()`를 실행하고 실패 시 최상위 속성을 복원하며 처리 반복자를 유지한다.
- 근거: RTSP 연결과 GPU 처리 자원을 다시 열지 않아 영상 재생 중단을 피한다.
- 고려한 대안: 새 인스턴스를 만들어 처리 구간을 다시 시작하는 방식은 활성 영상 자원을 닫으므로 채택하지 않는다.
- 제약: 현재 열린 자원이 생성 시점에 읽은 옵션은 즉시 바뀌지 않을 수 있다. 새 연결이나 새 자원이 자연스럽게 만들어질 때 반영된다.
