4. 사용자 정의 단계 변경 후 이전 설정이 새 인스턴스에 다시 적용되는지 확인한다.

6. 동적 컨텍스트에 임의 속성을 추가하고 동일 객체 전달과 새 객체 생성 경계를 구분한다.
# 추가 검증: 실행 중 설정 변경

1. 사용자 Step 설정을 가진 YAML로 지속 입력 파이프라인을 실행한다.
2. YAML에서 해당 Step 값만 수정하고 다음 입력의 출력이 새 값을 사용하는지 확인한다. 처리 반복자와 영상 연결은 계속 유지되는지 관찰한다.
3. 다른 Step 섹션만 수정해 기존 Step이 다시 시작하지 않는지 확인한다.
4. 잘못된 YAML을 저장한 뒤 처리가 이전 값으로 이어지는지 확인하고, 올바른 값으로 고쳐 새 설정 적용을 확인한다.
5. 소스 Step과 `Tap` 내부 사용자 Step에서도 같은 흐름을 확인한다.

## 재연결 간격 밀리초 검증

2026-10-09 후속 요청으로 두 RTSP 단계는 reconnect_interval_ms를 사용하며 기본값 3000ms로 기존 3초를 보존한다. 이전 키는 오류로 거부한다. 예제 YAML과 공개 문서의 수치는 1000배로 환산했다.

명세·명확화·계획·작업·일관성 분석 후 구현했다. FR-015~016과 SC-012~013은 T023~T027에 대응하며 차단 충돌은 없었다. 미작성 헌법 템플릿은 원칙 검사에서 제외했고 확장 훅은 없다. 구현 전 단위·속성·설정 오류 검증의 실패를 확인했다.

수신 8개·송출 13개·파이프라인 구성 7개 테스트가 모두 통과했다. 기본·0·250·1250.5ms 수신 대기, 중단 이벤트를 통한 대기 종료, 연결 및 송신 실패의 250ms 재시도 경계, 이전 키와 잘못된 값 거부를 확인했다. 전체 테스트는 이번 변경에서 반복하지 않았다.

## configure 필수 구현 검증 (2026-10-10)

`.venv/Scripts/python.exe -m unittest discover -s tests -p test_step_config_defaults.py`로 계약 검증을 실행한다. configure 누락은 생성 시 TypeError, 빈 구현과 구체 구현 상속은 정상 생성이어야 한다. 변경 전 누락 검증의 실패를 확인했고 변경 후 11개 테스트가 통과했다. 핫스왑 검증 30개도 통과했다.

전체 310개 검증의 첫 실행에서 새 계약을 누락한 동적 Metadata 예제 6건과 기존 step.post_process 모듈 누락 2건을 확인했다. Metadata 예제를 수정하고 핫스왑 검증을 재실행해 모두 통과했다. 전체 재실행은 중앙 프로세스 통신에서 멈춰 테스트 프로세스를 종료했다. 중앙 프로세스를 제외한 291개 검증은 287개 통과, 2개 건너뛰기, 기존 모듈 누락 오류 2개였다. 해당 모듈 참조와 파일 누락은 기존 저장소 상태이며 이번 변경 범위에 포함하지 않았다. 전체 통과는 확인하지 못했다.

정적 점검에서 configure가 없는 직접 Step 하위 클래스는 누락 거부 검증용 MissingConfigure만 남았다. 실행 코드·동적 테스트 코드·사용자 안내 예제의 필수 구현 계약을 확인했다.
