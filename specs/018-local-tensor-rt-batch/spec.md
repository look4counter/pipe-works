# TensorRT 공유 배치 모듈

## 공유 모델 경로의 초기화 시 검증 (2026-10-10)

- FR-005: YOLO와 TensorRT 공유 추론 경로는 작업자 최초 준비에만 모델 경로를 정규화하고 존재를 검사한다. 같은 입력 경로의 기존 작업자 재사용에는 resolve와 is_file을 호출하지 않는다.
- FR-006: 상대경로는 호출 시 작업 디렉터리를 구분하며 같은 실제 경로의 별칭은 하나의 작업자를 공유한다. 작업자 생성 실패는 캐시하지 않아 다음 요청에서 재시도한다. 동시 최초 접근은 중복 작업자를 만들지 않는다. 생성된 작업자 안의 모델 로드 실패는 기존 로더 재시도 계약을 유지한다.
- FR-007: 이미 로드된 모델은 파일 삭제 후에도 기존 작업자로 추론한다. 엔진 세션 오류 후 재로딩은 실제 파일 읽기로 검증하고 기존 오류 전달을 유지한다. 처음 해석한 별칭은 기존 작업자가 있는 동안 같은 대상에 고정한다.
- SC-002: 기존 작업자 재사용의 파일 조회 금지·초기 누락·생성 실패 재시도·동시 생성·상대경로 작업 디렉터리 구분·별칭 공유와 파일 삭제 후 추론이 검증된다. 기존 YOLO·TensorRT 공유 배치 회귀를 통과한다.

명확화: 사용자는 매 추론 검사를 초기화 시점으로 옮기고 파일 삭제 후에도 이미 로드된 모델을 사용하도록 승인했다. 새로운 모델 파일 감시·자동 재로드·작업자 종료 API는 추가하지 않는다. 단일 모드와 배치 입력·GPU 처리 계약은 유지한다. 추가 질문은 없다.

- FR-001: local_tensor_rt.infer는 GPU 텐서 또는 이름별 GPU 텐서 사전을 받아 엔진·GPU·이름·자료형·비배치 형상이 같은 요청을 공통 수집기로 묶는다. 개별 요청은 배치 축 0의 크기 1이며 출력도 배치 축 0으로 분리 가능해야 한다.
- FR-002: 모델 동명 YAML의 max_batch_size·밀리초 timeout으로 수집하고 plugins로 엔진을 로드한다. 설정 파일이 없으면 배치 1·수집 0으로 처리한다. timeout은 추론 제한 시간이 아니다.
- FR-003: 준비 이벤트를 기다려 입력을 배치 GPU 텐서로 구성하고 전용 작업자로 동기 추론한다. 결과는 GPU의 배치 1 텐서 사전으로 각 요청에 전달한다. 오류는 모든 배치 요청에 전달하며 다음 요청에서 재시도한다. 입력 수명과 완료를 보장한다.
- FR-004: 이번 작업은 모듈 추가이며 TensorRTInference의 batch 옵션 연결은 제외한다.
- SC-001: 실제 GPU에서 호환·비호환 요청·결과 분리·오류 복구·설정 검증이 통과한다.

명확화: 일반 TensorRT의 임의 출력 의미는 추론할 수 없으므로 배치 축 0 계약을 명시적으로 제한한다. 고정 배치 1 엔진은 max_batch_size=1로 사용해야 한다. 추가 질문은 필요하지 않다.
