# 조사: 마지막 단계 상태 보고

## 기록 비용 절감 조사

결정: 가변 누적값·deque 기록과 프로세스 공용 100ms 발행을 분리한다. 기존 CPython 3.11.9의 단일 불변 참조 읽기를 유지한다. 매 기록 replace를 계속하는 대안은 반복 측정에서 기록 4회 합계가 약 12.3µs여서 제외한다. 기록자가 주기적으로 발행하는 대안은 마지막 기록 후 입력이 멈추면 마지막 상태를 발행하지 못하므로 제외한다. 보고자가 직접 잠금 아래 발행하는 대안은 기존 읽기 전용 요구와 충돌한다.

발행 등록은 참조 계수로 공유하고 마지막 해제의 join은 등록 잠금 밖에서 실행한다. 새 구독은 이전 종료 작업자의 이벤트를 재사용하지 않는다. Hotswap·Tap·CudaAsync를 재귀 탐색하며 Tap의 문맥 전달 누락도 수정한다. 별도 감지 통계는 비활성화하지 않는다. 발행본은 시각을 포함하여 FPS 분모와 누적값 범위를 맞춘다. 표본은 조회 시각으로 10초 경계를 필터하되 최신 기록의 발행 지연을 문서화한다.

- 결정: 마지막 보고 단계가 별도 작업자로 주기 출력하고 본 실행 스레드는 상류 반복자를 소비한다.
- 근거: `RTSPPublish`는 입력을 모두 소비하며 출력 컨텍스트를 만들지 않으므로 프레임 기반 보고 단계는 그 뒤에서 실행되지 않는다.
- 결정: 수신·송신 성공은 실제 패킷 단위로 기록한다.
- 근거: 연결 시도 성공만으로 영상 흐름의 성공을 판단할 수 없다.
- 결정: 최근 성공 시각과 명시적 실패 시각을 분리한다.
- 근거: 연결 대기, 최근 성공, 실제 오류, 장시간 무응답을 구분할 수 있다.

## 읽기 전용 보고 조사

- 결정: 여러 기록 스레드는 기존 잠금으로 직렬화하고, 완성된 불변 스냅샷을 참조 교체로 발행한다. CPython 3.11 환경에서 보고자는 참조를 한 번 읽어 일관된 자료를 사용한다.
- 근거: 공유 dict/deque를 잠금 없이 순회하는 대안은 동시 변경에 취약하다. 통계 전담 스레드·큐를 추가하는 대안은 추가 전달 비용과 종료 관리가 필요하므로 채택하지 않는다.
- 결정: 1초 값은 누적값의 관측 차분이다. 보고자마다 이전 관측값을 보관하므로 한 보고자가 다른 보고자의 통계를 소모하지 않는다.
- 결정: 불변 이력은 초별 청크를 공유한다. 단순 전체 tuple 복사는 매 기록에 최근 10초 전체를 복사하므로 사용하지 않는다. 전체 실행을 연결하는 단일 불변 리스트는 과거 표본을 해제하지 못하므로 사용하지 않는다.
- 정확성: 경계 초의 개별 기록은 남겨서 정확한 (현재-10초, 현재] 범위를 계산한다. 무입력 상태의 만료와 상태 전환은 보고 시각으로 계산한다. 부동소수점 계산 순서 차이는 기존 표시 정밀도에서 허용한다.
- 성능 범위: 보고자의 잠금 대기는 제거하지만 기록별 불변 객체 생성 비용이 추가된다. 전체 처리량 개선은 별도 측정 대상이다.
