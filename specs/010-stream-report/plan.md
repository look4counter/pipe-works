# 구현 계획: 실행별 프레임 처리 보고

## 기록 비용 절감 설계

수집기는 기록 잠금 아래 가변 누적값·단계별 두 값 리스트 사전·연결 시각·최근 표본 deque를 갱신한다. 매번 replace와 불변 노드를 만들지 않는다. 발행할 때만 이력·단계를 tuple로 만들어 스냅샷 참조를 교체한다. 기록 시에도 만료 표본을 정리해 발행 없는 직접 수집의 메모리를 제한한다.

활성 StreamReport 수집기는 프로세스 공용 발행 작업자 하나에 등록하며 100ms마다 발행한다. 중복 보고자는 참조 계수로 보호한다. 마지막 해제 시 신호 후 잠금 밖 join을 수행하고 새 구독은 독립 작업자 세대로 시작한다. 발행 시각을 스냅샷에 포함하고 FPS 분모도 연속 발행 시각 차이에 맞춘다. Reader는 잠금 없이 같은 불변 자료만 읽고 10초 경계는 조회 시각으로 계산한다.

Pipeline은 Hotswap·Tap·CudaAsync 내부까지 보고자 유무를 확인해 report_scope(enabled=...)를 사용한다. 비활성 기록은 잠금과 시각 측정 전에 반환한다. detection_profile.store는 유지한다. Tap은 copy_context로 실행별 수집기를 전달한다. 명시적 report_scope는 기본 활성이다. 직접 테스트는 publish를 명시적으로 호출하고 내부 누적값 검증을 갱신한다. `stream_report.py`, `pipeline.py`, `tap.py`와 관련 테스트·문서를 수정한다. 기존 보고·감지·GPU·설정·Tap 회귀, 동일 조건 비용 측정과 수렴을 수행한다. 추가 의존성은 없고 미작성 헌장 외 추가 제약도 없다.

## 남은 이름 정리 (2026-10-04)

보고 구현 모듈을 `stream_report.py`로 옮기고 모든 내부 import와 테스트 import를 변경한다. 현재 기능 명세 디렉터리를 `010-stream-report`로 바꾸고 다른 명세의 링크와 요구사항을 현재 공개 단계에 맞춘다. 폐기한 이름의 문서 언급도 제거한다. 변경 뒤 관련 테스트와 전체 테스트를 실행해 보고 기능과 중앙 프로세스 전달을 확인한다.

## 단일 보고 단계 정리 (2026-10-04)

사용자 요청에 따라 구형 보고 클래스와 `embedded` 공개 내보내기를 제거한다. 수집기 및 기록 함수는 `StreamReport`와 다른 단계가 계속 사용하므로 유지한다. `tests/test_report.py`의 구형 단계 전용 사례는 제거하고, 컨텍스트 동일성 및 두 줄 출력 등 유효한 계약은 `StreamReport` 사례로 검증한다. 예제는 이미 `StreamReport`를 사용하므로 그대로 둔다.

## 추론 시간 명확화 (2026-10-04)

`local_yolo.py`의 공유 작업자가 배치 준비를 마친 뒤 `model.predict` 직전에 시간을 재고, GPU 완료 이벤트를 기다린 직후 구간을 닫는다. 측정값을 요청 객체에 보관하고 `infer`의 선택적 콜백으로 해당 파이프라인의 통계 수집기에 전달한다. 기존 반환값은 유지한다. `YoloDetectBatch`는 호출 전체의 벽시계 시간 기록을 제거한다. `YoloDetect`도 모델 로드와 이미지 복사 이후 예측 호출만 측정한다. 관련 단위 테스트에서 대기 시간 제외, 배치별 기록 및 반환값 호환을 확인한다.

## 현재 구성

`NvidiaDecode`가 프레임 시작 시각을 넣고 `NvidiaEncode`가 완료 프레임과 인코딩 시간을 기록한다. `YoloDetect`와 `YoloDetectBatch`는 공통 추론 시간을 기록한다. `YoloDetectBatch`와 `RTSPPublish`도 단계별 시간을 기록한다.

`Pipeline._run_local`은 실행마다 `report_scope()`를 열어 통계를 분리한다. 수집기는 기록 측 잠금으로 갱신한 불변 스냅샷을 발행하고 `StreamReport`가 약 1초마다 잠금 없이 읽는다. 공유 누적값은 초기화하지 않는다. 독립 Step 호출에는 기본 수집기를 사용한다.

## 출력과 검증

`StreamReport`는 첫 줄에 수신·송신 상태와 FPS·프레임 평균·추론 평균을, 둘째 줄에 실제 기록된 단계의 평균을 출력한다. 전달받은 패킷 컨텍스트는 변경하지 않는다. `tests/test_report.py`와 중앙 프로세스 테스트에서 통계 분리, 출력, 전달을 검증한다.

## 마지막 단계 상태 보고 계획

1. 수집기에 수신·송신별 마지막 성공 시각과 마지막 실패 시각을 추가한다. `RTSPSource`는 유효 비디오 패킷을 내보낼 때와 연결·수신 실패 때, `RTSPPublish`는 패킷 송신 완료와 연결·송신 실패 때 기록한다.
2. `StreamReport`는 마지막 Step으로 상류 반복자를 소비한다. `RTSPPublish`가 출력을 내지 않아도 별도 보고 작업자가 1초마다 실행별 수집기를 읽어 출력한다.
3. 보고 작업자는 실행 문맥의 통계 수집기와 호출자 표준 출력 대상을 이어받는다. 종료 신호를 받으면 즉시 끝내고 다른 파이프라인과 출력을 섞지 않는다.
4. 기존 FPS·평균 처리·추론·단계별 평균 계산을 공유한다. 첫 프레임 전에도 0 FPS와 수신·송신 대기를 표시한다. 최근 성공 5초 초과와 명시적 오류를 구분한다.
5. 01·02 RTSP 예제에서는 `RTSPPublish` 뒤에 `StreamReport`를 둔다.

## 추가 검증

- 출력 없는 상류를 소비하는 동안 주기 보고가 계속되는지, 종료 뒤 작업자가 멈추는지 테스트한다.
- 수신·송신 성공, 오류, 시간 경과 상태와 동시 파이프라인 분리를 검증한다.
- 중앙 프로세스에서 보고 문구가 호출자 콘솔에 전달되는지 확인한다.
## 최근 10초 계획

프레임·추론별 완료 시각과 처리 시간 이력을 수집 측에서 보관한다. 최근 10초 평균은 (현재-10초, 현재]의 표본을 대상으로 계산하고 표본 없는 값은 None으로 반환한다. 기록 측 갱신은 잠금으로 보호하며 출력 측은 불변 이력을 조회한다. 결정적 시계 모의로 가중 평균과 경계·격리를 확인한다.
## 표기 후속 계획

StreamReport.report_once의 문자열만 바꾸고 평균 계산은 유지한다. 프레임과 추론 각각 두 값을 하나의 출력 항목으로 묶으며 추론 건수는 항목 끝에 유지한다. tests/test_report.py의 기대 문자열과 검증 기록을 갱신한다.

## 읽기 전용 보고 설계 (2026-10-10)

아래는 이전 구현 설계의 기록이다. 매 기록 스냅샷·청크 생성과 작업자 미추가 결정은 이 문서의 기록 비용 절감 설계로 대체한다.

- Python 3.11.9의 CPython 실행 환경과 기존 의존성을 유지한다. 헌장은 미작성 템플릿이며 추가 원칙 위반은 없다. 기존 기록 함수·출력·컨텍스트 문법을 유지한다.
- `stream_report.py`의 수집기는 기록 잠금 아래 누적 프레임·추론·단계 건수/시간, 연결 시각과 불변 이력을 담은 스냅샷을 완성한 뒤 참조 하나로 발행한다. 독자는 그 참조를 한 번만 읽는다. 스냅샷의 내부도 tuple과 불변 자료만 사용한다.
- `_ReportReader`는 보고자별 이전 누적값과 관측 시각을 보관한다. 직전 관측과의 차분으로 FPS·평균·건수를 계산하며 수집기를 초기화하지 않는다. 시작부터 기록된 값은 첫 보고에 포함한다. 이전 출력 시각은 각 보고자의 개인 상태다.
- 정확한 10초 이력은 1초 단위 불변 청크로 보관한다. 각 청크는 그 초 안의 표본만 연결하는 불변 노드와 누적 합·개수를 갖는다. 새 표본 추가는 기존 노드를 공유하며 전체 이력을 복사하지 않는다. 초가 바뀔 때 최대 11개 청크 참조만 갱신하고 만료 청크를 제외한다. 보고는 완전 포함 청크의 합·개수를 사용하며 경계 청크의 개별 표본만 확인한다. 기록 시각은 기록 잠금을 잡은 뒤 측정해 시간 순서를 유지한다.
- 무입력 상태에서도 보고 시각으로 10초 범위와 연결 상태를 계산한다. 보고자는 공유 자료를 정리하지 않는다. 입력이 다시 오면 수집 측이 만료 청크를 해제한다. 오래된 스냅샷을 보관하는 외부 소비자의 메모리는 소비자 책임이며 기본 보고자는 이전 스냅샷 하나만 보관한다.
- StreamReport의 기존 출력 스레드는 읽기·문자열 생성·출력만 수행한다. 새 집계 스레드나 큐는 추가하지 않는다. DetectionReport의 기록 잠금과 동기화는 변경하지 않는다.
- `tests/test_report.py`의 구간 초기화 테스트를 차분 관측 테스트로 갱신하고, 잠금 금지·스냅샷 불변·다중 기록·독립 보고·청크 메모리·정확한 경계 검증을 추가한다. 보고·감지·비동기·RTSP·중앙 프로세스 회귀와 전체 검사를 실행한다. 실제 성능 수치를 보장하지 않는다.
