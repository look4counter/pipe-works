# 검증 안내: 마지막 단계 상태 보고

1. RTSP 소스, 디코딩, 추론, 인코딩, 송출 뒤에 `StreamReport()`를 마지막으로 등록한다.
2. 실행 중 약 1초마다 수신·송신 상태, FPS, 평균 프레임 처리 시간과 추론 시간의 표시를 확인한다.
3. 입력을 멈추거나 송출을 실패시키면 상태가 실패 또는 중단으로 변하고, 파이프라인 종료 뒤 새 보고가 출력되지 않는지 확인한다.
4. 두 파이프라인을 동시에 실행해 각 호출자 콘솔에 자신의 보고만 보이는지 확인한다.
# 추론 시간 해석

`StreamReport`의 평균 추론 시간은 모델 예측 호출 시작부터 GPU 작업 완료까지의 평균이다. 배치 추론에서는 같은 배치 실행 시간이 각 요청에 한 번씩 기록된다. 배치 대기, 입력 준비, 최초 모델 로드, 결과 변환 시간은 포함하지 않는다.
## 1초·최근10초 동시 표시

프레임처리(1초)·프레임처리(최근10초)·추론(1초)·추론(최근10초)를 동시에 출력한다. 최근10초는 완료 표본 전체의 평균이며 건수로 가중된다. 처음에는 확보된 표본만 사용하고 표본 없는 최근 구간은 없음으로 표시한다. 기존 FPS와 단계별 시간은 출력 구간 평균을 유지한다.

명세·명확화·계획·작업을 분석했고 차단 충돌은 없었다. 보고 테스트 11개가 통과했다. 불균등 건수·정확한 10초 만료 경계·1초 초기화 후 최근 값 유지·표본 소멸·출력 형식을 검증했다. 최종 수렴 점검에서 추가 구현 차이는 없다.
## 간결한 기간 표기

최신 출력은 `프레임처리 15.3ms/1s, 14.3ms/10s | 추론 5.2ms/1s, 4.8ms/10s` 형식이며 추론 건수는 뒤에 유지한다. 표본이 없으면 없음/구간으로 표시한다. 집계 계산은 변경하지 않았다. FR-022의 일관성을 확인했고 보고 테스트 11개와 공백 검사가 통과했다. 수렴 점검에서 추가 작업은 없다.
