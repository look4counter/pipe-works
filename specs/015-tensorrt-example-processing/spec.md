# TensorRT 예제 전처리·후처리 명세

## 사용자 시나리오

단일 RTSP 예제에서 GPU NV12 영상을 yolo11n.plan으로 추론하고 기존 BoxOverlay가 읽는 감지 결과를 얻는다. 전체 처리는 Async 내부에서 실행한다.

## 요구사항

- FR-001: TensorRTPreProcess는 원본 영상을 읽기 전용으로 유지하고 기본 설정에서 GPU NV12를 FP32 RGB 1×3×640×640으로 변환한다. 비율을 유지하고 중앙 패딩을 넣으며 원본 크기·비율·패딩을 보관한다. 범용 설정은 후속 FR-007~012를 따른다.
- FR-002: TensorRTPostProcess는 output0의 1×84×8400 YOLO 출력을 해석하고 신뢰도·클래스 필터와 클래스별 NMS를 적용한 뒤 원본 좌표를 복원한다. 감지 객체에 좌표·신뢰도·클래스 ID와 COCO 이름을 제공한다. 출력 누락은 detections=None으로 통과한다.
- FR-003: 두 단계는 클래스명 YAML 설정과 Hotswap을 지원하며 GPU 텐서를 CPU로 복사하지 않는다. 형식·설정 오류는 명확히 거부한다.
- FR-004: 단일 예제는 실제 plan 경로와 올바른 클래스명을 사용한다. 일반 TensorRTInference에 batch 인자는 전달하지 않는다.

## 성공 기준

- SC-001: 실제 엔진 입력·출력 형식, 원본 입력 보존·패딩·정규화와 좌표 복원·필터·NMS·빈 결과 검증이 통과한다.
- SC-002: 예제 생성과 기존 감지 결과 소비 검증이 통과한다.

## 명확화

추가 질문이 필요한 모호성은 없다. 제공된 plan을 직접 검사했으며 입력 images FP32 1×3×640×640, 출력 output0 FP32 1×84×8400이다. 후처리는 COCO YOLO11 탐지 엔진 예제로 제한한다. 전처리는 후속 요청에 따라 다양한 이미지 모델의 입력 규칙을 지원한다. 기본 신뢰도 0.25·IoU 0.7·최대 감지 300, 클래스 필터 [2]는 예제 기존 설정을 유지한다.
## CUDA 스트림 분리·버퍼 정리

- FR-005: 전처리·후처리는 영상 cuda_stream과 다른 모델 CUDA 스트림에서 실행한다. 영상 준비 완료와 모델 결과 완료를 확인하며 영상 스트림 자체는 교체하지 않는다. TensorRTInference는 model_cuda_stream이 있으면 입력 생산자로 사용한다.
- FR-006: 후처리 성공·누락·실패 시 model_input·model_output·복원 정보·모델 스트림 참조를 정리한다. 감지 결과와 원본 영상은 보존하고 GPU 완료 전에 저장 공간을 해제하지 않는다.
- SC-003: 실제 CUDA의 스트림 분리·영상 보존·결과 준비·버퍼 정리·실제 엔진과 Async 회귀가 통과한다.

명확화: 최신 요청은 전후처리의 영상 스트림 사용을 대체한다. 모델 작업 완료를 호스트에서 확인하여 공통 Async의 안전한 입력 수명 계약을 유지한다. 강제 메모리 캐시 비우기나 복수 Async 신호 최적화는 범위에 포함하지 않는다. 추가 질문은 필요하지 않다.

## 후속 사용자 시나리오: 범용 GPU 이미지 전처리 (2026-10-10)

### 사용자 시나리오 1: 모델별 입력 규칙 선택 (우선순위 P1)

개발자는 내장 TensorRTPreProcess의 설정을 바꿔 탐지·분류 등 서로 다른 이미지 모델에 맞는 입력을 준비한다. 특정 모델 공급자의 라이브러리를 사용하지 않고 GPU에서 변환한다.

독립 검증: 같은 합성 이미지에 letterbox, stretch, 중앙 자르기와 서로 다른 색상·정규화·출력 형식을 적용해 크기와 픽셀 값을 확인한다.

수용 시나리오:

1. 기존 기본 설정은 같은 크기·RGB 순서·정규화·원본 보존과 후처리 복원 정보를 유지한다.
2. 이름을 지정한 이미지 입력은 그 이름의 사전으로 전달되고 추가 입력은 다른 단계가 조합할 수 있다.
3. YAML의 일부 설정을 덮어쓰고 제거하면 최초 생성자 설정으로 돌아간다.
4. 잘못된 설정은 GPU 작업 전에 명확한 오류로 거부한다.

### 사용자 시나리오 2: 기존 파이프라인에서 안전하게 사용 (우선순위 P2)

기존 예제를 내장 전처리로 연결하고 비동기 실행·원본 프레임 수명·별도 모델 스트림·감지 보고를 유지한다.

독립 검증: 기존 전후처리·비동기 수명·보고 검증과 실제 예제 엔진을 실행한다.

### 기능 요구사항

- FR-007: 지정한 내장 경로에서 TensorRTPreProcess를 제공하고 embedded 패키지에서 가져올 수 있어야 한다. 기존 예제 경로는 같은 구현을 사용해야 한다.
- FR-008: size, resize_mode, auto, stride, scaleup, center, padding_value, crop_size로 크기 변경을 설정한다. letterbox는 비율 유지·패딩, stretch는 지정 크기로 늘리기, resize_center_crop은 비율 유지 리사이즈 후 중앙 자르기를 수행한다.
- FR-009: color_order, scale, mean, std, dtype, layout으로 채널 순서·정규화·출력 형식을 설정한다. 정규화는 (원본 픽셀 × scale − mean) / std이며 평균·표준편차와 패딩 채널은 출력 색상 순서를 따른다. 출력은 배치 크기 1의 연속 GPU 텐서다.
- FR-010: GPU uint8 NV12와 HWC RGB/BGR 이미지를 받고 원본을 수정하거나 이미지 데이터를 CPU로 복사하지 않는다. 입력 형식은 pixel_format으로 구분한다. NV12의 기존 색상 변환을 유지하며 정규화를 중복 적용하지 않는다.
- FR-011: 모든 옵션은 선택적 생성자 인자와 YAML 설정을 지원한다. YAML 우선·최초 생성자 기본값 보존·설정 제거 복원을 적용한다. input_name이 없으면 텐서, 있으면 해당 이름의 사전을 model_input에 저장한다.
- FR-012: 기존 별도 스트림·프레임 조기 읽기 완료 신호·보고와 후처리 호환성을 유지한다. 원본 크기, 가로·세로 배율, 패딩 또는 자르기 이동량과 최종 크기를 보관한다. 잘못된 형식·값은 거부한다.

### 경계 사례와 명확화

auto=True는 최소 패딩을 사용하므로 size와 다른 최종 크기를 만들 수 있다. 고정 입력 엔진에서는 auto=False를 사용한다. 여러 입력 모델 전체를 자동 생성하거나 엔진을 읽어 전처리를 자동 추론하지 않는다. RGB/BGR은 HWC의 3채널 uint8 GPU 텐서이며 NV12는 기존 영상 크기 정보를 사용한다.

size는 높이·너비이며 중앙 자르기는 size를 모두 채우는 비율로 리사이즈하고 crop_size로 자른다. crop_size 기본값은 size이고 size보다 클 수 없다. auto, center, stride, scaleup, padding_value는 letterbox에서만 결과에 영향을 준다. 다른 모드의 auto=True와 crop 모드 밖의 crop_size 지정은 구성 오류다. stride는 양의 정수이고 size는 stride 배수로 강제하지 않는다.

평균·표준편차는 채널별 3개이며 표준편차는 양수다. 패딩은 정규화 전 0~255 기준의 스칼라 또는 채널별 3개 값이다. 보간은 bilinear를 사용하고 계산은 FP32, 최종 변환은 지정 자료형으로 수행한다. 기존 NV12 실수 변환을 유지하므로 CPU OpenCV uint8 리사이즈와 비트 단위 일치를 보장하지 않는다.

### 성공 기준

- SC-004: 세 가지 크기 변경·최소 패딩·색상 순서·정규화·두 자료형·두 배치 형식·입력 이름의 수치 및 구성 검증을 통과한다.
- SC-005: 기존 기본 입력·좌표 복원·실제 엔진·비동기 원본 수명·보고 검증에 전처리 변경으로 발생하는 실패가 없다.
- SC-006: 문서에서 탐지용 letterbox와 분류용 중앙 자르기 설정을 보고 각각 입력을 구성할 수 있다.

## 후속 요구사항: 예제 YAML에 전체 옵션 노출

- FR-013: examples/config/stream.yml의 TensorRTPreProcess 섹션에 지원하는 15개 옵션을 모두 기본값으로 명시해야 한다. 기존 예제의 실제 전처리 동작을 유지한다.
- SC-007: 예제 섹션의 키가 생성자 옵션 전체와 일치하고 해당 설정을 configure에 전달했을 때 기본 설정과 같은 값이 적용된다.

명확화: 추가 질문이 필요한 모호성은 없다. 중앙 자르기와 이름별 입력은 각각 crop_size: null, input_name: null로 노출한다. 범위는 YAML 설정이며 사용자가 변경한 소스와 예제 파일은 보존한다.
