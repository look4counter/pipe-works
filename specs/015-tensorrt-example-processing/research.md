# 범용 전처리 설계 조사

## 좌표 복원 책임 분리 결정

변환 객체를 image_transform 모듈에 두고 전처리가 생성한다. 후처리는 shape와 restore_boxes_만 사용한다. 축별 뷰로 제자리 GPU 복원을 유지한다. 범용 행렬·별도 복원 Step은 현재 세 변환에 불필요하므로 도입하지 않는다. 균일 배율·반올림 규칙을 보존하며 미확정 사항은 없다.


## 결정과 근거

- 기존 GPU NV12 변환의 계산을 공통 image 모듈로 옮긴다. 기존 변환 결과와 원본 프레임 수명 계약을 보존하면서 전처리가 YOLO 모듈에 의존하지 않게 한다.
- PyTorch CUDA의 bilinear 보간과 GPU 패딩·정규화를 사용한다. Ultralytics LetterBox는 NumPy/OpenCV 경로이므로 직접 호출하면 GPU 입력을 유지할 수 없다.
- auto 패딩은 남은 높이·너비의 stride 나머지로 계산한다. 고정 엔진 입력에서는 auto=False를 사용한다.
- CPU uint8 OpenCV 결과와 비트 단위 일치를 약속하지 않는다. 기존 NV12 FP32 변환을 보존하고 합성 입력으로 크기·색상·정규화·좌표 변환을 수치 검증한다.
- 중앙 자르기는 size를 채우는 비율 유지 리사이즈 후 crop_size를 중앙에서 선택한다. 분류 모델의 짧은 변 256·224 자르기를 size=[256,256], crop_size=[224,224]로 표현할 수 있다.

별도 프레임워크 도입·모델 엔진 검사로 전처리 추측·CPU 변환은 채택하지 않는다. 추가 미확정 사항은 없다.
