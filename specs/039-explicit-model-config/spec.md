# 기능 명세: 모델 설정 경로 명시

작성일: 2026-10-17
상태: 검증 완료

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 설정 파일 직접 선택 (우선순위: P1)
개발자는 YoloInference 생성자의 config_path로 원하는 YAML 파일을 선택한다.
인수 조건: 모델과 다른 이름·디렉터리의 YAML도 사용하며, 경로를 생략하면 옆의 동명 파일을 읽지 않는다.

### 사용자 이야기 2 — 실행 방식 간 일관성 (우선순위: P1)
개발자는 로컬·중앙 배치 실행과 TensorRT에서 같은 명시 경로 규칙을 사용한다.
인수 조건: 동일 모델이라도 설정 경로가 다르면 공유 작업자를 분리한다.

## 경계 조건

명시한 파일이 없거나 YAML이 잘못되면 오류로 알린다. 상대 경로는 실행 디렉터리 기준이다. 플러그인의 상대 경로는 기존처럼 모델 디렉터리 기준으로 유지한다. 설정 파일 자동 재로딩은 추가하지 않는다.

## 요구사항

- FR-001: 생성자 전용 선택 인자 config_path를 받으며 기본값은 None이다.
- FR-002: 설정 경로를 생략하면 자동 탐색 없이 기존 무설정 기본값을 사용한다.
- FR-003: 명시 파일은 배치 및 TensorRT 설정에 전달하고 기존 값 검증을 유지한다.
- FR-004: 공유 작업자는 백엔드·모델·설정 경로별로 분리하고 같은 경로는 재사용한다.
- FR-005: 예제·사용자 문서·관련 테스트를 새로운 계약에 맞춘다.

## 성공 기준

- SC-001: 이름이 다른 설정 파일 적용, 생략 시 동명 파일 무시, 누락 파일 오류 테스트가 통과한다.
- SC-002: 서로 다른 설정의 작업자 분리와 동일 설정 재사용 테스트가 통과한다.
- SC-003: 관련 회귀 테스트가 통과한다.

## 가정과 명확화

모든 백엔드에 선택적 config_path를 제공한다. 미지정 시 기본값을 유지하는 방향으로 결정했다. 사용자 목표·범위·데이터·오류·용어·완료 조건을 검토했고 중대한 불명확성은 없으며 질문은 0건이다. 헌법은 미작성 템플릿이므로 구체 원칙 적용을 생략한다.
