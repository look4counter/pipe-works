# 연구 결과

## 결정과 근거

_prepare_inputs가 입력과 준비 이벤트를 반환하고 실제 소비 스트림에서 wait_event로 연결한다. 배치 작업자도 입력 결합 전에 요청 이벤트를 기다린다.
연구 에이전트가 수명과 오류 정리를 검토했다. 동일 스트림 이벤트 대기는 안전하고 다른 스트림도 같은 방식으로 처리한다. 입력 참조는 최종 완료 동기화까지 유지된다. 배치 중복 이벤트 기록은 제거한다.

[PyTorch 공식 설명](https://docs.pytorch.org/docs/main/generated/torch.cuda.Stream_class.html)에 따르면 wait_event는 CPU에서 이벤트 완료를 기다리지 않고 이후 제출 작업에 의존성을 등록한다. 설치된 PyTorch의 구현과 실제 GPU 회귀로 확인한다.

## 대안

같은 스트림만 조건부 생략하면 비교 분기를 늘린다. 모든 완료 대기 제거는 출력 할당기·통계·오류 복구 계약을 바꾸므로 이번 범위에서 제외한다.
