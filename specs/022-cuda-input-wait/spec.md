# 기능 명세: 추론 입력의 CPU 대기 제거

작성일: 2026-10-10. 상태: 명확화 완료. 요청: 같은 CUDA 스트림에서 중복 입력 대기를 제거한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 입력 준비 중에도 추론 제출 진행 (우선순위 P1)

사용자는 기존 파이프라인과 설정으로 동일한 감지 결과를 받으며, 입력 준비 때문에 호출 스레드가 중간에 멈추지 않는다.
독립 검증: 준비가 지연된 입력으로 개별·공유 배치 추론을 실행하고 결과와 작업 제출 순서를 확인한다.

1. 같은 실행 흐름의 전처리와 추론은 입력 완료를 CPU에서 기다리지 않고 순서대로 처리한다.
2. 다른 실행 흐름의 입력과 공유 배치 입력도 준비가 끝난 뒤 읽으며 CPU에서 입력 완료를 기다리지 않는다.
3. 반환 시 결과 완료, 오류 복구, 입력 수명과 기존 통계 계약을 유지한다.

### 경계 조건

전처리가 늦은 입력, 여러 생산자가 있는 배치, GPU 불일치, 비연속 입력, 제출 실패, 재시도와 타임아웃을 검증한다.

## 요구사항

- FR-001: 개별 TensorRT 추론은 입력 준비 완료를 CPU에서 기다리지 않아야 한다.
- FR-002: 공유 배치 TensorRT 추론도 모든 입력의 준비 순서를 보장하면서 CPU 입력 대기를 없애야 한다.
- FR-003: 입력을 다 읽기 전에 버퍼를 해제하거나 재사용하지 않아야 한다.
- FR-004: 결과 완료·오류 복구·설정·추론 통계·타임아웃 계약을 유지해야 한다.
- FR-005: 지연된 실제 GPU 입력과 CPU 대기 금지 검증을 포함한 회귀 테스트를 제공해야 한다.

### 주요 개체

- 입력: 생산 실행 흐름에서 준비되는 추론 텐서.
- 준비 신호: 입력을 읽어도 되는 시점을 나타내는 신호.
- 요청: 준비 신호와 입력을 보유하고 완료된 결과를 전달하는 처리 단위.

## 성공 기준

- SC-001: 개별·공유 배치 입력 준비의 CPU 완료 대기 호출은 0회이다.
- SC-002: 지연 입력의 결과는 준비 완료 후 실행한 참조 결과와 일치한다.
- SC-003: 관련 추론·배치·비동기 회귀 테스트가 통과하며 실제 속도 향상률을 측정 없이 주장하지 않는다.

## 가정과 명확화

대화로 범위가 확정되어 추가 질문은 0개이다. 기능·데이터·오류·성능·의존성 범주에 핵심 모호성이 없다.
이번 범위는 TensorRT 입력 대기이다. 추론 및 후처리의 최종 완료 대기, CudaAsync 자체의 원본 준비·완료 대기와 YOLO 경로는 유지한다.
