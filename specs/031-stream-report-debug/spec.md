# 기능 명세: 성능 보고 디버그 로그

**작성일**: 2026-10-15
**상태**: 검증 완료
**입력**: StreamReport에 있는 로그를 logging debug로 변환한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 로그 수준으로 통계 표시 제어 (우선순위: P1)

운영자는 디버그 로그를 켰을 때 StreamReport 통계를 확인하고 일반 실행에서는 통계 출력을 숨긴다.
**우선순위 이유**: 사용자가 요청한 출력 방식 변경이다.
**독립 검증**: 디버그 수준에서 기존 통계 메시지를 확인하고 정보 수준에서 해당 메시지가 기록되지 않는지 확인한다.

1. 디버그 로그가 활성화되면 기존 수신·송신 상태와 성능 통계를 기존 주기로 기록한다.
2. 로그 수준이 정보 이상이면 통계 메시지를 표시하지 않는다.
3. 입력이 없을 때의 주기 보고, 입력 객체 전달 및 종료 동작을 유지한다.
4. 단일 스트림 예제를 직접 실행하면 파이프라인을 만들기 전에 DEBUG 로깅을 설정한다. 모듈을 가져올 때에는 로깅 설정을 바꾸지 않는다.

### 경계 조건

- 라이브러리는 로깅 설정을 강제로 적용하지 않는다. 단일 스트림 예제의 직접 실행 진입점에서는 DEBUG 기본 설정을 적용한다.
- StreamReport와 YoloReport의 보고 출력을 DEBUG로 전환한다. 중앙 스트림 프로세스 중복 실행 안내는 WARNING으로 기록한다. 다른 Step의 출력 수준은 변경하지 않는다.
- 통계 계산과 수집 여부 및 보고 주기는 기존대로 유지한다.

## 요구사항

- **FR-001**: StreamReport의 직접 표준 출력 쓰기를 모듈 로거의 DEBUG 기록으로 바꾼다.
- **FR-002**: 기존 메시지의 지표·두 줄 형식·보고 주기·스레드 종료와 컨텍스트 전달 동작을 유지한다.
- **FR-003**: 로깅 핸들러나 전역 로그 수준을 라이브러리에서 설정하지 않고 사용자가 로그 수준을 제어하게 한다.

- **FR-004**: examples/01_single_stream_rtsp_style.py를 직접 실행할 때 표준 logging의 DEBUG 기본 설정을 파이프라인 생성 전에 적용하고 모듈 가져오기에는 부작용을 추가하지 않는다.

- **FR-005**: YoloReport의 주기 보고와 종료 시 마지막 보고를 pipeworks.embedded.yolo_report 로거의 DEBUG로 기록한다. 기존 다중 행 메시지·통계·입력 객체 전달·수집 정리 동작을 유지한다.

- **FR-006**: 중앙 스트림 프로세스가 이미 실행 중이라는 안내를 pipeworks.main 로거의 WARNING으로 기록한다. 기존 중복 실행 감지와 반환 동작은 유지한다.

## 성공 기준

- **SC-001**: 디버그 수준의 기존 보고 시험을 통과하고 정보 수준에서 StreamReport 기록이 0건이다.
- **SC-003**: 예제 진입점 검증에서 DEBUG 설정이 파이프라인 생성보다 먼저 실행되고 가져오기에는 실행되지 않는다.
- **SC-002**: 기존 통계 계산과 입력 전달 및 종료 회귀 시험을 모두 통과한다.

- **SC-004**: YoloReport의 DEBUG 메시지 내용·마지막 보고 시험과 INFO 필터링 및 기존 감지 통계 회귀 시험을 통과한다.

- **SC-005**: 중앙 프로세스 중복 실행 안내가 직접 표준 출력 대신 WARNING 기록으로 전달되는지 확인하고 기존 실행 경로를 유지한다.

## 가정과 명확화

요청은 StreamReport 통계 메시지의 DEBUG 수준 전환으로 명확하다. 추가 질문이 필요한 모호성은 없다. 기존 공개 설정과 통계 계약은 유지한다.

YoloReport도 동일하게 DEBUG 기록으로 전환한다는 후속 요청을 반영했다. 추가 질문이 필요한 모호성은 없다.
