# 기능 명세: 인코더 원본 타임스탬프 보존

작성일: 2026-10-31. 상태: 명확화 완료.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 원본 시간 유지 (우선순위 P1)

사용자는 `NvidiaEncode(preserve_timestamps=True)`로 프레임 드롭 후에도 원본 표시 시각과 간격을 유지한다. 9000, 15000의 원본 시각과 1/90000 시간 기준을 입력하면 동일한 값으로 출력한다. 지연 출력과 종료 출력도 대응하는 입력 시각을 사용한다.

### 사용자 이야기 2: 기존 동작 유지 (우선순위 P2)

옵션을 생략하거나 끄면 기존처럼 0부터 증가하는 시각과 1/fps 시간 기준을 사용한다. YAML로 옵션을 덮어쓰고 제거하면 생성자 기본값으로 돌아간다.

## 기능 요구사항

- FR-001: 생성자와 YAML에서 불리언 preserve_timestamps를 제공하며 기본값은 False다.
- FR-002: True이면 입력 컨텍스트의 pts와 time_base를 유지한다. time_base가 없으면 video_stream.time_base를 사용한다. B프레임 없는 출력이므로 DTS는 원본 PTS와 같고 원본 압축 패킷의 DTS는 재사용하지 않는다.
- FR-003: 입력 duration을 유지하며 없으면 0으로 둔다. 지연·종료 출력은 입력 순서대로 저장한 시간 정보와 대응한다. 실패한 인코더의 미출력 시간 정보는 폐기한다.
- FR-004: 원본 PTS가 없거나 시간 기준이 유효하지 않으면 경고와 함께 프레임을 건너뛴다. FPS로 대체하지 않는다. 타임스탬프를 가진 입력보다 출력 패킷이 많으면 초과 패킷도 버린다.
- FR-005: False이면 기존 패킷 생성·복구 동작을 유지한다. True에서도 fps는 인코더 FPS·GOP·IDR 설정에 계속 사용한다.
- FR-006: 사용법과 입력 필드 및 수정 wheel의 설치·빌드·배포 조건을 문서화한다. RTSPPublish의 중복·역행 DTS는 FR-014의 폐기 정책을 따른다.
- FR-007: 공식 2.2.2 ZIP에 재현 가능한 최소 패치를 적용하여 수정 wheel을 빌드한다. 버전은 2.2.2+pipeworks.1로 구분하고 원본 API는 유지한다.
- FR-008: 새 GetLockedFrameWithPTS 호출은 한 번의 내부 잠금 호출에서 GPU 포인터와 부호 있는 64비트 PTS를 함께 반환한다. 영상 복사를 추가하지 않고 기존 UnlockFrame 계약을 유지한다.
- FR-009: NvidiaDecode는 새 API가 있으면 해당 프레임의 PTS와 PyAV 시간 기준을 같은 컨텍스트에 넣어 NvidiaEncode까지 전달한다. 공식 wheel의 기존 잠금 경로도 유지하되 원본 시간이 없는 프레임의 PTS는 None이다.
- FR-010: 디코딩 지연·재정렬·종료 출력·복구·큐 드롭에서도 프레임과 시간의 대응을 유지한다. 패킷 시간 기준이 바뀌면 디코더 세션의 시간 기준으로 입력 PTS를 환산한다.
- FR-011: 수정본을 지정하는 설치 예시와 의존성 고정을 제공하여 공식 wheel로 잘못 대체되는 것을 방지한다. 지원 빌드 대상은 현재 Windows x64와 Python 3.11이다.
- FR-012: 준비 단계는 원본 ZIP의 해시와 패치 적용 가능성을 검증한다. 빌드 도구·개발 의존성 누락 시 구체적인 오류를 보고하고 다른 설치 환경을 덮어쓰지 않는다.
- FR-013: Windows 빌드는 설치된 MSVC 개발자 환경을 사용하고 공백이 있는 CUDA·외부 소스 경로를 인자 손실 없이 전달한다. 원격 소스를 받지 못하면 로컬 pybind11·DLPack 소스를 지정하여 재개할 수 있다.
- FR-014: RTSPPublish는 마지막 송신 성공 DTS와 실제 시각을 비교하여 중복·역행 패킷을 송신하지 않고 건너뛴다. PTS·DTS를 증가시키지 않으며 연결·마지막 성공 DTS·성공/실패 지표를 건너뛴 패킷 때문에 변경하지 않는다. 서로 다른 time_base는 유리수 시간으로 비교한다. DTS 누락 보완과 입력 스트림 교체 시 기준 초기화는 기존 동작을 유지한다. DTS가 증가하는 정상 B프레임 패킷의 PTS만 비단조인 경우는 폐기 조건에 포함하지 않는다.

최신 사용자 요청의 '보정하지 말고 무시'는 중복·역행 DTS 패킷을 폐기하는 의미로 명확화했다. 기존 DTS 보정 유지 문구는 FR-014가 대체한다. 추가 질문이 필요한 미정 사항은 없다.

## 경계 조건

0과 음수 PTS, 불규칙 간격, 빈 출력, 지연·종료 출력, 인코더 재생성 및 시간 기준 변경을 검증한다. 입력 하나당 압축 영상 패킷 하나를 대응하며 원본 시간이 없는 임의 프레임에서 시간을 추정하지 않는다.

## 주요 데이터

입력 시각은 pts, time_base, 선택적 duration이다. 출력은 해당 시각을 가진 압축 패킷과 독립적인 영상 메타데이터다.

## 성공 기준

- SC-001: 유효한 원본 시각의 값과 프레임 간격을 모든 검증 사례에서 정확히 유지한다.
- SC-002: 기존 기본 동작 및 설정 회귀 검사가 통과한다.

## 명확화와 가정

### 2026-11-02 재빌드 요청

- FR-015: 기존 최소 바인딩 패치를 유지하고, 직전 원본 비교 빌드와 같은 MSVC v141 14.16·CUDA 12.0.140·Python 3.11 환경에서 수정 wheel을 별도 경로에 생성한다. 기존 설치와 이전 산출물은 덮어쓰지 않는다.
- FR-016: 두 네이티브 모듈의 로드와 새 잠금 API, 링커 14.16·PTX 8.0 및 가능한 로컬 GPU 통합 검증 결과를 기록한다. 대상 Windows 10 vGPU 서버의 정상 동작은 로컬 검증만으로 보장하지 않는다.

사용자의 '같은 방식'은 직전 원본 비교 빌드 조건을 유지하는 의미로 명확화했다. 버전은 기존 2.2.2+pipeworks.1을 유지하며 출력 디렉터리로 이전 파일과 구분한다. scikit-build는 직전 비교 빌드와 같은 0.18.1을 사용한다. 질문이 필요한 미정 사항은 없다.

추가 질문 없이 기존 계약과 사용자 요청에 따라 기본값 False, 원본 누락 시 폐기로 정했다. 이후 사용자 요청으로 C++ 바인딩 패치와 재빌드, 디코더에서 인코더까지 무복사 시간 전달을 범위에 추가했다. 새 메서드를 추가하여 기존 API 호환성을 지킨다. 원본 압축 패킷의 PTS를 현재 출력에 추정 대응하지 않고 디코더 API가 제공하는 실제 출력 PTS를 사용한다. 영상과 추론의 진행 독립성은 기존 파이프라인 구성에 따르며 추론 경로 재설계는 이번 바인딩 작업 범위가 아니다.

## 2026-11-02 빌드 진입점 정리 요청

- FR-017: 사용자는 이름에 v141-cuda120이 들어간 영구 빌드 진입점 하나로 검증된 패치 wheel을 생성한다. 일반 PowerShell에서 실행하면 필요한 도구를 선택하고, 도구가 없거나 버전이 다르면 다른 환경으로 대체하지 않고 오류를 안내한다.
- FR-018: 원본 ZIP이 없으면 NVIDIA 공식 배포처에서 2.2.2를 자동 다운로드하고 고정 SHA-256 검증 후에만 사용한다. 캐시가 있으면 재사용하며 손상된 캐시·실패한 다운로드는 빌드에 사용하지 않는다. 사용자가 지정한 로컬 ZIP도 지원한다.
- FR-019: 이전 실패 빌드의 wheel·작업 디렉터리·임시 실행 파일과 구식 진입점을 정리한다. 정상 확인된 v141·CUDA 12.0 패치본, 원본 비교본, 공식 원본, 빌드 환경·의존성, 라이선스 묶음 및 PipeWorks 산출물은 보존한다.
- FR-020: 한글 빌드 문서를 새 진입점·자동 다운로드·출력 경로로 일관되게 갱신하고, 다운로드 실패·해시 불일치·캐시 재사용 및 실제 빌드·두 네이티브 모듈 검증 결과를 기록한다.

명확화: 사용자의 '잘못된 빌드파일'은 CUDA 12.6으로 생성한 수정·원본 비교 산출물과 해당 임시 작업을 의미한다. 정상 v141 원본 비교본은 진단 기준으로 유지한다. 추가 질문이 필요한 미정 사항은 없다.
