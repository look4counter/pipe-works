# 구현 검증 결과

## 절차와 분석

명세 작성 → 명확화 → 설계 → 작업 생성 → 읽기 전용 일관성 분석 → 구현 순으로 수행했다. 명세 품질 체크리스트는 5개 모두 충족했다. FR-001~006의 작업 연결률은 100%이며 충돌·중복·미해결 모호성은 0개였다. 헌장은 미작성 템플릿이므로 원칙 검사는 생략했다.

## 검사 결과

- 최초 신규 테스트 7개가 옵션 미구현으로 실패하는 것을 확인했다.
- 구현 후 인코더 25개 검사가 통과했다.
- 설정 기본값·파이프라인 설정·RTSP 송출·내장 복구·핫스왑 회귀 78개가 통과했다.
- 입력 스트림 교체 시 종료 출력 대응 검사를 추가한 뒤 인코더 26개와 설정 기본값 11개, 총 37개가 통과했다.
- git diff --check에서 공백 오류가 없었다.

## 보장 범위

불규칙 원본 PTS와 0·음수, 시간 기준 변경, duration 생략, 지연 출력, 종료 출력, 초과 출력, 실패 세션 시각 폐기, 생성자와 설정 우선순위를 검증했다. 실제 NVIDIA GPU와 RTSP 서버를 통한 통합 송출은 검증하지 못했다.

초기 구현에서는 NvidiaDecode가 원본 PTS를 출력하지 않았다. 이후 아래 바인딩 확장을 추가했다. RTSPPublish의 비단조 DTS 보정은 유지된다.

## 바인딩 확장 검증

FR-007~012를 추가하여 명세·명확화·설계·작업·일관성 분석 후 구현했다. 총 12개 요구사항이 작업에 연결되며 명세 충돌과 미해결 질문은 없다.

- 원본 ZIP SHA-256 검증, 안전한 경로 추출, 최소 패치 적용, 버전 변경과 재실행 시 변경 감지 테스트 3개가 통과했다.
- 원본 ZIP을 실제 작업 디렉터리에 준비하는 PowerShell 진입점이 통과했다.
- 디코더 API 출력 PTS, PyAV 시간 기준 환산, 지연·재정렬·종료 출력, 큐 드롭, 공식 API 호환성 및 인코더 통합을 추가 검증했다.
- 빌드·디코더·인코더·설정·송출·복구 검사 105개가 통과했다. 이후 음수·미정 PTS와 스트림 시간 기준 검사 2개도 통과했다.
- 수정 wheel 전용 GPU 통합 검사는 추가했으나 현재 공식 wheel만 설치되어 있어 건너뛰었다.
- 패치된 PyNvDecoder.cpp는 MSVC의 문법 검사에서 NVENC 12.1·13.0 매크로 설정 모두 통과했다. 이 검사는 설치된 PyTorch의 pybind11·DLPack 헤더를 사용했으며, 공식 빌드 의존성으로 전체 wheel을 링크한 검증을 대신하지 않는다.
- 확장 회귀 실행에서 잘못 지정한 test_cuda_async 모듈 이름으로 로더 오류가 1개 발생했다. 실제 모듈 test_async로 바로잡아 40개가 통과했다. 나머지 모듈의 144개 통과·1개 건너뜀과 합쳐 실제 검사는 184개 통과·1개 건너뜀이다.

실제 wheel 빌드는 build·scikit-build·setuptools·wheel 패키지 누락으로 중단되었다. 별도 빌드 환경을 만들고 로컬 캐시 설치를 시도했으나 필요한 패키지가 없었다. 네트워크 제한으로 개발 의존성을 다운로드할 수 없어 wheel 생성과 수정 네이티브 모듈 실행 검증은 아직 완료하지 못했다. 원본 패키지를 교체하지 않았으며, 개발 패키지를 준비한 환경에서 docs/pynvvideocodec-build.md 절차로 재실행해야 한다.

## 빌드 재개

사용자가 개발 의존성을 설치한 뒤 버전을 확인했다. Visual Studio 2026의 MSVC 14.44와 CUDA 12.6, Python 3.11, Ninja Multi-Config를 명시하여 C·C++·CUDA 컴파일러 검사와 FFmpeg·Python 탐색까지 통과했다. CMake가 GitHub에서 pybind11 2.10.0을 다운로드하는 단계에서 네트워크 제한으로 중단되었다. 이후 단계의 DLPack 0.8도 로컬 소스를 준비해야 한다.

scikit-build의 CMAKE_ARGS 중복 파싱으로 공백 경로가 손상되는 문제를 발견하여 SKBUILD_CONFIGURE_OPTIONS로 전달하도록 보완했다. 명세 FR-013·계획·T014 갱신 및 일관성 확인 후 구현했고, 관련 준비·공백 경로 테스트 4개가 통과했다. wheel 생성·설치·수정 GPU 검증은 여전히 T013으로 남긴다.

## 최종 빌드와 GPU 검증 완료

사용자가 제공한 pybind11 2.10.0·DLPack 0.8 소스를 로컬에서 사용했다. pybind11 압축본은 원본 CMake의 SHA-256과 일치했다. 컴파일 시 CMAKE_CXX_FLAGS를 지정하면서 기본 예외 처리 옵션이 사라져 /EHsc를 추가했다. 기존 CMake 캐시에도 변경을 적용한 뒤 빌드가 성공했으며, 재빌드 안내에는 옵션 변경 시 새 작업 디렉터리를 사용하도록 기록했다.

- 환경: Windows x64, Python 3.11.9, MSVC 19.44.35228 / 도구 집합 14.44.35207, CUDA Toolkit 12.6.20, CMake 3.31.6, Ninja Multi-Config, pybind11 2.10.0, DLPack 0.8.
- wheel: dist/pynvvideocodec-2.2.2+pipeworks.1-cp311-cp311-win_amd64.whl.
- 크기: 20,502,189바이트.
- SHA-256: 4ea783158cd2143cfa09ed312f493270ef0a2703a5e06dc78e5d1f90fac2edac.
- NVENC 12.1·13.0 네이티브 모듈, VersionCheck, 수정 패키지 버전과 wheel 태그를 확인했다.
- 기본 .venv의 공식 2.2.2를 수정 2.2.2+pipeworks.1로 교체 설치했다.
- 실제 GPU 통합 검사 1개가 건너뛰기 없이 통과했다. 잠긴 프레임의 GPU 주소 동일성, 프레임 보관 중 비덮어쓰기, 원본 PTS 간격과 인코더 출력을 검증했다.
- 빌드·디코더·인코더·설정·송출·복구·핫스왑·비동기 처리·파이프라인 설정 검사 186개가 모두 통과했다.
- build/pynvvideocodec-verify에 별도 설치한 wheel로도 실제 GPU 통합 검사 1개가 통과했다.

T013을 완료했다. 현재 명세 범위에서 남은 구현·검증 작업은 없다. 다른 드라이버의 배포 PC와 실제 RTSP 서버를 통한 송출 검증은 이번 로컬 GPU 검증의 범위 밖이다.

## 중복·역행 DTS 폐기 정책 검증

사용자 요청에 따라 FR-006과 FR-014를 갱신하고 명확화·계획·작업 생성·일관성 분석 뒤 T015~017을 구현했다. 새 정책과 관련된 충돌이나 미해결 질문은 없다. 기존 보정 동작을 기대하는 기록은 이 절의 최신 정책으로 대체한다.

- 먼저 새 기대값으로 테스트를 실행하여 기존 보정 때문에 4개 검사가 실패하는 것을 확인했다.
- RTSPPublish는 DTS가 마지막 송신 성공 시각 이하이면 해당 패킷을 폐기한다. PTS·DTS를 증가시키거나 기준 시각을 변경하지 않는다.
- DTS 누락 보완과 스트림 교체·새 연결의 시간 기준 초기화는 유지한다. 서로 다른 time_base를 실제 시각으로 비교한다. 정상 B프레임의 비단조 PTS만으로는 폐기하지 않는다.
- 같은 연결에서 중복·역행을 건너뛴 후 정상 패킷의 간격이 유지되며, 건너뛴 패킷은 송신 성공·실패 지표나 재연결을 만들지 않음을 검증했다.
- RTSP 송출 22개를 포함하여 송출·보고·내장 복구·핫스왑·인코더 검사 111개가 통과했다. 실제 RTSP 서버 송출은 실행하지 않았다.
- 이 변경은 PipeWorks의 Python 송출 코드에만 적용되며 수정 PyNvVideoCodec wheel의 재빌드는 필요 없다.
