# 구현 계획: 디코더 자동 복구

**날짜**: 2026-10-15 | **명세**: [spec.md](spec.md)

## 요약

디코더 네이티브 호출 예외를 복구 분기로 전환한다. 오류 입력과 큐를 버리고 다음 키프레임에서 새 디코더를 생성한다. RTSP 스트림 객체 교체도 같은 방식으로 처리한다. 소비자 스트림과 외부 프레임 소유권은 유지한다.

## 기술 배경

- Python 3.11.9, PyNvVideoCodec 2.2.2, torch 2.2.1+cu121, PyAV 18.1.0.
- 기존 생산자 스레드, 최대 30개 FIFO, 34개 잠금 상한을 유지한다.
- unittest 기반 CPU 대역 및 실제 NVIDIA GPU 시험을 수행한다.
- 저장소는 Python 라이브러리이며 새 의존성이나 프로세스 구조 변경은 없다.
- 복구 속도는 카메라 키프레임 주기에 의존한다. 재생성 실패도 다음 키프레임까지 입력을 소비한다.

## 원칙 확인

헌법은 미작성 양식이므로 해당 검사는 생략한다. 사용자 지정 한글 문서와 speckit 단계 순서를 준수한다. 설계 전후 위반 사항은 없다.

## 구조

- src/pipeworks/embedded/nvidia_decode.py: 네이티브 호출 경계, 재설정, 키프레임 대기, 스트림 변경 감지, 복구 기록.
- tests/test_nvidia_decode.py: 복구, 반복 실패, 입력 종료, 오류 분리, 취소, 잠금 수명 시험.
- docs/: 기존 디코더 참조 문서의 자동 복구 설명 갱신.
- specs/029-decode-auto-recovery/: 명세, 조사, 데이터 모델, 계약, 검증 안내, 작업 목록.

## 설계 단계

1. 네이티브 디코더 호출에서 RuntimeError 및 설치된 PyNvVCException을 내부 복구 예외로 감싼다. 지원 불가 예외와 디코더 외부 오류는 전파한다.
2. 복구 시 대기 큐를 비우고 기존 풀을 close하여 반환된 버퍼를 정리한다. 외부 참조가 있는 풀은 owner가 보유하며 마지막 참조까지 유효하게 둔다. 이전 디코더를 flush하지 않는다.
3. 다음 키프레임만 재생성을 시도하며 실패한 패킷은 다시 넣지 않는다. 새 스트림도 키프레임부터 시작한다. 최초 실행의 기존 동작은 유지한다.
4. 소비자 CUDA stream은 최초 생성 후 유지하고 디코딩 stream은 세대별로 생성한다. 실제 프레임 publish에서 복구 성공을 기록한다.
5. 마지막 flush 오류는 기록하고 버린다. 소스 예외, 설정 오류 및 내부 불변식 위반은 계속 전파한다.

## 검증

테스트를 먼저 갱신하고 실패를 확인한 뒤 구현한다. 기존 디코더, 프레임 해제, RTSP 입력, 실행 경로 시험과 정적 검사를 수행한다. 실제 GPU 잠금 프레임을 유지한 상태에서 복구와 후속 출력을 검증한다.
