# 기능 명세: 디코더 자동 복구

**작성일**: 2026-10-15
**상태**: 명세 검증 완료
**입력**: 디코더 오류에도 사용자 개입 없이 복구를 시도하여 영상을 계속 진행한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 일시 오류 이후 자동 재개 (우선순위: P1)

운영자는 손상된 영상 입력 때문에 실행을 다시 시작하지 않아도 된다.
**독립 검증**: 정상 입력, 디코딩 오류, 비키프레임, 정상 키프레임을 순서대로 전달하여 후속 영상 출력을 확인한다.

1. 정상 처리 중 디코딩 오류가 발생하면 해당 입력과 대기 영상을 버리고 다음 정상 키프레임부터 자동 재개한다.
2. 여러 번 복구에 실패하여도 입력 수신을 계속하며 이후 정상 키프레임에서 재개한다.
3. 마지막 지연 프레임을 처리하다 오류가 발생하면 오류 프레임을 버리고 정상 종료한다.

### 사용자 이야기 2 — 재연결과 자원 수명 보장 (우선순위: P2)

운영자는 RTSP 재연결 이후 새 영상으로 자동 전환되고 언제든 실행을 중지할 수 있다.
**독립 검증**: 스트림 교체, 이전 프레임 참조 유지, 복구 대기 중 종료를 각각 검증한다.

1. 재연결로 입력 스트림이 교체되면 이전 디코더를 폐기하고 새 스트림의 키프레임부터 처리한다.
2. 복구 이전에 전달된 프레임은 사용이 끝날 때까지 유효하다.
3. 복구 대기 중 중지 요청을 받으면 새 입력 처리나 복구 재시도 없이 종료한다.

### 경계 조건

- 키프레임이 오지 않으면 입력을 계속 소비하며 기다린다. 중간 프레임 손실과 일시 정지는 허용한다.
- 지원하지 않는 코덱, 잘못된 설정, 입력 소스 예외 및 후속 처리 오류는 기존대로 전달한다.
- 운영체제 수준의 네이티브 프로세스 충돌이나 복구 불가능한 GPU 장애는 이 기능의 보장 대상이 아니다.

## 요구사항

### 기능 요구사항

- **FR-001**: 복구 가능한 디코더 호출 예외는 전체 실행을 종료하지 않고 자동 복구를 시작한다.
- **FR-002**: 오류가 발생한 디코더를 재사용하지 않으며 다음 키프레임에서 새 디코더로 처리한다. 연속 실패에도 재시도 횟수 상한 없이 키프레임별로 재시도한다.
- **FR-003**: 오류나 스트림 교체 시 대기 영상을 비우고 이전 프레임의 사용 완료 전 자원을 해제하지 않는다.
- **FR-004**: 입력 스트림 교체를 감지하여 새 입력 정보에 맞게 복구한다.
- **FR-005**: 복구 대기 중에도 입력 소비와 종료 요청 처리를 유지하고, 입력 종료 시 오류가 난 지연 영상은 버린다.
- **FR-006**: 복구 시작 원인과 실제 프레임 출력 재개를 기록한다. 정상 실행과 무관한 오류 전파 정책은 유지한다.

### 주요 개체

- 복구 상태: 정상 처리, 키프레임 대기, 재생성 시도, 출력 재개.
- 디코더 세대: 입력 스트림과 해당 세대가 소유한 영상 자원.

## 성공 기준

- **SC-001**: 단일 및 연속 디코딩 실패 주입 시험에서 이후 정상 키프레임의 영상 출력이 사용자 개입 없이 재개된다.
- **SC-002**: 재연결 및 프레임 참조 유지 시험에서 이전 영상 자원이 조기 해제되는 경우가 0건이다.
- **SC-003**: 키프레임 대기 중 중지 시험이 2초 안에 완료된다. 입력 수신 자체의 대기는 기존 수신 제한 시간을 따른다.
- **SC-004**: 기존 정상 디코딩, 입력 오류 전달, FIFO 및 큐 용량 검증을 모두 통과한다.

## 가정 및 명확화

- 2026-10-15: 사용자 지시에서 자동 복구 우선 정책이 명확하므로 추가 질문이 필요한 중대한 모호성은 없다.
- 카메라가 주기적으로 정상 키프레임과 필요한 영상 헤더를 전송한다. 재개 시간은 해당 주기에 좌우된다.
- 프레임을 새로 만들거나 마지막 영상을 반복 출력하는 기능은 포함하지 않는다.
- 오류 분기와 GPU 자원 수명은 자동 회귀 테스트로 검증한다.
