# 구현 계획: 공통 참조 데이터

기존 HTML과 CSS를 유지하고 docs/reference/reference.js에 Step별 문서 데이터와 DOM 렌더링을 둔다. HTML은 data-step 또는 목록 표시 속성과 공통 defer 스크립트로 구성한다. fetch·모듈 import·외부 의존성은 사용하지 않는다. textContent로 설명을 표시하며 상대 링크를 사용한다. header와 note는 제외한다.

기존 문서를 구조화한 데이터로 옮기고 목록 순서를 보존한다. 렌더링 검증에서 16개 Step의 데이터·표와 17개 문서의 공통 스크립트·링크를 확인한다. 헌장은 미작성 템플릿이며 원칙 검사 대상이 없다.

## 수정 설계

설정 파라미터 표는 상세 HTML의 section.parameters에 복원한다. 공통 JS 데이터의 parameters는 제거하고 렌더링할 때 HTML의 해당 노드를 기존 위치에 배치한다. 입력·출력은 기존 JS에서 유지한다. 내용 보존과 전체 페이지 연결을 검증한다.

## 입력 링크 설계

공통 JS에 생성 위치 대응을 두고 Output 행에 안정된 앵커를 부여한다. 중첩 영상 속성은 video_stream으로 연결하고 검출 사전은 두 검출 Step의 결과로 연결한다. 렌더링 후 URL 해시의 Output 행을 찾아 이동한다.

## 변수 단일 관리 설계

reference.js의 VARIABLES 사전에서 이름·설명 변형·출력 생성 위치를 관리한다. STEP_REFERENCE의 rows는 변수 ID와 설명 ID만 가진다. 중첩 변수는 상위 변수의 생성 위치를 참조한다. 기존 렌더링 결과와 링크를 변경 전후 대조한다.

## 설명 단일화 수정

VARIABLES의 descriptions를 단일 description으로 바꾸고 Step별 설명 ID를 삭제한다. 렌더러는 항상 같은 변수 설명을 사용한다. 기존 링크·Output 앵커·HTML 파라미터 표는 유지한다.

## 안정적인 변수명 참조 설계

VARIABLES의 키를 실제 변수명으로 바꾸고 입력·출력·생성 위치·상위 참조를 함께 이전한다. 변수 조회는 누락 시 대체 설명을 반환하고 생성 링크는 대상 Step의 출력 존재 여부까지 검증한다. 변경 전후 렌더링과 중간 변수 삭제를 검증한다.
