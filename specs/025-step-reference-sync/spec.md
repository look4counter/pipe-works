# 기능 명세: Step HTML 참조 문서와 소스 계약 동기화

**작성일**: 2026-10-11

**상태**: 명세 완료

**사용자 요청**: docs/reference에 만든 HTML에 대한 새 명세를 작성하고, 소스코드의 설정 파라미터 및 Input·Output 변수가 바뀌면 HTML에도 반영한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 소스 변경과 함께 문서 갱신 (우선순위 P1)

Step을 수정하는 개발자는 설정이나 입출력 계약을 바꾸는 작업에서 해당 Step의 HTML도 갱신한다. 문서 독자는 최신 코드와 같은 설명으로 파이프라인을 구성할 수 있다.

**우선순위 근거**: 잘못된 기본값이나 입력 조건 때문에 발생하는 구성 오류를 줄인다.

**독립 검증**: 변경한 Step의 소스와 상세 HTML에서 설정 및 입출력 항목을 대조한다.

**인수 시나리오**:

1. 설정 파라미터를 추가·삭제·이름 변경하면 같은 변경 작업에서 상세 HTML의 설정 목록에도 반영한다. 삭제한 항목의 설명은 남기지 않는다.
2. 기본값·허용 값·단위·설정 위치를 변경하면 HTML 설명을 함께 갱신한다.
3. Input·Output 변수를 추가·삭제·이름 변경하거나 조건·자료형·형상·제공 의미를 바꾸면 해당 목록과 설명을 함께 갱신한다.
4. 변수명이 같아도 원본 수정·기존 값 유지·새 컨텍스트 생성·변수 제거 동작이 달라지면 설명에 반영한다.
5. 계약에 영향을 주지 않는 내부 구현 변경은 내용을 불필요하게 수정하지 않고 영향 없음을 확인한다.

### 사용자 이야기 2 — Step 목록과 상세 문서 탐색 (우선순위 P2)

문서 독자는 목록에서 Step을 선택해 간략한 설명, 설정 파라미터, Input 및 Output을 확인한다.

**우선순위 근거**: 개별 문서를 쉽게 찾고 동일한 형식으로 비교할 수 있다.

**독립 검증**: 목록에 표시된 모든 Step의 상세 문서 링크와 공통 스타일 파일을 확인한다.

**인수 시나리오**:

1. Step을 추가·삭제·이름 변경하면 상세 파일과 index.html의 목록·링크·개수를 함께 갱신한다.
2. 모든 상세 문서는 공통 CSS를 사용하고 목록으로 돌아가는 링크를 제공한다.
3. 설정이나 입출력이 없는 Step은 없다는 사실을 명시하며 실제로 제공하지 않는 값을 출력으로 소개하지 않는다.

### 경계 사례

- 조건부로 필요한 입력, 생략 가능한 입력, 실행 모드에 따른 출력 차이를 명시한다.
- 상속하거나 감싼 Step의 계약이 영향을 받으면 관련 상세 문서도 함께 검토한다.
- YAML 설정과 생성자 전용 인자는 구분하며 필수 인자를 기본값이 있는 것처럼 설명하지 않는다.
- 내부 관리 변수와 인스턴스 내부 상태를 PipelineContext 출력으로 오인하지 않는다.
- 이전 옵션 이름의 검사·호환 정책을 바꾸면 HTML의 이전 이름 안내도 갱신한다.
- 구현과 오래된 문서가 충돌하면 현재 소스의 실제 동작을 기준으로 문서를 수정한다. 의도와 구현의 불일치는 별도로 보고한다.

## 요구사항

### 기능 요구사항

- **FR-001**: 대상은 src/pipeworks/embedded와 examples/step에서 제공하는 공개 Step 클래스이며, 문서는 docs/reference에서 관리한다.
- **FR-002**: index.html은 클래스명·간단한 설명·내장 또는 예제 구분·상세 문서 링크를 제공한다. 각 Step은 클래스명.html로 분리하고 공통 style.css를 사용한다.
- **FR-003**: 상세 문서는 클래스명, 간단한 설명, 설정 파라미터, 요구하는 Input 변수와 설명, 제공하는 Output 변수와 설명을 포함한다. 메서드별 API 설명은 요구하지 않는다.
- **FR-004**: 설정 파라미터 설명은 이름·기본값 또는 필수 여부·설정 위치·의미·단위·허용 값과 제약을 실제 코드에 맞게 제공한다. 생성자 기본값과 YAML 덮어쓰기의 관계를 설명한다.
- **FR-005**: Input·Output은 PipelineContext의 공개 계약을 기준으로 정리한다. 선택·조건부 요구사항, 자료형·형상·장치 조건과 변수 유지·수정·추가·제거를 필요한 항목에 명시한다.
- **FR-006**: 소스에서 설정 파라미터 또는 Input·Output 변수가 바뀌면 해당 HTML에도 같은 변경 작업에서 반영해야 한다. 이름뿐 아니라 기본값·단위·제약·의미·모드별 동작의 변경도 반영 대상이다.
- **FR-007**: Step 추가·삭제·이름 변경 시 상세 파일과 index.html의 목록·링크·개수를 함께 갱신한다. 관련 설명을 제외한 기존 내용과 공통 문서 형식을 유지한다.
- **FR-008**: 계약 변경 작업을 완료하기 전에 소스와 HTML의 설정·입출력 항목을 대조하고 목록·상세·CSS의 상대 경로 연결을 확인한다. 문서 갱신이 빠진 상태를 완료로 취급하지 않는다.
- **FR-009**: 설정·입출력이 없는 경우 이를 명시한다. 실제 구현이 수행하지 않는 DB 접근 등은 기능으로 설명하지 않는다.

### 주요 항목

- **Step 계약**: 클래스 식별, 설정 파라미터, 요구 입력, 제공 출력과 적용 조건으로 구성한다.
- **상세 문서**: 한 Step의 계약을 설명하는 HTML 파일이다.
- **목록 문서**: 제공 Step의 요약과 상세 문서 연결을 관리한다.

## 성공 기준

- **SC-001**: 대상 공개 Step 전체가 목록에 정확히 한 번 표시되고 각각 상세 문서로 연결된다.
- **SC-002**: 변경한 설정 및 입출력 계약의 모든 항목이 해당 HTML에 반영되어 이름·기본값·단위·조건·설명 불일치가 0건이다.
- **SC-003**: 삭제하거나 이름을 바꾼 항목에 대한 오래된 설명과 끊어진 문서·CSS 연결이 0건이다.
- **SC-004**: 모든 상세 문서에서 설정·Input·Output 설명 또는 해당 항목이 없다는 표시를 확인할 수 있다.

## 가정과 범위

- HTML은 직접 편집하는 참조 문서이며 소스 변경 작업에서 함께 유지보수한다. 자동 생성·파일 감시·자동 동기화 도구 구현은 이번 명세의 요구사항이 아니다.
- 새 명세는 docs/reference의 현재 파일 구조를 기준으로 한다. 기존 두 Step 시험용 MkDocs 명세와 별도로 관리한다.
- 이번 요청은 명세 작성이며 실제 소스코드나 HTML 변경 작업은 포함하지 않는다.
- 현재 문서는 내장 11개·예제 5개 Step으로 구성되지만 개수는 고정 계약이 아니며 공개 Step 변경에 따라 갱신한다.
- 헌장은 미작성 템플릿이므로 별도의 원칙을 추정하지 않는다. Markdown 산출물은 한글로 작성한다.

## 후속 요구사항: 공통 JavaScript 데이터 관리

모든 참조 HTML은 공통 reference.js를 불러와 클래스 설명·Input·Output을 표시한다. 설정 및 생성자 파라미터는 각 HTML에서 직접 관리한다. 문서 내용은 공통 데이터 한 곳에서 직접 관리하고 목록과 상세 페이지가 이를 함께 사용한다. 소스 계약 변경 시 공통 데이터를 갱신한다.

- **FR-010**: 모든 Step의 입출력 변수와 설명, 클래스명·분류·요약은 공통 JS 데이터에 보관한다. 설정 및 생성자 파라미터의 표·설명은 각 HTML에 보관하고 공통 JS에는 중복 저장하지 않는다.
- **FR-011**: 모든 HTML은 같은 JS를 포함하고 목록 또는 지정된 Step 상세를 표시한다. 기존 내용·순서·링크·공통 CSS를 유지하며 header와 note 문단을 다시 추가하지 않는다.
- **FR-012**: 별도 서버·빌드·네트워크 요청 없이 로컬 HTML에서 동작한다. 설명은 실행되는 HTML로 해석하지 않고 텍스트로 표시한다.
- **SC-005**: HTML 17개 모두 공통 JS를 포함하고 16개 Step의 기존 설정·입출력 설명을 표시한다.

명확화: 이번 사용자의 요청은 HTML 변수 설명 데이터를 공통 JS로 옮기는 작업이다. 소스 계약 자동 추출은 도입하지 않는다. JavaScript 비활성 시 실행 안내를 표시한다. 추가 질문이 필요한 핵심 모호성은 없다.

## 명확화: 생성자 파라미터는 HTML 관리

사용자 수정 요청에 따라 설정 표 전체를 각 상세 HTML에서 직접 관리한다. Input·Output과 기존 공통 설명 데이터는 JS에 유지한다. 내용과 표시 순서는 보존하며 새 header·note 문단을 추가하지 않는다.

## 후속 요구사항: 입력에서 출력으로 이동

- **FR-013**: Input 변수명에는 그 값을 생성하는 Step의 Output 항목으로 이동하는 링크를 제공한다. 중첩 속성은 해당 상위 Output으로 연결하며 여러 생성 경로는 함께 표시한다. 출력이 없는 추상 설명 항목에는 임의 링크를 만들지 않는다.
- **SC-006**: 생성 위치가 확인된 입력 링크는 실제 Output 행으로 이동하고, 모든 대상 파일·앵커가 존재한다.

명확화: 입력에서 출력으로 연결하는 문서 탐색 기능이다. packet은 송출 입력에서 NvidiaEncode 결과로 연결하고 디코더 입력에서는 RTSPSource 결과로 연결한다. 설정 표의 HTML 관리는 유지한다.

## 후속 요구사항: 변수 정의 단일 관리

- **FR-014**: 같은 입출력 변수의 이름·설명·생성 위치는 공통 변수 사전에서 한 번 정의한다. Step은 변수 식별자를 참조한다. 변수마다 설명 하나만 정의하며 모든 페이지가 같은 설명을 표시한다.
- **SC-007**: 중복 변수 정의 없이 기존 모든 입출력 설명·출력 앵커·입력 링크가 유지된다.

명확화: 같은 변수의 여러 설명은 공통 의미와 필요한 사용 조건을 담은 하나의 설명으로 통합한다. 생성자 파라미터는 HTML에서 계속 관리한다.

## 공개 범위 변경: RTSP 문서 제외

사용자 요청으로 RTSPSource와 RTSPPublish는 docs/reference의 목록·상세 페이지에서 제외한다. 해당 페이지로 향하는 변수 링크도 제거한다. 소스 Step은 유지하며, 문서 대상은 나머지 14개 Step이다. 이 결정은 앞선 전체 공개 Step 포함 및 16개 대상 기준을 대체한다.

## 공개 범위 변경: 보고·DB 예제 제외

사용자 요청으로 MetadataFromDB·SaveInferenceResultToDB·StreamReport를 참조 목록과 상세 HTML에서 제외한다. 관련 링크도 제거하며 소스코드는 유지한다. 앞서 제외한 RTSPSource·RTSPPublish와 함께 참조 문서 대상은 나머지 11개 Step이다.

## 후속 요구사항: 안정적인 변수명 참조

- **FR-015**: 공통 변수 사전은 v1 같은 순번 대신 실제 변수명을 키로 사용한다. Step 입력·출력과 생성 위치·상위 변수 참조도 변수명을 사용한다. 중간 항목 삭제 시 번호 재지정을 요구하지 않는다.
- **FR-016**: 변수 정의나 생성 위치가 삭제되어도 페이지 전체가 중단되지 않는다. 정의가 없는 항목은 변수명과 설명 누락 표시를 보여 주고 유효하지 않은 생성 위치 링크는 만들지 않는다.
- **SC-008**: 기존 내용과 링크를 보존하며 변수 정의 하나를 삭제한 경우에도 모든 대상 페이지가 오류 없이 렌더링된다.

명확화: 변수별 설명 하나와 HTML의 생성자 파라미터 관리는 유지한다. 사용자 편집한 설명은 보존한다. 추가 질문이 필요한 핵심 모호성은 없다.

## 공개 범위 변경: 탐지 보고와 TensorRT 예제 제외

사용자 요청으로 YoloDetectReport·TensorRTReport·TensorRTPreProcess·TensorRTPostProcess의 참조 목록과 상세 HTML을 제거한다. 해당 페이지로 향하는 생성 위치 링크를 제거하며 소스코드는 유지한다. 이전 제외와 함께 참조 대상은 나머지 7개 Step이다.

## 공개 범위 변경: BoxOverlay 제외

사용자 요청으로 BoxOverlay의 상세 HTML·목록·해당 문서로 향하는 링크를 제거한다. 소스코드는 유지한다. 참조 대상은 NvidiaDecode·NvidiaEncode·YoloDetect·TensorRTInference·CudaAsync·Tap의 6개 Step이다.
