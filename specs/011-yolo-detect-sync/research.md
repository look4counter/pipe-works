# 동기 GPU 감지 설계 조사

- 결정: 기존 GPU 변환·패딩·예측기와 원본 좌표 복원을 유지한다.
- 근거: 기본 Ultralytics 예측기의 NumPy 변환을 우회해 영상·감지 텐서의 CPU 복사를 막아야 한다.
- 대안: CPU 경로나 공유 배치 추론은 이번 단일 감지 계약과 다르다.
- 결정: 입력 준비 이벤트를 기다리는 별도 CUDA 추론 스트림에서 동기 실행하고 원본을 작업 완료까지 보관한다. Python 작업자와 GPU 스트림 분리는 서로 다른 개념이다.
- 근거: 별도 스레드와 입력 복제 없이도 입력 순서와 표면 수명을 보장한다.
- 결정: 모델 동명 YAML을 읽지 않고 예외를 전파한다.
- 근거: 지연·오류 통과 정책은 공통 Async가 선택적으로 적용한다.
- 결정: TensorRT의 슬롯 관리 메서드를 해당 작업자로 옮긴다.
- 근거: 제거할 YOLO 작업자를 상속한 기존 의존성을 끊고 TensorRT의 동작은 유지한다.
# 선택적 배치와 입력 사용 종료

최신 요청에 따라 YoloDetect가 직접 GPU 입력을 검증·복제하고 신호·local_yolo 제출·통계를 처리한다. 중간 위임과 별도 배치 클래스·모듈·공개 API를 제거하고 공유 작업자·배치 큐와 전처리 엔진은 재사용한다. 기본 개별 경로는 유지한다.

입력 사용 종료는 전역 상태나 컨텍스트 데이터 필드 대신 요청 실행 문맥의 콜백으로 전달한다. GPU 복제 호출 직후 호스트 완료를 기다리면 기존 큐 제출 경로에 대기를 추가하므로, CUDA 완료 이벤트를 전달하고 Async 타임아웃 경계에서 비차단 query로 확인한다. 미완료나 오류는 보수적으로 기존 복사를 수행한다. 콜백은 요청을 값으로 캡처하여 이전 실행 문맥의 지연 신호가 다음 요청에 적용되지 않도록 한다.
# 예측기 타입 캐시 추가 조사 (2026-10-10)

결정: 프로세스 내 타입 저장소와 최초 생성 잠금을 사용한다. 근거: 일반 호출은 타입 참조 반환만 수행하고 동시 최초 호출의 중복 클래스를 방지한다. 대안: functools 캐시는 동시 미스에서 중복 호출을 허용하며, 모듈 전역 클래스 선언은 Ultralytics의 지연 로드를 바꾸므로 제외한다. 생성 실패는 저장하지 않아 다음 호출에서 재시도한다.
