# 기능 명세: 동기 GPU YOLO 감지

**기준**: 2026-10-09 사용자 요청 — YoloDetect 내부 비동기를 제거한다.
**상태**: 명세 완료

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 기본 동기 추론 (P1)

사용자는 YoloDetect를 직접 등록하여 선택 프레임의 모델 로드, 변환, 추론과 결과 준비가 끝날 때까지 기다린다. 실패는 호출자에게 예외로 전달한다.

**우선순위 근거**: 비동기 실행 정책을 모델에서 분리한다.
**독립 검증**: 모델 초기화·추론을 이벤트로 막고 반환되지 않는 것과 호출 스레드를 확인한다.

1. 7개 입력과 간격 3에서는 1·4·7번째만 추론하고 동일 객체를 순서대로 전달한다.
2. 초기화나 추론이 오래 걸려도 해당 결과가 준비되기 전에 프레임을 전달하지 않는다.
3. 입력 검증·모델 로드·추론 오류는 원본 통과로 숨기지 않고 예외로 전달한다.
4. 모델 동명 YAML의 timeout을 읽지 않는다.

### 사용자 이야기 2 — 선택적 비동기 조합 (P2)

사용자는 공통 Async로 감싸 필요한 경우에만 시간 제한과 실패 시 원본 통과를 적용한다.

**우선순위 근거**: 앞선 공통 단계로 실행 정책을 재사용한다.
**독립 검증**: Async로 감싼 YoloDetect의 지연과 실패를 주입하고 원본과 늦은 결과 격리를 확인한다.

1. Async의 기한이 지나면 원본이 결과 없이 전달되고 늦은 추론은 원본을 바꾸지 않는다.
2. 모델 오류는 Async가 처리하여 원본을 통과시킨다.
3. TensorRTInference의 기존 제한 시간과 비동기 동작은 유지한다.

## 기능 요구사항

- **FR-001**: 모델 경로, classes, confidence, gpu_id, inference_interval 설정과 검증을 유지한다. 간격 기본값은 1이다.
- **FR-002**: 첫 프레임부터 지정 간격으로 선택하고 나머지는 detections=None으로 전달한다.
- **FR-003**: 모델 로드·변환·추론·결과 복원을 호출 스레드에서 실행하고 선택 프레임의 GPU 결과 준비까지 기다린다. 내부 작업자·요청 큐·시간 제한·사용 중 건너뜀을 제거한다.
- **FR-004**: 처리 스트림에서 모델을 지연 로드하고 재사용하며 설정 GPU가 바뀌면 다시 준비한다.
- **FR-005**: 성공 결과를 원래 컨텍스트에 연결하고 객체 식별·입력 순서를 유지한다.
- **FR-006**: 입력 검증, 모델 로드, 추론 실패는 예외로 전파한다.
- **FR-007**: 실제 실행한 추론의 GPU 완료까지 시간을 공통 통계에 기록한다. 실패 추론도 기록하되 입력 검증·모델 로드 실패는 제외한다.
- **FR-008**: 입력과 결과는 GPU에 유지하고 원본 해상도와 박스 좌표, 빈 결과 처리를 유지한다. 영상·감지 텐서의 CPU 복사와 CPU 대체 경로는 금지한다.
- **FR-009**: GPU uint8 NV12 입력의 장치·크기·형식을 검증한다. 입력 CUDA 준비 이벤트를 기다리는 별도 추론 스트림에서 동기 처리하여 원본 수명을 보장한다. Async 조합 시 원본 영상 스트림에 추론 작업을 제출하지 않는다.
- **FR-010**: 모델 동명 YAML의 timeout 조회를 제거한다. 비동기와 시간 제한은 공통 Async를 선택적으로 조합해서 적용한다.
- **FR-011**: TensorRTInference가 YoloDetect의 제거된 내부 작업자에 의존하지 않도록 분리하되 기존 TensorRT 비동기 계약은 유지한다.

## 주요 개체

- 입력: GPU NV12와 읽기 전용 영상 메타데이터, CUDA 스트림을 가진 컨텍스트.
- 동기 처리 구간: 선택 프레임을 하나씩 추론하며 모델을 재사용하는 입력 스트림.
- 출력: 원본 컨텍스트의 GPU 감지 결과 또는 간격으로 건너뛴 입력의 빈 결과.

## 성공 기준

- **SC-001**: 7개 입력·간격 3에서 추론 3회, 원본 7개를 순서대로 전달한다.
- **SC-002**: 이벤트로 차단한 초기화와 추론이 해제 전 반환되지 않으며 실행 스레드는 호출자와 같다.
- **SC-003**: 입력·로드·추론 오류가 호출자에게 전파되고 실패 추론 통계가 한 번 기록된다.
- **SC-004**: CPU 복사를 금지해도 실제 모델의 영상·박스가 CUDA에 남고 원본 크기와 좌표를 유지한다.
- **SC-005**: Async 조합의 지연·오류 원본 통과와 TensorRT 기존 테스트가 통과한다.

## 경계 조건

잘못된 GPU·픽셀 형식·자료형·크기는 예외이다. 빈 감지는 성공이다. 동명 YAML이 잘못되어 있어도 YoloDetect는 읽지 않는다. 실행 중 GPU 작업은 결과 준비 또는 예외 정리 전에 원본 소유권을 잃지 않아야 한다.

## 명확화 및 범위

### 2026-10-09

앞선 대화에 따라 내부 비동기를 없애고 동기 모델과 공통 Async를 분리한다. 별도 질문이 필요한 불명확한 사항은 없다. 직접 사용 시 오류 전파는 기존에 합의한 동기 단계 계약이다.

batch 옵션 추가, YoloDetectBatch 변경, TensorRT의 비동기 제거, 예제·공유 YAML 변경은 포함하지 않는다. 이전 비동기 요구사항은 이번 명세로 대체하며 과거 완료 작업은 작업 목록의 기록으로 남긴다.
