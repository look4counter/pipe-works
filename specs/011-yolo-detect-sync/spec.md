# 기능 명세: 비동기 GPU YOLO 감지

**기준**: 2026-10-08 사용자 요청 — CPU 복사 금지, 추론 지연·실패 시 영상 전달 유지, 모델 동명 YAML의 제한 시간

## 사용자 시나리오 (US1, 우선순위 P1)

사용자는 `YoloDetect`에 `.pt` 또는 `.engine` 모델 경로를 전달한다. 선택된 프레임의 추론은 영상 처리와 분리하여 실행한다. 결과가 제한 시간 안에 준비되면 해당 프레임에 연결하고, 지연되거나 실패하면 결과 없이 같은 컨텍스트를 전달한다. 첫 모델 초기화나 영구 정지로 영상 전달이 무한 대기하지 않아야 한다.

수락 조건: GPU NV12 영상의 변환, 추론 및 결과 전달 과정에서 영상과 감지 텐서를 CPU로 복사하지 않는다. 제한 시간 안에 완료된 원본 좌표의 GPU 결과만 해당 프레임에 연결한다. 입력 객체와 순서는 지연·실패와 관계없이 보존한다.

## 명확화 및 가정

CPU 복사 금지는 영상과 감지 텐서에 적용하며, 모델 파일 읽기와 제어·로그·시간 측정을 위한 CPU 실행은 허용한다. 결과는 배치 단계와 같은 GPU 텐서 계약을 따른다.

### 2026-10-08 명확화

- 질문: 제한 시간만 대기한 뒤 결과 없이 전달할지, 기다리지 않고 이전 결과를 이후 프레임에 적용할지? → 답변: 감지 결과 없이 즉시 전달하는 방식. 제한 시간이 지난 프레임과 작업자가 사용 중인 프레임에는 이전 결과를 적용하지 않는다.
- 가정: 제한 시간의 단위는 기존 배치 YAML과 같은 밀리초다. 파일이나 `timeout` 항목이 없으면 기본값 5ms를 적용한다. 0은 기다리지 않고 완료 여부만 확인한다. `max_batch_size`는 단일 감지 단계에서 사용하지 않는다.

## 기능 요구사항

- **FR-001**: `YoloDetect`는 모델 경로와 `classes`, `confidence`, `gpu_id`, `inference_interval` 설정을 받아야 한다. 간격 기본값은 1이고 1 이상의 정수만 허용한다.
- **FR-002**: 첫 프레임부터 설정된 간격의 프레임만 추론 대상으로 선택하며, 간격에 따라 건너뛰거나 작업자가 사용 중인 프레임은 `detections=None`으로 즉시 전달해야 한다.
- **FR-003**: 선택된 GPU의 8비트 NV12 프레임을 GPU에서 변환하고 영상 전달과 분리하여 한 프레임씩 비동기로 추론해야 한다. 영상과 감지 텐서의 CPU 복사는 금지하며, CPU 입력을 GPU로 옮기는 대체 경로도 제공하지 않는다.
- **FR-004**: 모델은 첫 선택 프레임에서 로드하고 처리 구간 내 후속 요청에 재사용해야 한다. 추론 설정을 `model.predict`에 전달해야 한다.
- **FR-005**: 제한 시간 안에 준비된 성공 결과만 원래 `PipelineContext.detections`에 붙이고 입력 객체와 순서를 유지해야 한다. 전달한 컨텍스트를 나중에 수정하거나 늦은 결과를 다른 프레임에 붙여서는 안 된다.
- **FR-006**: 입력 변환, 모델 로드 또는 추론 실패 시 오류를 기록하고 해당 프레임을 결과 없이 전달한 뒤 다음 프레임을 계속 처리해야 한다. 실패도 간격 계산에 포함한다.
- **FR-007**: 실제 시작된 추론 요청의 시간은 배치 단계와 같은 `StreamReport` 추론 통계 항목에 기록해야 한다. 입력 변환 실패는 추론 건수에 포함하지 않는다.
- **FR-008**: 결과의 원본 영상과 박스 텐서는 GPU에 남아야 하며, 영상 크기 및 박스 좌표는 원본 해상도를 기준으로 해야 한다. 감지 객체가 없는 결과도 유효하다.
- **FR-009**: 입력 GPU와 설정된 GPU가 다르거나 입력 형식·자료형·크기가 유효하지 않으면 FR-006에 따라 처리해야 한다. 입력 복제와 추론 사이의 실행 순서를 보장하고 영상 스트림에 추론 대기를 추가해서는 안 된다.
- **FR-010**: 모델의 확장자를 `.yml`로 바꾼 파일에서 `timeout`을 읽어야 한다. 유한한 0 이상 숫자만 허용하고 불리언은 거부해야 한다. 파일·항목 부재 시 5ms를 사용하며 배치 설정과 함께 있어도 동작해야 한다.
- **FR-011**: 제출 시점부터 제한 시간 안에 결과가 준비되지 않으면 결과 없이 전달해야 한다. 제한 시간이 지난 실제 추론은 강제로 취소하지 않으며, 완료될 때까지 새 추론을 쌓지 않아야 한다.
- **FR-012**: 단일 단계 인스턴스의 실행 중 추론과 보관 입력은 각각 최대 1개여야 한다. 영구 정지와 같은 인스턴스 재실행에서도 작업자나 큐가 계속 늘어나서는 안 된다.
- **FR-013**: 입력 종료·반복자 닫기 시 작업 종료를 무한히 기다리지 않아야 한다. 종료 이후 원래 실행의 컨텍스트를 수정하거나 새 프레임을 추론해서는 안 된다.
- **FR-014**: 비동기 작업에서 기록한 추론 통계는 요청을 제출한 파이프라인 실행에 귀속되어야 한다. 제한 시간을 초과한 실제 완료 추론도 그 실행의 통계에 기록해야 한다.

## 성공 기준

- **SC-001**: 간격 3이고 각 요청이 제한 시간 안에 완료되면 7개 입력 중 1·4·7번째만 추론하고 7개 객체를 같은 순서로 전달한다.
- **SC-002**: 첫 요청의 모델 인스턴스를 다음 요청이 재사용하고 클래스·신뢰도·GPU 설정이 전달된다.
- **SC-003**: 선택 프레임이 실패해도 다음 선택 위치가 바뀌지 않고 이후 프레임을 처리한다.
- **SC-004**: `StreamReport`는 이 단계와 배치 단계의 추론을 같은 건수·평균 형식으로 표시한다.
- **SC-005**: 영상·결과의 CPU 복사 호출을 금지한 상태에서도 감지를 완료하며 `.pt`와 `.engine` 결과의 영상·박스 장치가 CUDA이다.
- **SC-006**: 정사각형 및 직사각형 입력의 원본 영상 크기와 좌표가 보존되고, 빈 결과와 잘못된 입력 뒤에도 후속 프레임이 처리된다.
- **SC-007**: 500ms 이상 지연 또는 외부 해제를 기다리는 추론에 5ms 제한 시간을 적용해도 첫 프레임과 이후 프레임을 먼저 전달하고 입력 종료·닫기가 대기하지 않는다. 실제 실행 중 요청은 1개이며 늦은 결과는 폐기된다.
- **SC-008**: 동명 YAML의 유효 값·누락·잘못된 값과 0ms를 검증하고, 겹치는 실행의 추론 통계가 섞이지 않는다.

## 경계 조건

CPU 입력, GPU 번호 불일치, NV12가 아닌 형식, 홀수 해상도, 잘못된 자료형·크기는 감지 실패로 처리한다. 빈 감지 결과는 성공이다. 첫 모델 로드 지연, 추론 지연·실패·영구 정지, 늦은 성공, 입력 종료와 재실행에서도 영상 전달과 자원 상한을 유지한다. 잘못된 YAML 설정은 실행 시작 시 명확한 설정 오류로 알린다.

## 범위

이 단계는 GPU NV12 영상과 감지 결과를 GPU에 유지한다. 별도 YOLO 프로세스와 모델별 배치 큐를 사용하지 않는다. GPU 하드웨어 전체의 장애 복구, 실행 중 CUDA 호출 강제 중단 및 이후 단계의 결과 내보내기는 범위에 포함하지 않는다.
