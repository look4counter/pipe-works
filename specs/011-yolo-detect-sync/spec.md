# 기능 명세: 동기 GPU YOLO 감지

**기준**: 2026-10-09 사용자 요청 — YoloDetect 내부 비동기를 제거한다.
**상태**: 명세 완료

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 기본 동기 추론 (P1)

사용자는 YoloDetect를 직접 등록하여 선택 프레임의 모델 로드, 변환, 추론과 결과 준비가 끝날 때까지 기다린다. 실패는 호출자에게 예외로 전달한다.

**우선순위 근거**: 비동기 실행 정책을 모델에서 분리한다.
**독립 검증**: 모델 초기화·추론을 이벤트로 막고 반환되지 않는 것과 호출 스레드를 확인한다.

1. 7개 입력과 간격 3에서는 1·4·7번째만 추론하고 동일 객체를 순서대로 전달한다.
2. 초기화나 추론이 오래 걸려도 해당 결과가 준비되기 전에 프레임을 전달하지 않는다.
3. 입력 검증·모델 로드·추론 오류는 원본 통과로 숨기지 않고 예외로 전달한다.
4. 모델 동명 YAML의 timeout을 읽지 않는다.

### 사용자 이야기 2 — 선택적 비동기 조합 (P2)

사용자는 공통 Async로 감싸 필요한 경우에만 시간 제한과 실패 시 원본 통과를 적용한다.

**우선순위 근거**: 앞선 공통 단계로 실행 정책을 재사용한다.
**독립 검증**: Async로 감싼 YoloDetect의 지연과 실패를 주입하고 원본과 늦은 결과 격리를 확인한다.

1. Async의 기한이 지나면 원본이 결과 없이 전달되고 늦은 추론은 원본을 바꾸지 않는다.
2. 모델 오류는 Async가 처리하여 원본을 통과시킨다.
3. TensorRTInference의 기존 제한 시간과 비동기 동작은 유지한다.

### 사용자 이야기 3 — 공유 배치와 중복 복사 제거 (P1)

여러 영상을 처리하는 사용자는 같은 YoloDetect API에서 batch=True를 선택하고 공통 Async로 제한 시간을 적용한다. 배치 작업자가 이미 원본 입력을 분리했으면 제한 시간 이후 영상 전달에 추가 복사를 하지 않는다.

독립 검증은 배치 추론을 이벤트로 차단하고 완료된 복제 이벤트와 원본 프레임 식별을 확인한다. 복제가 아직 시작되지 않았거나 완료 이벤트가 준비되지 않았으면 기존 전달용 복사가 유지되어야 한다. 신호를 사용하지 않는 일반 Step과 batch=False의 동작은 유지되어야 한다.

## 기능 요구사항

- **FR-001**: 모델 경로, classes, confidence, gpu_id, inference_interval 설정과 검증을 유지한다. 간격 기본값은 1이다.
- **FR-002**: 첫 프레임부터 지정 간격으로 선택하고 나머지는 detections=None으로 전달한다.
- **FR-003**: 기본 개별 모드는 모델 로드·변환·추론·결과 복원을 호출 스레드에서 실행하고 선택 프레임의 GPU 결과 준비까지 기다린다. 개별 모드에는 내부 작업자·요청 큐·시간 제한·사용 중 건너뜀이 없다.
- **FR-004**: 처리 스트림에서 모델을 지연 로드하고 재사용하며 설정 GPU가 바뀌면 다시 준비한다.
- **FR-005**: 성공 결과를 원래 컨텍스트에 연결하고 객체 식별·입력 순서를 유지한다.
- **FR-006**: 기본 개별 모드의 입력 검증, 모델 로드, 추론 실패는 예외로 전파한다. 선택적 배치 모드는 기존 YoloDetectBatch처럼 로그와 빈 결과로 통과하고 다음 입력에서 재시도한다.
- **FR-007**: 개별 모드는 실제 실행한 추론의 GPU 완료까지 시간을 공통 통계에 기록한다. 실패 추론도 기록하되 입력 검증·모델 로드 실패는 제외한다. 배치 모드는 기존 배치 통계 계약을 유지한다.
- **FR-008**: 입력과 결과는 GPU에 유지하고 원본 해상도와 박스 좌표, 빈 결과 처리를 유지한다. 영상·감지 텐서의 CPU 복사와 CPU 대체 경로는 금지한다.
- **FR-009**: 개별 모드는 GPU uint8 NV12 입력의 장치·크기·형식을 검증한다. 입력 CUDA 준비 이벤트를 기다리는 별도 추론 스트림에서 동기 처리하여 원본 수명을 보장한다. Async 조합 시 원본 영상 스트림에 추론 작업을 제출하지 않는다. 배치 모드는 기존 복제·작업자 준비 이벤트 경로를 유지한다.
- **FR-010**: 개별 모드는 모델 동명 YAML의 timeout을 조회하지 않는다. 배치 모드는 같은 YAML의 max_batch_size와 밀리초 timeout으로 배치 수집을 설정한다. 추론 대기 제한은 공통 Async를 선택적으로 조합한다.
- **FR-011**: TensorRTInference가 YoloDetect의 제거된 내부 작업자에 의존하지 않도록 분리하되 기존 TensorRT 비동기 계약은 유지한다.
- **FR-012**: 생성자의 선택적 batch 인자는 불리언이며 기본값은 False이다. True이면 공유 모델·배치 구성·간격·GPU 감지 결과·통계 동작을 제공한다. 배치 API는 YoloDetect(batch=True)로 통일한다.
- **FR-013**: 배치 처리 단계는 원본 데이터 사용이 끝나는 시점을 공통 요청 신호로 알린다. GPU 복사가 진행 중이면 완료 이벤트를 함께 전달하고 그 완료 전에는 사용 종료로 간주하지 않는다.
- **FR-014**: Async는 입력 사용 종료가 확인된 타임아웃 요청을 복사 없이 전달하며 늦은 결과는 폐기한다. 신호 미제공·미완료·조회 오류에는 기존 타임아웃 복사를 수행한다. 신호는 해당 요청에만 적용하고 일반 Step에는 선택 사항이다.
- **FR-015**: 입력 사용 종료 신호는 Async 밖에서는 아무 동작도 하지 않는다. 신호 후 공유 입력을 다시 읽거나 수정하면 안 되며, 원본 컨텍스트 식별과 구성·출력·직렬화·종료 계약은 유지한다.
- **FR-016**: batch=True는 YoloDetect 내부에서 입력 복제·완료 이벤트·사용 종료 신호·local_yolo 제출·배치 통계를 직접 처리한다. YoloDetectBatch 클래스·모듈·공개 내보내기를 제거하고 예제·테스트·공개 문서를 새 API로 옮긴다. 이전 별칭은 제공하지 않는다.

## 주요 개체

- 입력: GPU NV12와 읽기 전용 영상 메타데이터, CUDA 스트림을 가진 컨텍스트.
- 동기 처리 구간: 선택 프레임을 하나씩 추론하며 모델을 재사용하는 입력 스트림.
- 출력: 원본 컨텍스트의 GPU 감지 결과 또는 간격으로 건너뛴 입력의 빈 결과.

## 성공 기준

- **SC-001**: 7개 입력·간격 3에서 추론 3회, 원본 7개를 순서대로 전달한다.
- **SC-002**: 이벤트로 차단한 초기화와 추론이 해제 전 반환되지 않으며 실행 스레드는 호출자와 같다.
- **SC-003**: 입력·로드·추론 오류가 호출자에게 전파되고 실패 추론 통계가 한 번 기록된다.
- **SC-004**: CPU 복사를 금지해도 실제 모델의 영상·박스가 CUDA에 남고 원본 크기와 좌표를 유지한다.
- **SC-005**: Async 조합의 지연·오류 원본 통과와 TensorRT 기존 테스트가 통과한다.
- **SC-006**: 두 모드 모두 7개 입력·간격 3에서 3개 요청을 만들고 순서와 객체 식별을 유지한다. 배치 모드의 공유 작업자와 모델 동명 설정을 재사용한다.
- **SC-007**: 배치 복사 완료 후 추론을 차단한 Async 요청은 타임아웃에도 추가 복사 없이 원본을 전달하며, 다음 단계의 원본 변경은 배치 입력에 영향을 주지 않는다.
- **SC-008**: 완료되지 않은 GPU 이벤트·신호 없는 요청·이전 요청 신호에서는 필요한 타임아웃 복사가 유지된다. 일반 Step의 선택적 신호와 직접 배치 사용 회귀 검증이 통과한다.

## 경계 조건

잘못된 GPU·픽셀 형식·자료형·크기는 개별 모드에서 예외이다. 빈 감지는 성공이다. 동명 YAML이 잘못되어 있어도 batch=False는 읽지 않는다. 배치 모드는 기존 입력 검증과 오류 통과 정책을 따른다. 실행 중 GPU 작업은 결과 준비 또는 예외 정리 전에 원본 소유권을 잃지 않아야 한다.

## 명확화 및 범위

### 2026-10-09

앞선 대화에 따라 내부 비동기를 없애고 동기 모델과 공통 Async를 분리한다. 별도 질문이 필요한 불명확한 사항은 없다. 직접 사용 시 오류 전파는 기존에 합의한 동기 단계 계약이다.

후속 요청으로 batch 옵션과 선택적 입력 사용 종료 신호를 추가한다. batch=False는 기존 동작을 유지하고 True는 기존 배치 동작을 재사용한다. 기존 YoloDetectBatch와 TensorRT 동작·사용자 예제·공유 YAML은 유지한다. 배치 여부는 생성자에서 선택하며 실행 중 모드를 바꾸는 설정은 추가하지 않는다. 신호의 미완료 이벤트는 기다리지 않고 기존 복사로 처리한다. 별도 질문이 필요한 불명확성은 없다. 이전 완료 작업은 이력으로 유지한다.

최신 명확화: 중간 YoloDetectBatch 위임을 제거하고 YoloDetect에서 직접 배치 요청을 처리한다. local_yolo의 공유 작업자와 수집 설정, 오류 통과·통계·간격·입력 사용 종료 정책은 유지한다. 추가 질문이 필요한 불명확성은 없다.

최신 제거 요청: 통합된 배치 구현을 기준으로 별도 파일과 클래스를 제거한다. 기존 배치 검증은 YoloDetect(batch=True)로 옮기고, 예제 순서 검증은 Async 내부 감지 단계를 확인하도록 갱신한다. 클래스명 설정은 YoloDetect 또는 Async.step을 사용한다. 과거 유지 결정은 이 요청으로 대체하며 모델 수집 설정·사용자 예제의 batch=True 설정은 보존한다.
