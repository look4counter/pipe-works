# 기능 명세: 동기식 YOLO 감지

**기준**: 현재 `src/pipeworks/embedded/yolo_detect.py` 동작

## 사용자 시나리오

사용자는 `YoloDetect`에 `.pt` 또는 `.engine` 모델 경로를 전달한다. 선택된 프레임은 단일 YOLO 추론이 끝난 뒤 같은 컨텍스트 객체로 다음 단계에 전달된다. 현재 01·02 예제는 별도 단계인 `YoloDetectBatch`를 사용한다.

## 기능 요구사항

- **FR-001**: `YoloDetect`는 모델 경로와 `classes`, `confidence`, `gpu_id`, `inference_interval` 설정을 받아야 한다. 간격 기본값은 1이고 1 이상의 정수만 허용한다.
- **FR-002**: 첫 프레임부터 설정된 간격의 프레임만 추론하며, 건너뛴 프레임은 `detections=None`으로 전달해야 한다.
- **FR-003**: 선택된 8비트 NV12 프레임을 CPU BGR 영상으로 변환하고 한 프레임씩 동기적으로 추론해야 한다.
- **FR-004**: 모델은 첫 선택 프레임에서 로드하고 처리 구간 내 후속 요청에 재사용해야 한다. 추론 설정을 `model.predict`에 전달해야 한다.
- **FR-005**: 성공 결과는 원래 `PipelineContext.detections`에 붙이고 입력 객체와 순서를 유지해야 한다.
- **FR-006**: 입력 변환, 모델 로드 또는 추론 실패 시 오류를 기록하고 해당 프레임을 결과 없이 전달한 뒤 다음 프레임을 계속 처리해야 한다. 실패도 간격 계산에 포함한다.
- **FR-007**: 실제 시작된 추론 요청의 시간은 배치 단계와 같은 `StreamReport` 추론 통계 항목에 기록해야 한다. 입력 변환 실패는 추론 건수에 포함하지 않는다.

## 성공 기준

- **SC-001**: 간격 3으로 7개 프레임을 입력하면 1·4·7번째만 추론하고 7개 객체를 같은 순서로 전달한다.
- **SC-002**: 첫 요청의 모델 인스턴스를 다음 요청이 재사용하고 클래스·신뢰도·GPU 설정이 전달된다.
- **SC-003**: 선택 프레임이 실패해도 다음 선택 위치가 바뀌지 않고 이후 프레임을 처리한다.
- **SC-004**: `StreamReport`는 이 단계와 배치 단계의 추론을 같은 건수·평균 형식으로 표시한다.

## 범위

이 단계는 GPU NV12 프레임을 CPU 영상으로 복사한다. 별도 YOLO 프로세스와 모델별 배치 큐를 사용하지 않는다.
