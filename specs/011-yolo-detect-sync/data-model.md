# 동기 감지 데이터 모델

- 입력: GPU uint8 NV12 프레임, 동일 GPU의 CUDA 스트림, 양의 짝수 너비·높이.
- 추론 입력: GPU RGB float 텐서, 크기 (1, 3, 640, 640).
- 모델: 처리 스트림에서 지연 로드하여 선택 입력에 재사용한다. GPU 변경 시 재생성한다.
- 결과: 원래 컨텍스트의 detections, 원본 크기 GPU RGB HWC 영상과 GPU 박스.
- 흐름: 입력 → 간격 선택 → 검증 → 모델 준비 → 변환·예측 → GPU 완료·좌표 복원 → 원본 전달.
- 오류: 예외 전파 후 처리 스트림이 끝난다. Async 조합 시 공통 래퍼가 복구한다.
- 개별 모드는 YOLO 요청 큐와 작업자 상태가 없다. 배치 모드는 기존 local_yolo의 공유 작업자와 요청 큐를 사용한다. TensorRT 요청 상태는 기존대로 해당 파일에 유지한다.
- batch는 생성자에서 정하는 불리언이며 기본값은 False이다. 자체 배치 처리 반복자는 입력마다 현재 감지 설정을 조회하고 GPU 복제·완료 신호·local_yolo 제출·통계를 직접 처리한다. 중간 YoloDetectBatch 인스턴스는 없다.
- 입력 사용 종료 신호는 Async 요청에 귀속되며 선택적 CUDA 완료 이벤트를 가진다. 이벤트 미완료 요청은 타임아웃 복사를 유지한다.
# 예측기 타입 캐시 추가 설계

프로세스 내 공통 예측기 타입은 미생성 상태에서 최초 성공 생성 후 준비 상태로 전환한다. 준비 상태의 타입은 개별·배치 추론 호출자가 공유한다. 생성 실패는 미생성 상태를 유지한다. 모델과 예측기 인스턴스는 이 캐시의 대상이 아니다.
