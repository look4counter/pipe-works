# 조사: RunOnce Step 래퍼

## 기존 래퍼 관례

EveryNFrames, CudaAsync, TapSkipIfBusy는 모두 Step을 구현하고 내부 Step을 Hotswap 또는 내장 Step으로 보존한다. 파이프라인은 _hot_steps를 통해 내부 Step을 찾아 설정을 적용하고 파일 변경 감시를 연결한다.

## 결정

- RunOnce는 embedded 패키지의 내장 Step으로 제공한다.
- 내부 Step에 첫 번째 컨텍스트만 전달한다. 이 방식은 이후 입력을 잃지 않으면서 내부 Step의 출력이 0개·1개·여러 개인 경우를 모두 보존한다.
- 내부 generator가 정상적으로 끝난 후에만 단회 실행 상태를 성공으로 전환한다. 예외가 발생하면 다음 처리에서 재시도할 수 있다.
- 별도 YAML 옵션은 두지 않고, 내부 Step 설정은 파이프라인의 기존 클래스명 섹션을 사용한다.

## 대안과 제외 이유

- 전체 입력 스트림을 내부 Step에 한 번 전달하는 방식은 내부 Step이 모든 입력을 소비하므로 이후 원본 통과가 불가능하고, 스트림을 버퍼링해야 하므로 제외한다.
- 최초 입력을 내부 Step에 전달하지 않고 side effect만 실행하는 전용 callback API는 기존 Step 조합성을 잃으므로 제외한다.
- 프로세스 전역 변수나 클래스 전역 상태는 서로 다른 래퍼 인스턴스의 독립성을 깨므로 제외한다.
