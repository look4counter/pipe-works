# 기능 명세: RunOnce Step 래퍼

**기능 브랜치**: `046-run-once`

**작성일**: 2026-10-21

**상태**: 초안

**입력**: 프로세스당 한 번만 실행되는 `RunOnce` Step 래퍼 추가

## 사용자 시나리오 및 테스트

### 사용자 스토리 1 - 스트림에서 한 번만 실행하기 (우선순위: P1)

파이프라인 작성자는 기존 Step을 `RunOnce`로 감싸서 해당 Step의 동작이 하나의 파이프라인 프로세스에서 최초 입력에 대해서만 실행되도록 선언한다. 이후 입력은 래퍼가 변경하지 않고 다음 Step으로 전달한다.

**우선순위 이유**: 초기화, 등록, 상태 기록처럼 스트림 전체에서 한 번이면 충분한 작업을 Step 코드의 의도와 사용 위치에서 읽기 쉽게 표현할 수 있다.

**독립 테스트**: 입력 컨텍스트 여러 개와 실행 횟수를 기록하는 내부 Step을 `RunOnce`로 감싼 뒤 전체 입력을 처리하고, 내부 Step은 최초 입력에 한 번만 호출되며 모든 입력이 출력되는지 확인한다.

**인수 조건**:

1. **주어진** `RunOnce`와 정상적인 내부 Step 및 여러 입력이 있을 때, **실행하면**, 내부 Step은 첫 입력에 대해 한 번 실행되고 이후 입력은 원본 컨텍스트로 전달된다.
2. **주어진** 입력이 비어 있을 때, **실행하면**, 내부 Step은 실행되지 않고 출력도 없다.
3. **주어진** 내부 Step이 첫 실행에서 예외를 발생시킬 때, **실행하면**, 예외가 호출자에게 전달되고 실행 완료 상태로 기록되지 않는다.
4. **주어진** 내부 Step이 첫 실행에 성공한 뒤 같은 `RunOnce` 인스턴스의 처리기가 다시 호출될 때, **실행하면**, 내부 Step은 다시 호출되지 않고 두 번째 입력 스트림은 그대로 전달된다.

---

### 사용자 스토리 2 - 기존 파이프라인 래퍼와 함께 사용하기 (우선순위: P2)

파이프라인 작성자는 `RunOnce`를 기존의 Step 래퍼 및 파이프라인 등록 흐름에 포함해도 설정, 직렬화 탐색, 실행 경로가 깨지지 않도록 사용한다.

**우선순위 이유**: 실제 사용에서는 래퍼가 파이프라인, 핫스왑, 비동기 래퍼와 결합되므로 기존 실행 경로와의 호환성이 필수다.

**독립 테스트**: `RunOnce`를 파이프라인에 등록하고 기존 래퍼와 조합한 구성에서 내부 Step의 단회 실행과 입력 전달을 확인한다.

**인수 조건**:

1. **주어진** `RunOnce`가 파이프라인에 등록될 때, **실행하면**, 일반 Step과 동일한 설정 및 입력/출력 계약으로 동작한다.
2. **주어진** 내부 Step이 `RunOnce`로 감싸질 때, **설정하면**, 내부 Step의 설정은 기존 Step 설정 방식으로 전달된다.

### 경계 조건

- 내부 Step이 하나의 입력에 대해 여러 출력을 내보내면 첫 실행에서 그 출력들을 모두 전달한다.
- 내부 Step이 입력을 소비하지 않고 종료하면 `RunOnce`는 내부 Step의 출력 계약을 새로 판단하지 않고 기존 Step의 결과를 전달한다.
- 한 번 실행이 완료된 뒤에는 입력 스트림을 미리 소비하거나 버퍼링하지 않는다.
- `RunOnce`는 인스턴스 단위로 상태를 관리하며 서로 다른 인스턴스는 각각 한 번 실행된다.

## 요구사항

### 기능 요구사항

- **FR-001**: 시스템은 정상적인 `Step` 인스턴스를 감싸는 `RunOnce` 래퍼를 제공해야 한다.
- **FR-002**: `RunOnce`는 인스턴스별로 최초 입력 처리 시 내부 Step을 정확히 한 번 실행해야 한다.
- **FR-003**: 최초 실행 성공 후의 모든 입력은 내부 Step을 거치지 않고 원본 컨텍스트 그대로 전달해야 한다.
- **FR-004**: 입력이 없으면 내부 Step을 실행하지 않아야 한다.
- **FR-005**: 최초 실행 중 예외가 발생하면 해당 예외를 전달하고 성공 완료로 표시하지 않아야 한다.
- **FR-006**: 내부 Step의 최초 실행 결과가 여러 컨텍스트인 경우 해당 결과를 모두 전달해야 한다.
- **FR-007**: `RunOnce`는 기존 `Step`의 설정 및 파이프라인 입력/출력 계약을 유지해야 한다.
- **FR-008**: 서로 다른 `RunOnce` 인스턴스는 실행 상태를 공유하지 않아야 한다.
- **FR-009**: 래퍼의 사용법은 클래스명과 생성자 호출만으로 단회 실행 의도를 식별할 수 있어야 한다.

### 핵심 엔터티

- **RunOnce 래퍼**: 내부 Step과 최초 실행 완료 상태를 보유하며, 입력 스트림의 첫 처리만 내부 Step에 위임한다.
- **내부 Step**: 기존 `Step` 계약을 구현하고 `RunOnce`가 최초 입력에 대해 호출하는 처리 단위다.

## 성공 기준

### 측정 가능한 결과

- **SC-001**: 여러 입력을 처리하는 테스트에서 내부 Step의 실행 횟수가 항상 1회이고, 성공한 최초 입력 이후의 입력 손실률이 0%여야 한다.
- **SC-002**: 빈 입력 처리에서 내부 Step 실행 횟수가 0회여야 한다.
- **SC-003**: 내부 Step의 최초 실행 예외가 원래 예외 유형과 메시지로 호출자에게 전달되어야 한다.
- **SC-004**: 사용자는 파이프라인 코드의 `RunOnce(SomeStep())` 표현만 보고 해당 Step이 단회 실행임을 별도 문서 없이 이해할 수 있어야 한다.

## 가정

- “프로세스당 한 번”은 하나의 `RunOnce` 인스턴스가 살아 있는 동안의 단회 실행으로 정의한다.
- 첫 입력은 내부 Step의 기존 처리 결과로 변환할 수 있으며, 이후 입력만 원본 그대로 통과한다.
- 동시 호출은 현재 파이프라인의 일반적인 단일 처리 흐름을 따른다. 별도의 스레드 안전성 보장은 범위에 포함하지 않는다.
- YAML 설정 항목을 추가하지 않으며, 래퍼는 Python 코드에서 명시적으로 사용한다.

## 범위 제외

- 프로세스 간 공유 상태 또는 여러 `RunOnce` 인스턴스 간 중복 제거
- 내부 Step의 출력 개수나 입력 소비 방식에 대한 새로운 검증 규칙
