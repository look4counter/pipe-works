# 기능 명세: 배치 여부와 독립적인 중앙 실행

**작성일**: 2026-11-06
**상태**: 명세 검토 완료
**요청**: Batch가 False일 때도 batch_server를 이용해 중앙 프로세스에서 실행한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 일관된 실행 위치 (우선순위: P1)

사용자는 추론의 배치 옵션에 관계없이 지정한 서버에서 전체 파이프라인을 실행한다. 실행 위치가 추론 설정에 따라 바뀌지 않는 것이 핵심 가치다.

**독립 검증**: 배치 참·거짓, 래퍼 내부 추론, 추론 없는 파이프라인의 중앙 실행 요청과 서버 별칭을 검사한다.

**인수 시나리오**:

1. batch=False인 추론과 서버 별칭을 지정하고 실행하면 전체 파이프라인이 해당 서버에서 실행된다.
2. batch=True인 추론을 실행하면 기존 중앙 실행과 공유 배치 처리가 유지된다.
3. 추론이 없거나 단계가 비어 있어도 동일한 중앙 실행 규칙을 적용한다.
4. 중앙 실행 중 서버는 전달된 파이프라인의 단계를 직접 처리하여 재귀적인 원격 요청을 만들지 않는다.

### 경계 사례

- 별칭을 생략하면 production 서버를 선택한다. 잘못된 별칭은 기존과 같이 생성 시 거부한다.
- 서버 연결·직렬화 실패는 호출자에게 전달하며 호출자 프로세스로 자동 전환하지 않는다.
- 래퍼 안에 들어 있는 추론도 실행 위치를 변경하지 않는다.

## 요구사항

### 기능 요구사항

- **FR-001**: Pipeline.run()은 batch 값과 추론 존재 여부에 관계없이 전체 파이프라인을 중앙 서버에서 실행해야 한다.
- **FR-002**: batch_server의 기본값 production, 별칭 검증, 같은 별칭의 서버 공유와 다른 별칭의 분리를 유지해야 한다.
- **FR-003**: batch=False는 개별 추론, batch=True는 공유 배치 추론이라는 기존 의미를 유지해야 한다.
- **FR-004**: 서버 내부 단계 실행, 종료 감지, 로그 전달과 오류 전달을 기존 중앙 실행 경로로 처리해야 한다.
- **FR-005**: 사용자 안내와 실행 경로 회귀 검증을 변경된 동작에 맞춰 갱신해야 한다.

### 주요 개체

- 파이프라인: 서버 별칭과 실행할 단계 목록을 보관한다.
- 서버 그룹: 별칭으로 구분되는 중앙 프로세스다.
- 추론 배치 옵션: 실행 위치와 독립적으로 요청 수집 방식을 선택한다.

## 성공 기준

- **SC-001**: 배치 참·거짓·추론 없음·빈 단계·래퍼 조합의 모든 검증 사례에서 지정한 중앙 실행 경로를 선택한다.
- **SC-002**: 기존 별칭 계약과 추론 동작의 관련 회귀 검증을 통과한다.
- **SC-003**: 최신 사용자 안내에 배치가 없으면 호출자에서 실행된다는 설명이 남지 않는다.

## 가정

- 중앙 실행을 항상 사용하며 별도의 공개 로컬 실행 옵션은 추가하지 않는다.
- 기존 내부 단계 실행기는 서버용으로 유지한다.
- 메모리 캐시 정책이나 배치 추론 알고리즘 변경은 범위 밖이다.
- Windows 중앙 서버 통합 실행에는 Named Pipe 생성 권한이 필요하다.
