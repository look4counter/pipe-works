# 구현 계획: RTSP 비디오 패킷 수신

**후속 변경**: 종료 이벤트와 컨텍스트 설계의 현재 계약은 [003 구현 계획](../003-step-yaml-config/plan.md)이 우선한다.

**작성일**: 2026-10-02  
**명세**: [기능 명세](spec.md)

## 요약

`RTSPSource`는 첫 비디오 스트림의 패킷을 생산한다. 연결이 끊기면 자원을 닫고 설정에 따라 재시도하며 반복자 닫힘을 처리한다.

## 기술 배경

- **언어**: 파이썬 3.11 이상
- **주요 의존성**: 프로젝트에 선언된 PyAV
- **저장소**: 사용하지 않음
- **검증**: 모의 컨테이너와 패킷을 이용한 로컬 실행 검사
- **대상**: 현재 `pipeworks` 패키지
- **범위**: `src/pipeworks/embedded/rtsp_source.py`만 수정

## 헌장 확인

프로젝트 헌장은 채워지지 않은 템플릿이므로 적용할 별도 원칙이 없다. 저장소의 `AGENTS.md`가 요구하는 명세·계획·작업·분석·구현·수렴 순서를 적용한다.

## 설계

1. `PipelineContext`에 비디오 스트림과 원본 패킷을 보존한다.
2. 기존 URL 생성 인자를 유지하고 전송 방식과 재연결 설정은 단계 설정에서 받는다.
3. `process()`는 이전 단계의 입력을 사용하지 않는 생성기로 구현한다. RTSP 연결에서 첫 비디오 스트림을 선택하고 크기가 있는 패킷만 제공한다.
4. FFmpeg 연결·수신 오류와 스트림 종료 시 연결을 닫는다. 재연결이 켜져 있으면 설정된 간격 뒤 재연결한다.
5. 생성기가 닫히면 반복을 끝낸다. 재연결이 꺼진 상태에서 연결·수신 오류나 스트림 종료가 발생하면 오류를 올려 `Pipeline.run()`을 중단한다. 비디오 스트림 부재도 호출자에게 오류로 알린다.

## 자료 모델

`PipelineContext`의 `video_stream`과 `packet`은 동일한 수신 연결에서 나온 원본 객체를 참조한다. 별도 복사나 디코딩은 수행하지 않는다.

## 공개 계약

- `RTSPSource(url)`은 기존 예제와 호환된다.
- 전송 방식과 재연결 여부는 단계 설정으로 지정한다.
- `process(inputs)`는 `PipelineContext`의 반복자를 반환한다. 소스 단계이므로 `inputs`를 읽지 않는다.
- RTSP 소스는 생성한 `PipelineContext`에 `video_stream`과 `packet` 속성을 넣는다.

## 검증 절차

- 모의 패킷의 순서, 빈 패킷 제외, 동일 원본 객체 전달을 확인한다.
- 모의 FFmpeg 오류와 스트림 종료 후 연결 닫힘 및 재연결을 확인한다.
- 재연결 비활성화와 생성기 닫힘 후 추가 연결이 없고 기존 연결이 닫혔는지 확인한다.
- 비디오 스트림 부재가 명시적인 오류를 내는지 확인한다.

## 현재 재연결 설계

- `RTSPSource`는 단계 등록 중 `configure()`가 호출될 때 기본 전송 방식, 제한 시간, 재연결 간격 및 재연결 활성 상태를 초기화한다.
- 설정에서 `reconnect`가 꺼져 있으면 연결 오류나 스트림 종료 후 오류를 올려 파이프라인 실행을 끝낸다.
- 재연결이 켜져 있으면 열린 연결을 닫고 설정된 간격만큼 대기한 뒤 다시 연다.
- 비디오 스트림 부재는 호출자에게 오류를 전달한다. 반복자 닫힘은 `finally`에서 연결을 정리한다.
