# 기능 명세: RTSP 비디오 패킷 수신

**기능 디렉터리**: `002-rtsp-packet-source`  
**작성일**: 2026-10-02  
**상태**: 구현 대상  
**입력**: 제공된 RTSP 패킷 수신 코드를 참고하여 현재 `RTSPSource`를 수정한다.

**후속 변경**: 단계별 설정, 단일 컨텍스트, 종료 이벤트 제거는 [003 명세](../003-step-yaml-config/spec.md)를 따른다. 재연결 동작은 이 명세의 현재 요구사항으로 유지한다.

## 사용자 시나리오와 검증

### 사용자 시나리오 1: 비디오 패킷 전달 (우선순위: P1)

사용자는 RTSP 주소를 지정한 소스 단계를 파이프라인 첫 단계로 등록하고, 수신된 비디오 패킷을 순서대로 다음 단계에 전달한다.

**우선순위 이유**: 입력 데이터가 있어야 이후 단계가 동작한다.

**독립 검증**: 모의 RTSP 연결에서 크기가 있는 패킷 두 개와 빈 패킷 하나를 공급하고 전달 순서와 내용을 확인한다.

**인수 조건**:

1. **주어진 조건** 비디오 스트림과 패킷이 있는 RTSP 연결일 때, **행동** 소스를 반복하면, **결과** 첫 비디오 스트림의 크기가 있는 패킷만 수신 순서대로 제공된다.
2. **주어진 조건** 패킷이 제공될 때, **행동** 다음 단계가 이를 받으면, **결과** 원본 패킷과 해당 비디오 스트림을 식별할 수 있다.

### 사용자 시나리오 2: 연결 복구와 종료 (우선순위: P1)

사용자는 일시적인 연결 실패 이후 수신이 재개되기를 기대하며, 재연결을 끄거나 반복자를 닫으면 자원 사용이 멈추기를 기대한다.

**우선순위 이유**: 실시간 입력은 연결 단절과 명시적 종료를 처리해야 한다.

**독립 검증**: 모의 연결에서 수신 오류와 스트림 종료를 유발하고 재연결 설정 및 반복자 닫기에 따른 자원 정리를 확인한다.

**인수 조건**:

1. **주어진 조건** 연결 또는 수신 중 FFmpeg 오류가 발생했을 때, **행동** 소스가 계속 실행되면, **결과** 현재 연결을 닫고 정해진 간격 뒤 재연결을 시도한다.
2. **주어진 조건** 스트림이 정상 종료되고 재연결이 켜져 있을 때, **행동** 소스가 계속 실행되면, **결과** 현재 연결을 닫고 재연결을 시도한다.
3. **주어진 조건** 재연결이 꺼져 있을 때, **행동** 수신 오류나 스트림 종료가 발생하면, **결과** 현재 연결을 닫고 실패를 호출자에게 알리며 파이프라인 실행을 중단한다.
4. **주어진 조건** 사용자가 반복자를 닫았을 때, **행동** 소스가 정리되면, **결과** 현재 연결이 닫힌다.

### 경계 조건

- 비디오 스트림이 없는 연결은 사용할 수 없는 입력으로 보고 오류를 호출자에게 전달한다.
- 크기가 없는 패킷은 이후 단계에 전달하지 않는다.
- 연결 정리 자체가 FFmpeg 오류를 일으켜도 원래 수신 흐름의 정리는 계속한다.
- RTSP 소스는 파이프라인 첫 단계로 사용하며 이전 단계의 입력을 소비하지 않는다.

## 요구사항

### 기능 요구사항

- **FR-001**: RTSP 소스는 기존 주소 인자를 유지해야 한다.
- **FR-002**: 첫 비디오 스트림에서 패킷을 순서대로 받아야 한다.
- **FR-003**: 크기가 없는 패킷은 제외해야 한다.
- **FR-004**: 전달되는 항목은 원본 패킷과 해당 스트림을 보존해야 한다.
- **FR-005**: 재연결이 켜진 경우 연결 또는 수신의 FFmpeg 오류와 스트림 종료 후 연결을 닫고 설정된 간격 뒤 재시도해야 한다.
- **FR-006**: 재연결이 꺼진 경우 연결 또는 수신 오류와 스트림 종료 후 현재 연결을 닫고 오류를 전달하여 파이프라인 실행을 중단해야 한다. 반복자를 닫으면 현재 연결을 닫아야 한다.
- **FR-007**: 비디오 스트림이 없는 연결은 오류로 알려야 한다.
- **FR-008**: RTSP 전송 방식은 기본값을 제공하고 선택적으로 지정할 수 있어야 한다.
- **FR-009**: 재연결 설정이 없으면 기본적으로 재연결을 시도해야 한다.

### 주요 개체

- **RTSP 소스**: 주소, 전송 방식, 재연결 설정을 가진 입력 단계.
- **패킷 컨텍스트**: 원본 비디오 패킷과 해당 스트림을 담은 `PipelineContext`.

## 성공 기준

### 측정 가능한 결과

- **SC-001**: 유효한 패킷 2개와 빈 패킷 1개를 입력했을 때 유효한 패킷 2개가 순서대로 전달된다.
- **SC-002**: 연결 오류 후 첫 연결이 닫히고 재연결이 1회 이상 시도된다.
- **SC-003**: 재연결이 꺼진 상태의 수신 실패는 오류로 파이프라인 실행을 끝내고, 반복자를 닫으면 현재 연결이 닫히며 추가 연결 시도가 발생하지 않는다.

## 가정

- 기본 재연결 간격은 3초, 연결 및 읽기 제한 시간은 5초이며 단계 설정으로 변경할 수 있다.
- 기존 예제의 생성 방식과 호환되도록 기본 RTSP 전송 방식은 TCP로 한다.
- 패킷을 디코딩하거나 통계를 기록하는 작업은 이 기능의 범위에 포함하지 않는다.
- 원본 패킷과 스트림은 기존 `PipelineContext`에 담는다.
