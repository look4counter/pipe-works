# 조사 기록

- Windows PyTorch는 프로세스 간 CUDA 텐서 공유를 지원하지 않는다. 영상 프레임을 중앙 프로세스 내부에 보관한다.
- 기존 예제는 Python 파일의 사용자 정의 단계 객체를 `Pipeline.step()`에 전달한다. 단순 JSON 구성으로는 기존 호출을 보존할 수 없어 `cloudpickle` 직렬화를 선택한다.
- 현재 배치 감지는 별도 YOLO 작업자 프로세스 없이 중앙 프로세스의 모델별 로컬 큐와 GPU 텐서를 사용한다.
- RTSP 수신 같은 블로킹 작업은 즉시 중단이 보장되지 않는다. 중단 이벤트 확인과 시간 제한을 함께 사용한다.
# 출력 전달 결정

중앙 프로세스가 여러 파이프라인을 동시에 실행하므로 스레드별 출력 대상을 사용한다. 중앙 프로세스의 전역 표준 출력을 단순 교체하는 방식은 서로 다른 호출자의 출력을 섞을 수 있다. 기존 호출자 연결에 출력 메시지를 추가하면 별도 포트나 공유 파일이 필요하지 않다.
## GPU 추론 조사 결과

설치된 Ultralytics의 기본 텐서 추론은 입력을 GPU에 둘 수 있지만 감지 후처리에서 원본 영상을 CPU 배열로 변환한다. 전용 감지 후처리에서 GPU 원본 영상을 유지하고, 모델 입력은 32 배수 크기의 정규화된 RGB 텐서로 만든다. 배치 큐는 중앙 프로세스 안의 스레드가 공유하므로 별도 프로세스나 GPU IPC 전송이 필요하지 않다.

## GPU 큐 동기화 조사 결과

별도 작업자 프로세스가 제거된 뒤에도 `YoloDetectBatch`는 GPU 프레임을 복제한 직후 호스트에서 스트림 전체 완료를 기다렸다. 같은 프로세스의 모델별 작업자에게 CUDA 이벤트를 넘기고 작업자 스트림만 복제 완료를 기다리게 하면 CPU 영상 스레드는 GPU 복제를 기다리지 않는다. 모델별 큐의 요청 완료 대기는 추론 결과를 전달하기 위해 유지한다.
