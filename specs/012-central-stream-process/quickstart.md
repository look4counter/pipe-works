# 검증 절차

1. 두 개의 호출자 프로세스에서 파이프라인을 실행한다.
2. 중앙 프로세스 PID가 같고 각 단계의 실행 PID도 중앙 프로세스와 같은지 확인한다.
3. 호출자 하나를 종료하고 해당 스트림만 정리되는지 확인한다.
4. 나머지 스트림을 종료한 뒤 오류와 정상 종료가 각각 호출자에게 전달되는지 확인한다.
5. 실제 GPU에서 중앙 프로세스 내부의 배치 추론 경로가 동작하는지 확인한다.

## 현재 검증 결과

- 중앙 프로세스 실행·오류·연결 종료 통합 테스트를 통과했다.
- 2026-10-03 전체 테스트 108개 실행 중 1개가 오류로 끝났다. `tests/test_yolo_detect.py`는 공유 YAML에 `YoloDetect` 섹션이 있다고 가정하지만 현재 예제는 `YoloDetectBatch`를 사용한다. 이 테스트는 현행 예제 계약과 일치하지 않는다.
- 실제 CUDA 텐서와 예제 TensorRT 모델을 사용한 중앙 프로세스 내부 추론을 확인했다.
- 실제 RTSP 스트림 50개 동시 실행은 실환경 부하 검증이 필요하다. 현재 02 예제의 기본 영상 목록은 5개다.
# Step 출력 확인

`examples/01_single_stream_rtsp_style.py`를 콘솔에서 실행하면 `StreamReport`와 `Sink(PostProcess())`의 출력이 모두 해당 콘솔에 표시된다. 다른 콘솔에서 실행한 파이프라인 출력은 전달되지 않는다.
## GPU 배치 감지 확인

`YoloDetectBatch`는 중앙 프로세스 내부에서 GPU NV12 프레임을 변환하고 같은 모델의 요청을 배치로 처리한다. 감지 결과의 좌표 텐서도 GPU에 남는다. 실제 `.pt`와 `.engine` 모델 및 GPU 검증은 `tests/test_local_yolo.py`에 포함되어 있다.

## 프레임 지연 진단

`StreamReport`는 FPS와 전체 프레임 처리 시간 다음에 단계별 평균을 항상 출력한다. `입력 대기`는 디코더가 프레임을 내놓은 뒤 배치 단계가 읽을 때까지의 시간이고, `배치 대기`는 읽은 뒤 배치 단계가 내보낼 때까지의 시간이다. `인코딩`과 `송출`은 각 호출 시간이다. 송출은 전체 프레임 처리 시간 측정이 끝난 다음에 수행되므로 두 수치를 단순 합산하지 않는다.

## 단일 영상 지연 최소화

`YoloDetectBatch`는 입력 프레임을 미리 읽지 않고 선택 프레임의 추론이 끝나면 즉시 내보낸다. 모델별 GPU 요청 큐와 `inference_interval`은 그대로 사용한다. `low_latency` 설정은 지원하지 않는다.

01 예제의 `BoxOverlay`는 감지 사각형을 인코딩 전 GPU NV12 프레임에 그린다. 공유 설정의 `line_width`, `line_color`, `keep_previous`로 선 두께·색과 추론을 건너뛴 프레임에서 이전 상자 유지 여부를 정한다. 새 감지 결과에 상자가 없으면 이전 상자를 지운다. `line_color`는 YAML에서 `"#00ff00"`처럼 따옴표로 감싼다.
