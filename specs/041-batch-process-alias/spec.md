# 기능 명세: 배치 프로세스 별칭

작성일: 2026-10-17
상태: 검증 완료

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 별칭으로 배치 프로세스 선택 (우선순위: P1)
개발자는 Pipeline 생성자에서 batch_process 문자열을 지정한다. 같은 별칭의 실행은 중앙 프로세스를 공유하고 다른 별칭의 실행은 분리한다.
인수 조건: 임의의 유효한 두 별칭에 대해 같은 별칭은 같은 PID, 다른 별칭은 다른 PID를 사용한다.

### 사용자 이야기 2 — 기존 실행 동작 유지 (우선순위: P1)
배치 추론이 없으면 호출자 프로세스에서 실행하고, 배치 추론이 있으면 별칭에 해당하는 중앙 프로세스에서 전체 파이프라인을 실행한다.
인수 조건: 별칭만 지정해도 로컬 실행이 중앙 실행으로 바뀌지 않으며 직렬화 후 별칭이 유지된다.

## 요구사항

- FR-001: development 불리언 인자를 제거하고 batch_process 문자열 인자를 제공한다. 기본값은 production이다.
- FR-002: 별칭은 기존 서버 그룹 규칙대로 영문자·숫자·밑줄·하이픈으로 이루어진 1~64자이며 대소문자를 구분한다. 잘못된 값은 생성 시 거부한다.
- FR-003: 같은 설치·Windows 사용자·별칭은 연결 주소와 시작 잠금을 공유한다. 다른 별칭은 분리한다.
- FR-004: 별칭은 생성자 전용이며 직렬화와 중앙 실행에 그대로 전달한다. 배치 유무에 따른 라우팅은 유지한다.
- FR-005: 예제·문서·관련 테스트를 갱신한다. 기존 내부 server_group과 CLI 이름은 유지한다.

## 성공 기준

- SC-001: 기본값·유효성·이전 인자 제거·직렬화 및 라우팅 검사가 통과한다.
- SC-002: 별칭별 실제 PID 공유·분리와 한 그룹 종료 후 다른 그룹 유지 검사가 통과한다.
- SC-003: 관련 비동기·중앙 프로세스 회귀 검사가 통과한다.

## 경계 조건과 가정

빈 문자열·공백·경로 구분자·불리언은 거부한다. 서로 다른 별칭이 같은 GPU를 쓰는 것은 허용하며 GPU 자원이나 장치 장애의 격리는 제공하지 않는다. 프로세스 자동 재시작 정책은 변경하지 않는다.

## 명확화 검토

현재의 기본 운영 그룹 production과 내부 별칭 규칙을 유지한다. 범위·데이터·오류·의존성·완료 조건을 검토했고 중대한 불명확성은 없으며 질문은 0건이다. 헌법은 미작성 템플릿이다.
