# 구현 계획: 내장 단계의 영상 처리 지속

## 기술 맥락과 헌법

기존 Python 3.11.9·PyAV·PyTorch·PyNvVideoCodec을 유지한다. 헌법은 미작성 템플릿이며 한글 문서와 필수 speckit 순서를 따른다. 새 의존성과 영상 복사는 없다.

## 구현 단계

1. src/pipeworks/embedded/recovery.py에 공통 GPU 장애 분류·안전한 정리와 직접 추론의 반복자 재생성 도우미를 둔다. 예외의 원인 사슬과 명시적인 CUDA 장애·메모리 부족을 확인하며 버퍼 안전성·동기화 실패는 명시적으로 치명 오류로 보존한다.
2. rtsp_source.py는 일반 연결·읽기 오류와 입력 종료를 닫힘·기존 간격·취소 가능한 재연결로 처리한다. rtsp_publish.py는 입력별 실패 경계를 두고 잘못된 패킷을 폐기하며 출력 실패 후 재연결한다. reconnect 인자는 호환을 위해 유지한다.
3. nvidia_decode.py는 입력별 일반 오류를 잡고 reset 후 키프레임을 기다린다. 잠금·반환·동기화 오류는 보존한다. nvidia_encode.py는 입력·패킷 오류 경계와 기존 1초 네이티브 재시도를 유지한다.
4. yolo_inference.py의 process 경계에서 성공 시 기존 세션을 유지하고 실패 시 해당 반복자 정리 후 다음 입력에서 재생성한다. 입력 추적 반복자는 상류를 닫지 않으며 상류 자체의 예외는 분리한다. 실패 입력의 model_output을 비우고 프로파일을 정리한다.
5. every_n_frames.py는 단계별 실패를 원본 통과로 바꾸고 내부 반복자를 재생성한다. 실행 주기와 폐기 신호를 유지한다. cuda_async.py와 tap_skip_if_busy.py는 작업 오류 중 GPU 장애를 호출자에게 전달하고 기존 일반 오류 복구는 보존한다.
6. tests/test_embedded_recovery.py와 기존 관련 테스트의 정책 기대값을 갱신하고 docs/pipeworks/embedded의 변경된 오류 계약을 동기화한다.

## 검증

각 단계에서 정상·실패·정상 입력, 하드웨어 오류 전파, 재시도 간격·자원 정리 및 기존 관련 테스트를 실행한다. 기존 오류 전파 테스트 중 변경된 계약만 갱신한다. 실제 RTSP 네트워크 실험은 가용성 한계를 기록한다.
