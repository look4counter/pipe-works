# 기능 명세: 내장 단계의 영상 처리 지속

**작성일**: 2026-10-20
**상태**: 명확화 완료

## 사용자 시나리오와 검증

### 사용자 스토리 1 — 잘못된 영상 입력에서 복구 (P1)

운영자는 일반 처리 오류로 파이프라인이 종료되지 않기를 원한다. 잘못된 패킷·프레임은 폐기하고 코덱·연결은 재생성하며 이후 정상 입력을 처리한다.
수락 조건: 정상·비정상·정상 입력에서 정상 영상이 계속 전달된다. 연결은 닫힌 후 기존 간격으로 재시도하며 중단·취소가 가능하다.

### 사용자 스토리 2 — 부가 처리 실패에도 영상 전달 (P1)

추론이나 주기 실행 내부 단계가 실패하면 해당 입력의 영상을 전달하고 다음 입력에서 처리를 다시 시도한다. 비동기 처리의 기존 원본 통과와 프레임 폐기 계약은 보존한다.
수락 조건: 직접 실행·비동기·주기 실행에서 일반 오류 후 원본 영상과 다음 정상 처리 결과가 전달된다.

### 경계 조건

실행 전 생성자·설정 검증은 유지한다. GPU 메모리 부족, 명시적인 CUDA 장치·드라이버 장애와 잠금 버퍼 안전성·GPU 동기화 실패는 전파한다. 중단 신호와 GeneratorExit·KeyboardInterrupt·SystemExit는 복구하지 않는다. 상류 사용자 생성기 자체의 종료는 내장 단계가 재생성할 수 없으며 오류를 숨겨 복구한 것처럼 처리하지 않는다. 손실된 영상 자체나 영구적인 네트워크·코덱 불일치의 재생 성공은 보장할 수 없다.

## 요구사항

- **FR-001**: 내장 소스·송출은 일반 실행 오류와 입력 종료 후 연결을 재생성한다. reconnect=False도 실행 중 중단을 요청하는 옵션으로 사용하지 않는다. 기존 간격·취소·정리와 정상 메타정보 공유를 보존한다.
- **FR-002**: 디코더의 잘못된 입력·미지원 코덱·출력 레이아웃과 일반 네이티브 실패는 해당 입력을 폐기하고 재생성 후 키프레임에서 재개한다. 인코더는 잘못된 입력·패킷을 폐기하고 일반 실행 실패 후 기존 재시도 간격으로 복구한다.
- **FR-003**: 직접 추론의 모든 백엔드·배치 모드에서 일반 오류는 실패 결과를 비우고 원본 입력을 전달하며 다음 입력에서 세션을 재생성한다. 프로파일과 세션을 정리한다.
- **FR-004**: 주기 실행은 내부 단계의 일반 오류·입출력 계약 위반을 기록하고 실패한 반복자를 정리·재생성하며 원본 입력을 전달한다. 주기와 명시적인 프레임 폐기 의미는 보존한다.
- **FR-005**: GPU·하드웨어 및 자원 안전성 오류는 일반 오류와 구분하고 전파한다. 비동기 작업 스레드에서도 호출자에게 전달한다. 실행 전 설정 검증은 유지한다.
- **FR-006**: 정상·실패·정상 재개, 연속 실패, 자원 정리, 중단·취소와 기존 소스·송출·코덱·추론·래퍼 회귀를 검증하고 문서를 동기화한다.

## 주요 개체

실행 실패 분류, 입력 프레임·패킷, 연결·코덱·추론 세션, 내부 반복자와 GPU 버퍼 소유권.

## 성공 기준

- **SC-001**: 일반 오류가 주입된 각 내장 처리 경로가 외부 예외 없이 다음 정상 입력을 처리한다.
- **SC-002**: 명시적인 GPU 장애와 안전하지 않은 버퍼 정리 실패는 전파되며 관련 회귀 테스트가 통과한다.

## 가정과 명확화

사용자 지시는 실행 중 무중단 정책이다. 잘못된 설정으로 시작하는 동작까지 자동 보정하지 않는다. 명확화 검토에서 기능·실패·통합·종료·범위·검증이 명확하며 질문은 0개다. 기존 명세의 일반 오류 전파와 reconnect=False 실행 중 종료 계약은 이번 정책으로 대체한다. 새 의존성이나 매 프레임 영상 복사는 추가하지 않는다.
