# 기능 명세: NVIDIA 비디오 인코딩

**작성일**: 2026-10-03

**상태**: 현행 구현 명세

**입력**: `NvidiaEncode`가 디코딩된 프레임을 인코딩하고 다음 단계에 송출 가능한 패킷 컨텍스트를 전달한다.

## 사용자 시나리오와 검증

### 시나리오 1: 프레임을 패킷으로 변환

사용자는 디코딩된 비디오 프레임을 NVIDIA 인코더로 압축해 RTSP 송출 단계에 전달한다.

**인수 조건**:

1. 첫 프레임의 비디오 스트림, CUDA 스트림, 픽셀 형식과 설정된 GPU·FPS로 인코더를 생성한다.
2. 인코딩 결과의 각 항목에서 압축 데이터를 꺼내 PyAV 패킷을 만든다.
3. 출력 컨텍스트에 패킷과 입력 비디오 스트림을 담는다.
4. 각 패킷에는 증가하는 PTS·DTS, 양수 시간 기준, 지속 시간을 설정한다.

### 시나리오 2: 여러 결과와 종료 처리

인코더가 프레임 하나에서 결과 여러 개를 내거나 내부에 결과를 보관해도 각 결과를 빠짐없이 전달한다.

**인수 조건**:

1. 비어 있는 결과는 패킷으로 만들지 않는다.
2. 여러 결과 항목은 원래 순서대로 개별 패킷이 된다.
3. 입력이 정상 종료되면 인코더의 잔여 결과를 가져와 같은 패킷 계약으로 전달한다.
4. 압축 바이트를 찾을 수 없는 결과는 명시적인 오류가 발생한다.

## 기능 요구사항

- **FR-001**: `NvidiaEncode`는 단계 설정에서 GPU 번호와 양수 FPS를 받아야 한다.
- **FR-002**: 첫 입력 프레임의 비디오 스트림과 CUDA 스트림, 픽셀 형식을 사용해 인코더를 만들어야 한다.
- **FR-003**: 인코더의 압축 결과가 단일 바이트열 또는 여러 항목일 때 각 결과에서 압축 바이트를 추출해야 한다.
- **FR-004**: 사전과 중첩 목록의 압축 데이터도 처리하고, 지원하지 않는 구조는 명시적인 오류를 내야 한다.
- **FR-005**: 비어 있지 않은 압축 결과마다 PyAV 패킷을 만들고 PTS·DTS, 시간 기준, 지속 시간을 설정해야 한다.
- **FR-006**: 생성한 패킷과 비디오 스트림을 일반 `PipelineContext`로 다음 단계에 전달해야 한다.
- **FR-007**: 빈 결과는 건너뛰고 입력이 정상 종료되면 인코더의 잔여 결과를 처리해야 한다.
- **FR-008**: 인코딩 과정은 전달받은 CUDA 스트림을 사용해야 한다.

## 성공 기준

- **SC-001**: 여러 사전 항목과 중첩 압축 데이터를 반환하는 모의 인코더에서 항목마다 실제 PyAV 패킷 하나가 나온다.
- **SC-002**: 세 출력 항목의 PTS와 DTS가 각각 `0`, `1`, `2`이고 시간 기준이 설정 FPS의 역수다.
- **SC-003**: 빈 결과가 전달되지 않고 종료 시 잔여 결과가 출력된다.
- **SC-004**: 압축 데이터가 없는 결과는 `TypeError`를 발생시킨다.

## 가정과 범위

- 입력 컨텍스트에는 `frame`, `video_stream`, `cuda_stream`, `pixel_format` 속성이 있다. 생성 단계는 [NVIDIA 디코딩 명세](../006-nvidia-decode/spec.md)에서 다룬다.
- 현재 구현은 첫 입력으로 인코더를 만들고 입력 도중 스트림 설정 변경에 따른 재생성은 수행하지 않는다.
- 실제 GPU와 RTSP 서버를 사용한 종단 간 검증은 별도 실행 환경이 필요하다.
- RTSP 연결과 패킷 송출은 [RTSP 송출 명세](../004-rtsp-publish/spec.md)에서 다룬다.

## 현행 검증 상태

- 패킷 변환과 타임스탬프 부여는 코드에서 확인되지만, 저장소의 테스트 모음에는 `NvidiaEncode`의 `Encode()`·`EndEncode()` 반환 형태를 직접 검증하는 테스트가 없다. SC-001~SC-004는 현재 테스트 실행으로 확인되지 않았다.
- 원본 `video_stream`을 인코딩된 패킷과 함께 전달한다. 이 스트림을 송출 템플릿으로 쓸 때 실제 RTSP 서버가 재인코딩 결과를 수용하는지는 종단 간 검증이 필요하다.
