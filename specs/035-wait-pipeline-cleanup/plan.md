# 구현 계획: 중앙 프로세스 정리 완료 대기

## 요약 및 기술 맥락

Python 3.11.9의 기존 threading.Thread·Event 및 Windows AF_PIPE 구성을 유지한다. 새 의존성과 공개 옵션은 없다.
수정 대상은 src/pipeworks/main.py의 _handle, 회귀 검증은 tests/test_central_shutdown.py, 사용자 안내는 docs/pipeworks/main.md다.

## 헌법 검토

헌법은 미작성 템플릿이므로 규범 검사를 생략한다. AGENTS.md의 한글 문서 및 전체 speckit 순서를 준수한다. 설계 후에도 위반 사항은 없다.

## 설계

1. 실행 Thread 참조를 보관한다.
2. 기존 연결 감시와 생존 신호 만료 판정은 유지한다.
3. 감시 루프의 finally에서 미완료 실행에 중단 신호를 보내고 시간 제한 없는 Thread.join으로 실제 작업자 종료를 기다린다.
4. _handle이 끝난 다음에만 기존 handle_client가 active_connections를 감소시킨다. 유휴 타이머와 새 요청 수락은 기존 구조를 유지한다.
5. finished 이벤트는 기존 결과 전송 완료 신호로 유지한다. 정리 대기는 이벤트 상태가 아닌 스레드 종료를 기준으로 한다.

## 검증 설계

- 단위: 연결 종료·생존 신호 만료·예상 밖 감시 오류에서 중단 신호와 정리 완료 순서를 확인한다.
- 통합: 고유 서버 그룹에서 중단 시 파일 기반 장벽으로 정리를 보류한다. 기존 10초+1초보다 긴 12초 동안 서버 생존을 확인한다. 정리 중 같은 서버에서 별도 실행을 완료한다. 장벽 해제 후 정리 완료 파일과 서버 유휴 종료를 확인한다.
- 정상 완료·실행 오류·그룹 분리는 기존 tests/test_central_process.py로 회귀 확인한다.
- 정리를 끝내지 않는 호출을 임의로 끊는 정책과 개별 비동기 단계 수명 변경은 범위 밖이다.
