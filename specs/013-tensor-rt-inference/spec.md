# 기능 명세: GPU TensorRT 추론 전용 단계

## 고정 입력 메타데이터 캐시 (2026-10-10)

- **FR-039**: 엔진의 입력 형상과 선택 프로파일의 동적 입력 최소·최대 형상을 세션 초기화 시 한 번 조회해 재사용한다. 고정 입력에는 프로파일 형상 조회를 하지 않는다.
- **FR-040**: 매 요청의 입력 rank·고정 차원·프로파일 범위 검증을 유지한다. 실행별 입력 형상 설정·형상 추론·출력 형상 및 입력·출력 stride 조회를 유지한다. 엔진 재로딩이나 GPU·프로파일 변경으로 새 세션을 만들면 캐시도 새로 만든다.
- **SC-016**: 반복 추론에서 엔진 입력 메타데이터 재조회가 없고, 입력 형상·프로파일 범위 오류·실행별 동적 출력과 stride·세션 재생성 회귀가 통과한다.

명확화: 사용자는 고정 메타데이터만 캐시하고 실제 실행의 출력 형상과 stride는 계속 조회하도록 승인했다. 세션의 엔진·프로파일은 수명 동안 고정이며 공개 입력·출력·동기화·할당기 정책은 변경하지 않는다. 추가 질문은 없다.

## 영상별 프로파일 및 배치 시간 단위 명칭 (2026-10-10)

### US5 영상별 실행 설정과 모델 공통 배치 설정 분리 (우선순위 P1)

사용자는 stream.yml의 TensorRTInference 아래 profile_index를 지정하고 모델 동명 YAML에 plugins·max_batch_size·timeout_ms를 지정한다. 서로 다른 영상은 같은 모델에서도 서로 다른 프로파일을 선택한다.

1. 두 TensorRTInference 인스턴스가 같은 모델을 사용하더라도 각자 지정한 프로파일로 추론한다. 기본 번호는 0이다.
2. 공유 배치에서 프로파일이 다르면 같은 형상의 요청도 섞지 않고 GPU·프로파일별 세션을 사용한다.
3. 실행 중 configure로 번호가 변경되면 다음 입력부터 해당 프로파일을 적용한다. 개별 모드는 기존 세션의 GPU 작업 완료 후 재생성한다.
4. yolo11n.yml의 timeout_ms: 20은 YOLO 및 TensorRT 공유 배치의 20밀리초 수집 대기를 뜻하며 추론 제한은 아니다.

- **FR-035**: profile_index는 TensorRTInference의 공개 속성과 클래스명 YAML 설정으로 옮긴다. 기본 0과 음수가 아닌 정수 검증을 유지하며 잘못된 설정은 기존 GPU·간격·프로파일 상태를 변경하지 않는다.
- **FR-036**: 개별 모드는 실행 중 GPU 또는 프로파일 변경 시 세션을 재생성한다. 공유 배치는 요청에 프로파일을 전달하고 호환 키와 GPU·프로파일별 세션 키에 포함하며 실패 시 해당 세션만 제거한다.
- **FR-037**: 모델 YAML의 배치 대기 키를 timeout_ms로 통일하고 YOLO·TensorRT 수집기가 밀리초를 초로 변환한다. 기존 기본값과 유한한 0 이상 숫자 검증 및 각 경로의 생략 정책을 유지한다. 이전 timeout 키는 변경 안내 오류로 거부한다.
- **FR-038**: plugins는 모델 YAML에 유지하고 모델 YAML의 이전 profile_index는 stream.yml의 TensorRTInference로 이동하라는 오류로 거부한다. 예제·사용 문서를 새 계약으로 이전한다.
- **SC-015**: 설정 검증·실행 중 변경·프로파일별 수집·세션 분리와 실패 격리·실제 엔진 두 모드·YOLO 및 TensorRT timeout_ms 회귀가 모두 통과한다.

명확화: 직전 사용자 설명에 따라 영상별 Step 인스턴스와 클래스명 YAML로 프로파일을 설정한다. plugins·배치 수집 설정은 모델 공통이다. 생성자 인자와 입력별 자동 프로파일 선택은 포함하지 않는다. 기존 FR-031~034의 모델 YAML 프로파일 위치 및 이전 timeout 설명은 FR-035~038로 대체한다. 이동과 명칭 변경에는 기존 프로젝트의 변경 안내 오류 정책을 적용한다. 핵심 모호성은 없어 추가 질문은 필요하지 않다.

## 모델 YAML의 프로파일 및 플러그인 설정 (2026-10-10)

### US4 모델별 실행 옵션 지정 (우선순위 P1)

사용자는 엔진과 동명의 `.yml` 한 곳에서 프로파일 번호와 외부 플러그인 목록을 지정한다. 독립 검증은 개별·공유 배치 양쪽에서 동일한 모델 설정을 적용하는 것이다.

1. 설정 파일이나 항목을 생략하면 프로파일 0과 빈 플러그인 목록으로 기존 엔진을 실행한다.
2. `profile_index: 1`과 `plugins: [custom.dll]`을 지정하면 해당 플러그인을 로드하고 프로파일 1을 선택한 다음 입력 형상을 설정한다.
3. 잘못된 번호·엔진 범위 밖 번호·선택 실패·잘못된 플러그인 목록과 누락 파일은 원인이 드러나는 오류로 처리한다.

- **FR-031**: 모델 동명 `.yml`의 `profile_index`는 기본값 0인 음수가 아닌 정수다. 불리언·실수·문자열·None·음수는 거부한다.
- **FR-032**: 개별 및 공유 배치 경로에서 선택한 프로파일을 실제 엔진에 적용하고 엔진 프로파일 수와 선택 성공을 검증한다. 입력 형상 설정 이전에 실행 스트림에서 프로파일을 선택하며 오류에 선택 번호를 표시한다.
- **FR-033**: 기존 모델 YAML의 `plugins` 목록과 YAML 디렉터리 기준 상대 경로·표준 플러그인 초기화·역직렬화 전 외부 플러그인 로딩을 양쪽 경로에서 유지한다. 누락 파일과 로딩 실패는 전파한다.
- **FR-034**: TensorRT 안내와 모델 YAML 예제에 두 옵션·기본값·경로 기준·재시작 필요를 설명한다.
- **SC-014**: 설정 검증·모형 엔진의 프로파일 선택 순서 및 오류·두 경로 설정 전달과 실제 다중 프로파일 엔진 검증 및 기존 TensorRT 회귀가 통과한다.

명확화: 직전 설명의 모델 동명 YAML을 사용한다. 실행 시작 시 설정을 읽고 공유 배치는 모델 작업자 생성 시 읽는다. 실행 중 파일 변경 자동 반영과 생성자 옵션은 범위 밖이며 반영하려면 실행을 다시 시작한다. 기존 배치 수집 크기와 대기 설정은 유지한다. 기존 프로파일 0 고정·plugins만 읽는 계약은 FR-031~034로 대체한다. 핵심 모호성은 없어 질문은 필요하지 않다.

## 프레임 간격 이름 통일 (2026-10-10)

### US3 프레임 단위 설정 사용 (우선순위 P1)

사용자는 YOLO와 TensorRT에서 같은 이름으로 프레임 추론 간격을 설정한다. 독립 검증은 새 설정 적용과 두 모드의 프레임 선택 확인이다.

1. 설정이 없으면 모든 입력을 추론하고 공개 속성의 기본값은 1이다.
2. `inference_interval_frame=3`이면 개별·배치 모드 모두 1·4·7번째 입력을 추론하며 나머지는 원래 객체를 `model_output=None`으로 전달한다.
3. 이전 설정 키가 있으면 새 이름을 안내하는 오류가 발생하고 기존 설정값은 유지된다.

- **FR-027**: TensorRTInference의 공개 속성과 클래스명 YAML 설정 키는 `inference_interval_frame`으로 통일한다. 기본값 1과 1 이상의 정수 검증을 유지하며 불리언은 거부한다.
- **FR-028**: 개별·배치 모드의 첫 입력부터 지정 간격으로 추론하는 동작과 건너뛴 입력의 원본 전달·출력 초기화를 유지한다.
- **FR-029**: 이전 `inference_interval` 설정 키는 새 키와 함께 있어도 변경 안내 오류로 거부하며 설정 상태를 변경하지 않는다.
- **FR-030**: README·TensorRT 안내·예제 YAML은 새 이름을 사용하고 이전 키의 이전 방법을 안내한다.
- **SC-013**: 새 이름의 기본값·설정 갱신·잘못된 값·이전 키 거부와 두 모드 간격 회귀 검증이 모두 통과한다.

명확화: 이름 변경 외에 추론 동작을 바꾸지 않는다. 이전 키 처리 방식은 기존 YOLO 계약을 따른다. 최신 FR-027~030은 아래 과거 산출물의 간격 이름을 대체한다. 불명확한 핵심 사항은 없어 추가 질문은 필요하지 않다. 경계값은 0·음수·불리언·실수·문자열·None 및 두 키 동시 지정이다.

**작성일**: 2026-10-08
**상태**: 명세 검토 완료
**입력 요구**: 전처리·후처리 없이 `model_input`의 GPU 텐서를 TensorRT 엔진으로 추론하고 `model_output`에 원시 출력을 전달한다.

## 사용자 시나리오와 수락 조건

### US1 추론 전용 단계 연결 (우선순위 P1)

사용자는 전처리 단계에서 GPU 텐서를 준비하고 `TensorRTInference(model_path)` 뒤의 후처리 단계에서 원시 출력을 읽는다.

1. 단일 입력 엔진에 GPU 텐서를 제공하면 엔진에서 읽은 입력 이름으로 연결하고 모든 출력을 실제 출력 이름과 GPU 텐서의 사전으로 반환한다.
2. 다중 입력 엔진에는 실제 입력 이름별 GPU 텐서 사전을 제공한다. 이름을 코드에 고정하거나 영상 크기·값·자료형을 자동 변환하지 않는다.
3. 추론이 제한 시간을 넘기거나 실패·사용 중이면 해당 컨텍스트는 `model_output=None`으로 전달되고 영상은 계속 흐른다.

### US2 다양한 엔진과 플러그인 사용 (우선순위 P1)

사용자는 고정·동적 해상도 및 플러그인을 사용하는 엔진을 동일 단계로 실행한다.

1. 엔진의 입출력 이름·모드·자료형·형상·장치 위치를 읽어 바인딩한다.
2. 엔진에 직렬화된 플러그인 및 표준 플러그인을 초기화하며 외부 라이브러리가 필요하면 모델 동명 YAML에 지정한다.
3. 입력에 따른 동적 형상과 실행 결과에 따른 동적 출력 크기를 처리한다. 지원하지 않는 장치·자료형·포맷·프로파일은 원인과 함께 실패 처리한다.

## 명확화 및 가정

기존 대화로 비동기·시간 초과·CPU 복사 금지 조건이 명확하므로 추가 질문은 없다. 단일 입력은 GPU 텐서, 다중 입력은 이름별 텐서 사전이며 출력은 출력 이름별 GPU 텐서 사전으로 고정한다. 단일 출력도 사전이다. CPU 바인딩과 벡터화 저장 형식은 지원하지 않으며 기본 최적화 프로파일 0을 사용한다. YOLO의 클래스·신뢰도 필터는 후처리이므로 이 단계의 설정에 포함하지 않는다. 배치는 이미 전처리에서 만든 텐서의 배치 차원을 그대로 사용하며 요청을 모아 배치하지 않는다.

## 기능 요구사항

- **FR-001**: `src/pipeworks/embedded/tensor_rt_inference.py`에 공개 `TensorRTInference` Step을 제공하고 embedded에서 가져올 수 있어야 한다.
- **FR-002**: GPU 텐서 또는 엔진 입력 이름별 GPU 텐서 사전을 `model_input`에서 읽어야 한다. 단일 텐서는 입력이 하나인 엔진에서만 허용한다.
- **FR-003**: TensorRT 엔진에서 모든 입출력 이름·모드·자료형·형상·위치·포맷을 읽고 GPU 주소로 연결해야 한다. 이름을 고정하지 않는다.
- **FR-004**: 전처리·후처리와 CPU 텐서 복사 없이 TensorRT로 추론해야 한다. 입력 자료형·GPU·형상은 엔진과 일치해야 하며 메모리 연속화를 위한 GPU 복제만 허용한다.
- **FR-005**: 유효한 완료 결과를 원래 컨텍스트의 `model_output`에 이름별 GPU 출력 사전으로 기록한다. 원시 출력 값·자료형·형상을 보존하며 빈 출력도 허용한다.
- **FR-006**: 동적 입력 형상과 실행 중에 결정되는 동적 출력 할당을 지원하고 프로파일 범위 및 바인딩 설정 실패를 검증해야 한다.
- **FR-007**: 역직렬화 전에 표준 플러그인을 초기화하고 엔진에 포함된 실행 코드·플러그인 로딩을 허용한다. 외부 라이브러리는 동명 `.yml`의 `plugins` 목록에서 읽으며 상대 경로는 YAML 디렉터리 기준이다. 누락 플러그인·실패 엔진은 오류를 기록한다.
- **FR-008**: 클래스명 YAML 섹션에서 `gpu_id`와 `inference_interval`을 받고 기본값은 0과 1이다. 모델 동명 `.yml`의 `timeout`은 유한한 0 이상 밀리초이고 기본값 5이다. 불리언·음수·잘못된 형식은 거부한다.
- **FR-009**: 추론은 단일 데몬 작업자와 전용 CUDA 스트림에서 수행한다. 입력 GPU 복제·준비 이벤트로 생산자와 순서를 보장하고 작업 중 입력 수명을 유지한다.
- **FR-010**: 제한 시간 초과·실패·추론 간격·작업자 사용 중에는 `model_output=None`으로 원래 객체를 전달한다. 늦은 출력으로 이미 전달한 객체를 수정하지 않는다.
- **FR-011**: 단계 인스턴스당 작업자와 실행 중 요청은 최대 1개다. 종료·반복자 닫기·재실행이 멈춘 추론을 무한히 기다리거나 작업자를 늘려서는 안 된다.
- **FR-012**: 실제 실행된 TensorRT 추론의 완료·실패 시간을 제출한 실행의 공통 추론 통계에 기록한다. 엔진 로딩과 입력 준비 실패는 제외한다.

## 주요 데이터

- 컨텍스트: `model_input`, `model_output`, 선택적인 생산자 `cuda_stream` 및 기존 영상 속성.
- 엔진 설정: 경로, GPU 번호, 추론 간격, 제한 시간, 플러그인 라이브러리 목록.
- 바인딩: 엔진에서 읽은 이름·입출력 구분·자료형·형상·GPU 주소.

## 성공 기준

- **SC-001**: 임의 이름의 단일·다중 입출력과 서로 다른 자료형을 가진 엔진에서 원시 GPU 값이 보존된다.
- **SC-002**: GPU 영상·결과의 CPU 복사 호출을 금지한 상태에서도 추론이 완료된다.
- **SC-003**: 입력에 따른 동적 크기, 데이터에 따른 출력 크기 및 빈 출력을 처리한다.
- **SC-004**: 지연·실패·초기화 정지에서도 제한 시간 이후 입력 순서가 유지되고 종료·재실행이 기다리지 않는다.
- **SC-005**: 표준·내장·외부 플러그인 로딩과 누락 시 실패를 검증한다.
- **SC-006**: 설정 오류·입력 이름 누락·자료형·장치·프로파일·지원 포맷 오류를 기록하고 이후 입력을 처리한다.
- **SC-007**: 요청 수와 작업자 수 상한, 늦은 결과 폐기 및 실행별 추론 통계를 검증한다.

## 경계 조건 및 범위

모델 파일 없음·손상, 플러그인 누락, 빈·잘못된 입력 사전, CPU 텐서, GPU 불일치, 형상 불일치, 지원하지 않는 자료형·호스트 바인딩·벡터화 포맷은 실패 처리한다. 실제 GPU 전체 장애 복구 및 CUDA 호출 강제 취소는 범위 밖이다. 엔진 생성·모델 전처리·후처리는 수행하지 않는다. 일반 TensorRT 엔진과 Ultralytics 메타데이터가 앞에 붙은 엔진을 읽는다.
## 후속 동기 실행 계약

- **FR-020**: TensorRTInference는 호출 스레드에서 동기 실행하고 GPU 완료 후 결과를 전달한다. 내부 작업자·요청 큐·자체 타임아웃·사용 중 프레임 통과는 제거한다. 시간 제한과 오류 통과는 공통 Async가 담당한다.
- **FR-021**: 연속 GPU 입력은 복제하지 않는다. 비연속 입력만 연속화한다. 입력 생산 완료를 확인한 별도 추론 CUDA 스트림을 사용하고 출력 및 오류 경로에서 제출된 작업 완료를 보장한다.
- **FR-022**: 모델 YAML은 plugins만 읽으며 기존 timeout 항목은 무시한다. gpu_id·inference_interval과 엔진 형식·플러그인·GPU 출력·통계 계약은 유지한다. 실패는 예외로 전파한다.
- **SC-010**: 호출 스레드 실행·복제 제거·간격·GPU 완료·Async 타임아웃 및 기존 엔진 검증이 통과한다.

명확화: 최신 요청은 과거 비동기·시간 제한 계약을 대체한다. 모델 동명 YAML은 다른 YOLO 경로도 공유하므로 timeout을 삭제하거나 거부하지 않고 TensorRT에서 읽지 않는다. 추론 GPU 제출 API는 비동기지만 Step은 완료까지 기다린다. 추가 질문은 필요하지 않다.
## 선택적 공유 배치

- FR-023: TensorRTInference(model_path, batch=False)는 기존 동기 경로를 유지하며 batch=True일 때 local_tensor_rt에 GPU 입력·준비 이벤트를 제출하고 출력 사전을 받는다. batch는 불리언만 허용한다.
- FR-024: 배치 모드에서도 gpu_id·inference_interval·입력 준비·원본 컨텍스트·GPU 결과와 호출자 추론 통계를 유지한다. 수집 시간은 모델 YAML이며 자체 추론 제한은 없다. 실패는 호출자에 전파하여 CudaAsync가 처리한다.
- SC-011: 기본 경로·배치 직접 제출·간격·준비 이벤트·통계·오류·생성자 검증이 통과한다.

명확화: local_tensor_rt의 배치 축 0·개별 배치 크기 1 계약을 사용한다. 임의 엔진 출력 일반화와 예제 모드 변경은 포함하지 않는다. 추가 질문은 필요하지 않다.

## 예제 후처리의 NMS 보호 복제 제거

- FR-025: examples/step/tensor_rt_post_process.py는 해당 요청의 원시 출력 prediction을 복제하지 않고 NMS에 직접 전달한다. NMS가 좌표 표현을 제자리에서 바꾸도록 허용하며 처리 이후 원시 출력은 재사용하지 않는다.
- FR-026: input.detections의 원본 영상 좌표·신뢰도·클래스·이름과 GPU 저장, 원본 frame 보존 및 모델 입출력 정리 동작을 유지한다. BoxOverlay는 후처리된 detections를 사용해 원본 영상에 표시한다.
- SC-012: NMS 전 clone을 금지한 실제 CUDA 검증에서 박스 선별·클래스 필터·좌표 복원·빈 결과·정리가 유지되며, 생성한 detections로 BoxOverlay가 원본에 표시한다. 제공된 실제 plan 후처리도 통과한다.

명확화: 최신 요청은 예제 TensorRTPostProcess의 NMS 전 prediction.clone() 한 곳을 제거하는 것이다. 원시 출력은 후처리가 단독으로 소비하고 정리한다. 사용자 예제 파이프라인·TensorRT 추론기·배치 출력 분리·BoxOverlay의 박스 보관 복제는 변경하지 않는다. 추가 질문이 필요한 모호성은 없다.
