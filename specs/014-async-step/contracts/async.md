# 공개 계약

```python
from pipeworks.embedded import Async
wrapped = Async(step, timeout_ms=5)
```

`step`은 `Step` 인스턴스이다. `timeout_ms`는 불리언을 제외한 유한한 0 이상의 숫자이다. 성공 결과는 원본 속성 사전을 교체하되 원본 객체 식별은 유지한다. 정상 완료·제시간에 끝난 실패·사용 중 통과는 데이터 복사를 하지 않는다. 타임아웃에만 후속 전달용 데이터를 복사하고 같은 원본 객체의 속성을 교체한다. 복사 실패 시 작업 완료를 기다리고 원본을 전달한다.

```yaml
Async:
  timeout_ms: 10
YoloDetect:
  inference_interval_frame: 3
```

Async는 timeout_ms만 받는다. 내부 단계 설정은 Pipeline이 각 클래스명 최상위 섹션에서 전달하고 실행 중 변경도 각 단계 처리 경계에 적용한다. step·steps 매핑과 평면 내부 설정은 오류로 거부한다.

감싼 단계는 입력마다 한 번 출력하고 GPU 작업을 포함한 입력 사용을 출력 전에 마쳐야 한다. 작업용 컨텍스트에는 속성 추가·교체·삭제가 가능하나 공유 텐서·프레임·중첩 객체는 읽기 전용이다. 입력을 수정하려면 해당 Step이 새 데이터를 만들어 반환해야 한다. 출력 후 데이터를 사용하거나 공유 스트림을 수정해서는 안 된다. 타임아웃 복사 동안 전달이 더 늦어질 수 있다. DLPack 공급자는 텐서가 살아 있는 동안 메모리를 재사용하지 않아야 한다. 외부 저장·전송은 취소하지 않는다. 소스·집계·다중 출력은 지원하지 않는다.

`pipeworks.execution.release_input(*, ready_event=None)`은 현재 요청의 공유 입력 사용 종료를 알리는 선택적 API이다. CUDA 완료 이벤트를 넘기면 Async는 query 결과가 참일 때만 타임아웃 복사를 생략한다. 이벤트를 넘기지 않으면 호출 시점에 공유 입력 사용이 끝났음을 보장해야 한다. 이후 공유 입력을 다시 읽거나 수정하면 안 되며 출력용 컨텍스트의 결과 속성 갱신은 가능하다. Async 밖에서는 아무 동작도 하지 않는다. 신호 미제공·미완료·조회 실패에는 기존 복사를 유지한다.
## 복수 단계 계약

Async(first, second, ..., timeout_ms=5)는 하나 이상의 Step을 받는다. steps 튜플은 전체 목록이고 step은 첫 항목으로 기존 단일 API를 유지한다. 제한 시간은 전체 요청에 적용한다. 실행 중인 작업은 끝나도록 두며 만료 후 남은 단계는 시작하지 않는다. 단계마다 입력 하나에 출력 하나가 필요하고 오류 시 전체 연결 반복자를 닫는다. 복수 모드에서는 release_input 신호를 무시한다.

단일·복수·중첩 Async의 내부 설정은 모두 클래스명 최상위 섹션을 사용한다. 누락 섹션은 빈 매핑이며 같은 클래스 인스턴스는 같은 설정을 받는다. YAML 변경은 내부 Hotswap에 독립 연결되고 잘못된 값은 해당 단계 이전 설정을 유지한다.
