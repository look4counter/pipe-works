# 구현 계획: 공통 Async 단계

**작성일**: 2026-10-09 · **명세**: [spec.md](spec.md)

## 요약

`src/pipeworks/embedded/async_step.py`에 일반 `Step`을 감싸는 `Async`를 추가한다. 지속 입력 반복자와 단일 요청 슬롯을 통해 단계의 지역 상태를 유지하고, 완료 이벤트와 단조 시계로 기한 내 결과만 원본에 반영한다. 모델 코드는 변경하지 않는다.

## 기술 환경

- 언어: Python 3.11.9.
- 의존성: 표준 라이브러리 스레드·문맥·복사, 기존 PyTorch. 새 의존성 없음.
- 대상: CPU 검증 환경과 CUDA 영상 파이프라인.
- 검증: unittest, 이벤트 기반 차단 및 재개 테스트. GPU 테스트는 CUDA가 있을 때 실행한다.
- 성능: 처리 중 후속 입력은 복사도 하지 않고 통과한다. 대기는 남은 기한만큼만 한다.
- 제약: 한 입력당 한 출력, 공유 입력은 읽기 전용. 속성 변경은 작업용 컨텍스트에서 수행한다. 타임아웃 복사 자체나 외부 부작용은 강제 취소하지 않는다.

## 헌장 확인

헌장은 미작성 템플릿이므로 원칙 검증을 생략한다. 저장소 지침의 한글 문서와 speckit 순서를 준수한다. 기존 사용자 변경은 보존한다. 설계 후에도 충돌 없음.

## 구조와 설계

- `src/pipeworks/embedded/async_step.py`: 입력 복사, 단일 요청 슬롯, 작업 스레드와 공개 단계.
- `src/pipeworks/embedded/__init__.py`: `async_step` 모듈에서 일반 가져오기 구문으로 `Async`를 공개한다.
- `tests/test_async.py`: 성공 결과, 상태, 오류 재시도, 지연·사용 중 통과, 입력 격리, 종료, 계약과 설정 검증.
- `src/pipeworks/main.py`: 감싼 사용자 단계의 중앙 프로세스 직렬화 등록. Async 작업자의 출력 전달도 기존 중앙 출력 경로를 따른다.
- `docs/pipeworks/embedded/async.md`와 `README.md`: 공개 사용 안내.

슬롯은 제출된 요청을 입력 반복자로 전달한다. 출력 전에 다음 입력을 읽으면 계약 위반이다. 정상 출력은 요청을 완료하고 슬롯을 비운다. 예외나 조기 종료에는 원본 통과 후 다음 요청부터 처리 반복자를 재생성한다. 출력 반복자의 종료 처리는 작업자에서 수행한다.

제출 시 속성 사전을 얕게 분리하고 DLPack 프레임을 복사 없이 텐서로 가져온다. 원본 필드와 텐서 소유권 및 생산자 CUDA 이벤트를 요청에 보관한다. 정상 완료에는 데이터 복사가 없다. 타임아웃 판정 후에만 원본 필드의 깊은 복사와 텐서 복제를 수행하여 후속 전달용 컨텍스트를 만들고 GPU 복사 완료를 확인한 뒤 같은 원본 객체의 속성을 교체한다. 작업자는 원본 데이터를 계속 참조한다. 완료 시 CUDA 작업을 확인하고 슬롯을 해제한다. 복사 실패에는 작업 완료와 제출된 복사를 정리할 때까지 기다리고 원본을 전달한다.

PyNvVideoCodec 2.2 공식 DLPack 문서에 따르면 텐서가 파괴될 때까지 프레임이 메모리 소유권을 유지한다. 일반 외부 공급자도 같은 수명 계약을 지켜야 한다. 타임아웃 여부 판정과 결과 채택은 슬롯 잠금으로 직렬화하되 복사 중에는 잠금을 잡지 않는다. 정상 경로 무복사, 타임아웃 복사 방향, 복사 완료 경합, 오류·재수락·소유권 및 실제 CUDA/DLPack 검증을 수행한다. 기존 쓰기 기반 테스트는 읽기 전용 계약과 타임아웃 후 분리 검증으로 갱신한다.

`configure`는 `timeout_ms`를 래퍼에서 읽고 `step` 하위 매핑을 감싼 단계에 전달한다. 하위 매핑이 없으면 제한 시간 외의 구성 항목을 직접 전달한다. 기존 파이프라인 설정 갱신 경로를 사용한다. 사용자 단계 코드 핫스왑은 이번 범위에 추가하지 않는다.

## 구현 순서

1. 명세·계획·계약과 테스트 작성.
2. 슬롯, 입력 복사, 작업자, 기한 처리 구현.
3. 공개 가져오기와 구성 통합, 문서 작성.
4. 집중 검증과 전체 회귀 검증 후 명세 대비 수렴 점검.

## 후속 파일명 변경

모듈 파일명을 `src/pipeworks/embedded/async_step.py`로 정규화한다. 패키지 공개 가져오기, 테스트의 모듈·로그 참조, 현재 문서의 경로를 갱신한다. `tests/test_async.py`와 `tests/test_yolo_detect.py`를 실행하여 가져오기와 직렬화, 오류 로그 경로를 검증한다. 처리 로직과 클래스 이름은 유지한다.
