# 데이터 모델

작업 요청은 원본 필드를 유지하는 소유자, 공유 데이터를 가진 별도 작업 컨텍스트, 원본 텐서 참조, 실행 문맥, 준비 이벤트, 완료 이벤트·시각, 성공 결과를 가진다. 준비 → 제출 → 실행 → 완료로 이동한다. 시간 초과는 결과 채택을 중단하고 후속 전달용 복사를 시작한다. 작업 완료와 복사 완료는 서로 다른 시점이며 양쪽이 끝날 때까지 요청의 입력 참조를 유지한다.

요청 슬롯은 조건 변수, 보류 요청, 현재 요청, 닫힘 상태를 가진다. 보류 또는 현재 요청이 있으면 추가 제출을 거부한다. 출력 없이 다음 입력을 요구하면 계약 위반이다.

선택적 입력 사용 종료는 요청의 release_requested와 release_event로 기록한다. 신호 미제공은 기존 타임아웃 복사를 유지한다. 이벤트가 없으면 사용 종료가 즉시 확인되며, 이벤트가 있으면 query 완료 확인 후에만 복사를 생략한다. 실행 범위 콜백은 요청에 귀속되며 이전 요청의 콜백은 슬롯 검사에서 무시된다.
## 복수 단계

CudaAsync.steps는 Step 인스턴스 튜플이다. 연결 단계별 입력 슬롯은 현재 입력과 소비 여부를 보관하며 출력 반복자는 요청 사이에 유지한다. 요청의 공통 기한을 상류 결과 수신 뒤 검사한다. 복수 모드 입력 종료 콜백은 무동작이며 보관한 원본과 타임아웃 복사 정책은 유지한다.
