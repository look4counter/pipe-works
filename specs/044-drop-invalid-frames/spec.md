# 기능 명세: 잘못된 NV12 프레임 폐기

**작성일**: 2026-10-19
**상태**: 명확화 완료
**요청**: 자동 크기 보정 없이 잘못된 프레임을 버리고 계속 처리한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 영상 처리 지속 (우선순위 P1)

운영자는 잘못된 NV12 크기 때문에 정상 프레임 처리까지 중단되지 않기를 원한다.
독립 검증은 정상·비정상·정상 프레임을 연속 입력하고 정상 두 프레임만 출력하는 것이다.

1. 높이 또는 너비가 홀수인 프레임이 들어오면 그 프레임만 폐기하고 다음 정상 프레임을 처리한다.
2. 크기가 0 이하이거나 유효한 정수가 아니거나 버퍼가 명시된 NV12 크기보다 작으면 폐기한다.
3. 연속 비정상 입력과 빈 입력은 출력 없이 정상적으로 소진한다.
4. 비동기 처리와 주기 실행 안에서도 폐기된 프레임은 후속 단계로 전달하지 않는다.

### 사용자 이야기 2: 오류 구분과 진단 (우선순위 P2)

운영자는 폐기 원인을 확인하고, 다른 오류가 숨겨지지 않기를 원한다.
독립 검증은 폐기 경고와 기존 설정·픽셀 형식 오류 동작을 확인하는 것이다.

1. 크기 오류에 의한 폐기는 경고로 기록한다.
2. 설정 오류, 지원하지 않는 픽셀 형식, 자료형·장치 오류와 실행 오류는 기존 정책을 유지한다.

### 경계 조건

- 프레임 폐기는 원본 버퍼와 높이·너비를 수정하지 않는다.
- 정상 NV12의 피치 여유 공간을 허용하는 기존 동작을 유지한다.
- 폐기 전에 시작한 추론 프로파일은 종료하고 컨텍스트에서 제거한다.
- 폐기 시 GPU 작업을 새로 제출하지 않으며 입력 소유권은 기존 반복자 수명 규약에 따른다.

## 요구사항

- **FR-001**: 전처리와 박스 표시에서 잘못된 NV12 크기의 프레임을 출력하지 않고 다음 입력을 처리해야 한다.
- **FR-002**: 크기 보정을 위해 원본 영상이나 크기 메타데이터를 변경하지 않아야 한다.
- **FR-003**: 크기 오류 이외의 예외와 설정 검증은 기존 정책을 유지해야 한다.
- **FR-004**: 폐기를 경고로 기록하고 시작된 프로파일을 정리해야 한다.
- **FR-005**: 비동기 처리와 주기 실행에서도 폐기 의미를 보존하고 다음 정상 입력을 처리해야 한다.

### 주요 개체

- 영상 입력: 픽셀 형식, 높이·너비, 프레임 버퍼와 CUDA 스트림을 가진다.
- 폐기 대상: NV12 크기 계약을 만족하지 못하는 영상 입력이다.

## 성공 기준

- **SC-001**: 정상·비정상·정상 입력에서 정상 두 프레임만 순서대로 출력한다.
- **SC-002**: 비정상 입력만 주어진 경우 예외 없이 출력 0개로 종료한다.
- **SC-003**: 크기 오류 외의 기존 오류 검증과 정상 처리 회귀 검증을 통과한다.

## 가정과 명확화

- 이번 변경은 대화에서 확인한 NV12 크기 검사에 한정한다. 일반적인 오류 복구나 재연결 정책 추가는 제외한다.
- 사용자 선택인 프레임 폐기를 적용하며 크기 자동 보정은 하지 않는다.
- 명확화 검토: 범위, 입력, 실패 처리, 관측성, 검증 기준이 명확하며 추가 질문은 0개다.
- 프로세스와 파이프라인의 전역 복구 설정은 변경하지 않는다.
- 테스트는 폐기 후 재개, 비동기 전달 차단, 원본 불변성과 다른 오류 보존을 검증한다.
