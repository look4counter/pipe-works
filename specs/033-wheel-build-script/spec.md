# 기능 명세: wheel 빌드 스크립트

**작성일**: 2026-10-15
**상태**: 검증 완료
**입력**: 빌드를 직접 실행하는 대신 ps1 파일을 만든다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 명령 하나로 패키지 빌드 (우선순위: P1)

사용자는 저장소의 PowerShell 스크립트를 실행해 현재 소스의 wheel을 생성한다.
**우선순위 이유**: 반복 가능한 빌드 진입점이 필요하다.
**독립 검증**: 스크립트의 구문과 인자를 검사하고 실제 빌드를 실행하지 않는다.

1. 어느 작업 디렉터리에서 호출해도 저장소 루트를 대상으로 빌드한다.
2. 기본 출력은 저장소 dist이며 사용자가 출력 경로를 지정할 수 있다.
3. 오프라인 모드를 선택할 수 있고 빌드 도구 누락이나 빌드 실패를 명확히 전달한다.

### 경계 조건

기존 산출물을 지우거나 버전과 의존성을 변경하지 않는다. 스크립트 작성 과정에서는 빌드를 실행하지 않는다.

## 요구사항

- **FR-001**: 루트 build.ps1에서 프로젝트의 uv build를 사용해 wheel만 생성한다.
- **FR-002**: 스크립트 위치를 기준으로 저장소와 기본 dist 경로를 결정하고 출력 경로와 오프라인 선택 인자를 지원한다.
- **FR-003**: 도구 부재와 빌드 실패를 알리고 호출 전 작업 디렉터리를 복원한다.

- **FR-004**: wheel 빌드 인터프리터를 Python 3.11.9로 명시한다.

- **FR-005**: 생성되는 wheel의 Python 태그는 py311, 플랫폼 태그는 Windows x64인 win_amd64로 지정한다. Python 3.11.9 설치 제한을 유지하고 소스 컴파일 방식은 바꾸지 않는다.

## 성공 기준

- **SC-001**: PowerShell 구문 오류가 0건이다.
- **SC-002**: wheel·출력 경로·오프라인 인자와 실패 코드 처리가 스크립트에 명확히 반영된다.

- **SC-003**: uv 빌드 인자에 --python 3.11.9가 포함되어 프로젝트의 requires-python과 일치한다.

- **SC-004**: 빌드 옵션을 적용한 setuptools 태그 계산 결과가 py311-none-win_amd64이고 기존 출력 경로 및 오프라인 선택을 유지한다.

## 가정과 명확화

프로젝트가 uv를 사용하므로 uv를 빌드 도구로 사용한다. 미설치 시 자동 설치하지 않고 안내한다. 사용자 요청이 명확하여 추가 질문이 필요 없다.

후속 요청으로 빌드 Python을 3.11.9로 고정한다. 추가 명확화가 필요한 모호성은 없다.

Windows 대상은 현재 프로젝트 환경과 NVIDIA 의존성에 맞춰 x64로 해석한다. 앞선 파일명 버전 표기 요청에 맞춰 py311을 함께 지정한다. 추가 질문이 필요한 모호성은 없다.
