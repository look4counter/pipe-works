# 기능 명세: RTSP 패킷 송출

**작성일**: 2026-10-02

**갱신일**: 2026-10-03

**상태**: 구현 및 검증
**입력**: RTSP 송출 단계는 패킷과 비디오 스트림을 가진 입력을 동일한 경로로 송출한다. 통계 집계는 제외한다.

## 사용자 시나리오와 검증

### 시나리오 1: 단일 패킷 계약으로 송출

사용자는 수신한 압축 패킷이나 인코딩 단계가 만든 패킷을 같은 RTSP 송출 단계에 전달한다.

**인수 조건**:

1. `packet`과 `video_stream`을 가진 컨텍스트를 받으면 입력 스트림을 템플릿으로 출력 스트림을 만들고 패킷을 송출한다.
2. 패킷의 출처에 따라 송출 경로가 달라지지 않는다.
3. 두 속성 중 하나라도 없으면 명시적인 입력 오류가 발생한다.
4. 별도 인코딩 바이트와 코덱·크기·프레임 속도 메타데이터만 가진 입력은 거부한다.

### 시나리오 2: 시간 정보와 스트림 변경

패킷의 DTS가 없거나 역행해도 송출 가능한 시간 순서로 보정한다.

**인수 조건**:

1. 입력 패킷의 PTS, 지속 시간, 시간 기준을 이용해 DTS를 보정한다.
2. 입력 스트림의 코덱·크기·추가 데이터·시간 기준이 바뀌면 기존 출력을 닫고 새 스트림을 연다.
3. 패킷에 시간 기준이 없으면 입력 스트림 또는 출력 스트림의 시간 기준을 사용한다. 최종 시간 기준이 없거나 양수가 아니면 오류가 발생한다.

### 시나리오 3: 출력 장애와 정리

출력을 열거나 패킷을 송출하지 못하면 재연결 설정에 따라 다음 입력 패킷에서 다시 시도하거나 오류를 전달한다.

**인수 조건**:

1. 재시도 대기 중 들어온 패킷은 건너뛴다.
2. 재연결이 꺼진 상태의 출력 오류는 호출자에게 전달된다.
3. 입력 종료나 처리 중 예외 발생 시 열린 출력 연결을 닫는다.

## 기능 요구사항

- **FR-001**: `RTSPPublish`는 URL 생성 인자와 단계 설정 계약을 유지해야 한다.
- **FR-002**: 송출 단계는 `packet`과 `video_stream`을 가진 컨텍스트만 받아야 한다.
- **FR-003**: 입력 스트림을 출력 템플릿으로 사용하고 패킷을 재인코딩하지 않고 송출해야 한다.
- **FR-004**: 인코딩 바이트 전용 입력을 직접 패킷으로 만들거나 별도 타임스탬프를 생성하지 않아야 한다.
- **FR-005**: 누락되거나 역행하는 DTS를 입력 패킷의 시간 정보에 맞춰 보정해야 한다.
- **FR-006**: 입력 스트림 설정이 바뀌면 출력을 다시 열고 시간 보정 상태를 초기화해야 한다.
- **FR-007**: 출력 열기와 송출 실패 시 재연결 설정에 따라 자원을 정리하고 재시도하거나 오류를 전달해야 한다.
- **FR-008**: 입력 종료나 처리 중 예외 발생 시 열린 출력 연결을 닫아야 한다.
- **FR-009**: 통계 집계 없이 입력을 소비하고 패킷을 다음 단계로 전달하지 않아야 한다.
- **FR-010**: 출력 단계는 재연결 여부와 간격, 전송 방식, 제한 시간, 패킷 크기를 설정으로 받아야 한다. FPS와 코덱은 설정으로 요구하지 않아야 한다.
- **FR-011**: 출력 연결 옵션의 값은 문자열이어야 하며, `timeout_ms`는 밀리초로 받아 마이크로초 문자열로 변환한다. 기본값은 5000이며 이전 `timeout` 키는 오류로 처리한다.

## 성공 기준

- **SC-001**: 두 입력 출처를 모사한 패킷이 동일한 송출 경로로 처리된다.
- **SC-002**: 패킷 또는 스트림이 없는 입력과 인코딩 바이트 전용 입력이 거부된다.
- **SC-003**: 누락·역행 DTS와 입력 스트림 변경 사례에서 시간 보정과 출력 재생성을 확인한다.
- **SC-004**: 출력 실패 후 대기 구간의 패킷을 건너뛰고 다음 허용 시점에 재시도하며, 종료 시 연결을 정리한다.
- **SC-005**: 패킷 크기 1200과 `timeout_ms: 10000`으로 설정하면 출력 연결에 문자열 `1200`과 마이크로초 단위 문자열 `10000000`이 전달된다.

## 가정과 범위

- 인코딩 단계는 송출 가능한 패킷과 비디오 스트림을 제공한다. 해당 단계의 동작은 [NVIDIA 인코딩 명세](../005-nvidia-encode/spec.md)에서 다룬다.
- 기본 전송 방식은 TCP, 패킷 크기는 1452바이트, `timeout_ms`는 5000밀리초, 출력 재시도 간격은 3초다.
- 통계 집계와 인코딩 단계 구현은 이 기능의 범위 밖이다.
- 인코딩 단계가 원본 비디오 스트림을 템플릿으로 전달하는 경우, 재인코딩된 패킷과 템플릿의 실제 서버 호환성은 별도 종단 간 검증이 필요하다.

## 입력 계약 변경 기록

초기 명세에는 `data`, `codec`, `width`, `height`, `time_base`, `fps`를 받는 인코딩 바이트 전용 경로가 있었다. 현행 계약에서는 해당 경로를 제거하고 모든 입력에 `packet`과 `video_stream`을 요구한다.
