# 기능 명세: 비디오 스트림 수명 분리

**작성일**: 2026-10-16
**상태**: 명세 검증 완료
**요청**: 원본 VideoStream 공유를 필요한 값의 연결당 복사로 대체하고 성능 부담을 최소화한다.

## 사용자 시나리오 및 검증

### 사용자 스토리 1 — 연결 종료 후 안전한 처리 (P1)

운영자는 수신 연결이 끊겨도 이미 전달된 영상의 후속 처리를 안전하게 계속한다.
우선순위 이유: 해제된 스트림 접근에 따른 프로세스 종료 위험을 제거한다.
독립 검증: 연결을 닫은 뒤 이전 컨텍스트의 모든 영상 메타데이터를 읽고 송출 초기화를 수행한다.

1. 연결이 열려 있을 때 메타데이터를 복사하면, 연결 종료 후에도 그 값이 유지된다.
2. 프레임 여러 개를 전달하면 같은 연결의 메타데이터는 하나이며 원본 스트림은 포함하지 않는다.

### 사용자 스토리 2 — 재연결과 재인코딩 송출 유지 (P1)

운영자는 같은 해상도와 코덱으로 재연결해도 새 연결을 감지하고 영상을 다시 송출한다.
우선순위 이유: 기존 자동 복구와 송출을 보존한다.
독립 검증: 동일한 설정의 서로 다른 연결을 전달하고 디코더·인코더 교체 및 출력 재생성을 확인한다.

1. 같은 설정으로 재연결해도 연결 식별자가 달라 복구를 수행한다.
2. 재인코딩 결과는 원본이 아닌 출력 코덱 설정으로 송출한다.

### 경계 조건

- 수신 종료와 후속 처리의 동시 실행, 동일 설정 재연결, 인코더 지연 패킷을 포함한다.
- 없는 부가 메타데이터는 선택 값으로 처리한다. 필수 코덱·크기 누락은 명시적 오류로 처리한다.
- 사용자 정의 단계의 기존 너비·높이 접근 경로를 유지한다.

## 요구사항

### 기능 요구사항

- **FR-001**: 소스는 열린 연결에서 필요한 값만 복사하고 후속 단계에 원본 스트림·코덱 객체를 전달하지 않는다.
- **FR-002**: 연결당 하나의 불변 메타데이터를 생성해 모든 패킷과 프레임에서 공유한다. 영상·GPU 버퍼 복사와 매 프레임 메타데이터 복사는 추가하지 않는다.
- **FR-003**: 같은 설정의 재연결도 식별하고 디코더·인코더·송출의 기존 복구 동작을 유지한다.
- **FR-004**: 송출은 원본 스트림 템플릿 없이 압축 패킷을 처리하고 타임스탬프 보정과 재시도를 유지한다.
- **FR-005**: 재인코딩 출력의 코덱·크기·시간 기준·헤더는 실제 출력에 맞으며 이전 세대의 지연 패킷은 이전 메타데이터를 사용한다.
- **FR-006**: 사용자 정의 단계의 video_stream.codec_context.width·height 접근 경로를 유지하고 변경된 메타데이터 계약을 문서화한다.
- **FR-007**: 연결 종료 후 접근·동일 설정 재연결·메타데이터 재사용·실제 PyAV 패킷 송출에 대한 회귀 검증을 추가한다.

### 주요 엔터티

- 영상 메타데이터: 연결 식별자, 코덱 이름, 크기, 시간 기준, 프레임률 및 코덱 부가 데이터의 독립적인 값.
- 출력 세대: 입력 연결과 인코더 생성에 대응하며 출력 헤더와 지연 패킷의 소속을 구별한다.

## 성공 기준

- **SC-001**: 연결 종료 후 메타데이터 접근 및 송출 회귀 검증에서 원본 스트림 접근 횟수가 0이다.
- **SC-002**: 한 연결에서 1,000개 패킷을 전달해도 메타데이터 생성은 1회다.
- **SC-003**: 동일 설정 재연결과 지연 패킷을 포함한 관련 자동 검증이 모두 통과한다.

## 가정 및 범위

- 현재 사용처의 호환성을 위해 video_stream 필드 이름은 유지하고 값의 종류를 불변 메타데이터로 바꾼다.
- 실제 GPU·RTSP 서버 검증은 해당 장비가 있는 환경에서 실행하며 로컬 PyAV 파일 기반 송출로 기본 호환성을 검증한다.
- 원래 장애의 모든 가능한 원인 제거가 아니라 확인된 스트림 수명 결합을 제거하는 범위다.
