# 기능 명세: 1.0.0 릴리즈 기준 고정

**기능 브랜치**: `048-release-1-0-0`

**작성일**: 2026-10-27

**상태**: 초안

**입력**: 현재 소스를 1.0.0 최초 릴리즈 기준으로 고정하고, 재현 가능한 의존성·독점 배포 문서를 준비한다.

## 사용자 시나리오 및 테스트

### 사용자 스토리 1 - 릴리즈 버전과 실행 환경 고정 (우선순위: P1)

릴리즈 담당자는 패키지 메타데이터와 잠금 파일을 확인해 1.0.0 릴리즈가 어떤 버전과 Python 실행 환경을 대상으로 하는지 알 수 있다.

**인수 조건**:

1. `pyproject.toml`의 프로젝트 버전이 `1.0.0`이다.
2. 잠금 파일의 프로젝트 버전과 패키지 버전이 릴리즈 메타데이터와 일치한다.
3. Python 3.11.9와 Windows x64 대상 조건이 문서와 핀 파일에 명시된다.

### 사용자 스토리 2 - 고정 의존성으로 설치하기 (우선순위: P1)

배포 담당자는 네트워크나 패키지 해석 결과에 의존하지 않고 릴리즈에 사용된 고정 의존성 목록을 확인할 수 있다.

**인수 조건**:

1. 모든 직접 의존성의 버전이 핀 파일에 고정되어 있다.
2. CUDA 12.1 PyTorch 공급 경로와 Windows x64 대상 조건이 핀 파일에 명시된다.
3. 핀 파일의 생성 기준이 잠금 파일과 일치한다.

### 사용자 스토리 3 - 독점 배포 조건 확인하기 (우선순위: P1)

사용자는 회사명을 공개하지 않고도 이 소프트웨어가 사내·비공개 배포용이라는 점과 공동 기여자 표기를 확인할 수 있다.

**인수 조건**:

1. LICENSE에 사내·비공개 사용, 복제·재배포 제한, 보증 부인 조건이 명시된다.
2. LICENSE의 공동 기여자 표기는 `look4counter`와 `lhoris`이다.
3. 서드파티 의존성 고지 문서에는 직접 의존성과 주요 전이 의존성의 버전·라이선스 확인 출처가 기록된다.

### 사용자 스토리 4 - 릴리즈 내용을 검토하기 (우선순위: P2)

릴리즈 담당자는 1.0.0의 범위, 주요 기능, 지원 환경, 알려진 제한을 릴리즈 노트에서 확인할 수 있다.

**인수 조건**:

1. RELEASE_NOTES.md에 1.0.0 릴리즈 날짜, 포함 기능, 지원 환경, 설치 기준, 알려진 제한이 있다.
2. 릴리즈 노트는 현재 소스 확정본을 기준으로 작성되며 구현되지 않은 계획을 완료된 기능처럼 표현하지 않는다.

## 경계 조건

- 현재 저장소에 회사명이나 기존 오픈소스 라이선스가 없으므로 회사명 없는 독점 고지문을 사용한다.
- uv 실행 파일이 없는 환경에서는 잠금 파일을 임의로 재해석하지 않고, 핀 파일 생성이 불가능한 원인을 기록한다.
- 서드파티 라이선스를 자동으로 확정할 수 없는 패키지는 공식 메타데이터 확인 필요 항목으로 명시한다.
- 이 기능에서는 wheel, wheelhouse, 실행 번들 zip, 체크섬 생성은 범위에 포함하지 않는다.

## 기능 요구사항

- **FR-001**: 프로젝트 버전을 1.0.0으로 고정해야 한다.
- **FR-002**: 잠금 파일을 갱신해 프로젝트 버전과 릴리즈 버전을 일치시켜야 한다.
- **FR-003**: Python 3.11.9·Windows x64·CUDA 12.1 기준의 고정 의존성 파일을 제공해야 한다.
- **FR-004**: 핀 파일은 직접 의존성의 버전과 PyTorch 전용 공급 경로를 보존해야 한다.
- **FR-005**: 사내·비공개 배포용 LICENSE를 회사명 없이 제공해야 한다.
- **FR-006**: LICENSE에 look4counter와 lhoris를 공동 기여자로 기록해야 한다.
- **FR-007**: 직접·주요 전이 의존성의 라이선스와 확인 출처를 THIRD_PARTY_NOTICES.md에 기록해야 한다.
- **FR-008**: RELEASE_NOTES.md에 1.0.0 릴리즈 정보와 현재 소스 기준의 제한사항을 기록해야 한다.
- **FR-009**: 문서와 핀 파일은 한국어 설명을 사용하고, 명령·패키지명·라이선스명은 원문 표기를 유지해야 한다.

## 성공 기준

- **SC-001**: 버전·핀·라이선스·고지·릴리즈 노트 파일 검사가 모두 통과한다.
- **SC-002**: 새 환경에서 핀 파일을 사용한 설치 시도에 필요한 Python·플랫폼·공급 경로 정보가 누락되지 않는다.
- **SC-003**: 배포 담당자가 회사명을 확인하지 않고도 독점 배포 조건과 공동 기여자 2명을 확인할 수 있다.

## 가정

- 최초 공개 릴리즈 버전은 1.0.0이며 현재 main의 소스를 기준으로 한다.
- 회사명은 LICENSE와 릴리즈 문서에 기록하지 않는다.
- 공동 기여자 표기는 사용자가 제공한 `look4counter`, `lhoris`를 그대로 사용한다.
- LICENSE는 법률 자문을 대체하지 않는 내부 배포 고지문으로 작성한다.
