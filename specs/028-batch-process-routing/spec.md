# 기능 명세: Batch 여부에 따른 실행 프로세스 선택

**작성일**: 2026-10-14
**상태**: 검토 완료
**사용자 요청**: Batch가 아닌 YoloInference는 중앙 프로세스를 사용하지 않고, 실행 코드를 중복하지 않는다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 - 일반 실행 (우선순위: P1)
사용자는 Batch 추론이 없는 파이프라인을 호출한 프로세스에서 실행한다.
**독립 검증**: 실행 PID가 호출자 PID와 같고 중앙 프로세스 연결이 발생하지 않는다.
**인수 시나리오**:
1. 일반 추론 또는 추론 없는 파이프라인을 실행하면 호출자에서 실행한다.
2. 직렬화할 수 없는 사용자 상태도 일반 실행에서 사용할 수 있다.

### 사용자 이야기 2 - 공유 Batch 실행 (우선순위: P1)
사용자는 Batch 추론이 하나라도 있는 파이프라인을 기존 중앙 프로세스에서 실행한다.
**독립 검증**: 직접 또는 래퍼 안에 있는 Batch 추론이 중앙 실행을 선택한다.
**인수 시나리오**:
1. 일반 추론과 Batch 추론이 섞여 있으면 파이프라인 전체를 중앙에서 실행한다.
2. 개발 및 운영 그룹은 중앙 실행에서 기존처럼 분리한다.

### 경계 조건
빈 파이프라인과 추론 없는 파이프라인은 일반 실행이다. 여러 겹의 래퍼, 반복 참조를 안전하게 검사한다. 실행 오류는 선택한 기존 실행 경로의 방식으로 전달한다.

## 요구사항

### 기능 요구사항
- **FR-001**: Batch 추론이 없으면 호출자 프로세스에서 실행해야 한다.
- **FR-002**: Batch 추론이 하나라도 있으면 기존 중앙 실행을 선택해야 한다.
- **FR-003**: Hotswap, CudaAsync, EveryNFrames, TapSkipIfBusy 안의 추론도 판별해야 한다.
- **FR-004**: 두 실행 경로는 기존 단계 실행·설정 감시·추론 처리를 재사용해야 한다.
- **FR-005**: 중앙 실행의 개발/운영 분리, 출력 전달과 종료 처리를 유지해야 한다.

### 주요 개체
파이프라인은 단계의 실행 순서를 소유한다. 추론 단계의 Batch 여부는 공유 실행 필요성을 결정한다. 래퍼는 자식 단계들을 포함한다.

## 성공 기준
- **SC-001**: 일반 실행 검증에서 추가 중앙 프로세스 연결은 0회이고 실행 PID는 호출자와 같다.
- **SC-002**: 직접·중첩·혼합 Batch 검증 사례가 모두 중앙 실행을 선택한다.
- **SC-003**: 기존 설정 감시와 중앙 실행 회귀 검증이 통과한다.

## 가정 및 명확화
기존 batch 생성자 설정을 실행 위치의 기준으로 사용한다. 실행 중 프로세스 이동은 지원하지 않는다. 추론 없는 파이프라인도 일반 실행한다. 사용자 요청과 기존 구조로 중요한 모호성을 해소했으므로 추가 질문은 없다. 사용자 수정 중인 단일 스트림 예제는 수정하지 않는다.
