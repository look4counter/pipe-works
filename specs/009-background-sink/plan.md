# 구현 계획: 단일 작업자 Sink

**명세**: [spec.md](spec.md)

## 요약

`Sink` 안에 단일 백그라운드 작업자와 용량 1의 입력 슬롯을 둔다. 주 스트림은 입력을 즉시 반환한다. 감싼 Step은 지속적인 입력 반복자를 한 번 받고 출력은 작업자가 소비한다.

## 기술 배경

- 언어: Python 3.12
- 의존성: 표준 라이브러리 `threading`, `logging`
- 대상: 기존 `Pipeline`과 `Hotswap`의 Step 연결
- 검증: 이벤트로 제어하는 짧은 동시성 확인과 전체 단위 테스트

## 구성 원칙 확인

프로젝트 헌법은 미작성 템플릿이다. 추가 제한은 없다. 설계 후에도 동일하다.

## 설계

1. 생성자에서 감쌀 Step을 `step` 속성에 보관한다. 이 속성은 `Hotswap`이 구간 재시작 때 생성자를 재구성하는 데도 사용한다.
2. `configure`는 감싼 Step에 설정을 전달한다.
3. `process`가 소비될 때 조건 변수와 입력 슬롯 및 데몬 작업자를 만든다.
4. 주 스레드는 작업자가 비었을 때만 슬롯에 컨텍스트를 넣고 모든 컨텍스트를 즉시 반환한다.
5. 작업자는 감싼 Step의 `process`에 지속적인 입력 반복자를 한 번 전달하고 모든 출력을 소비한다. 반복자가 다음 입력을 요청할 때 작업 중 상태를 해제한다.
6. 작업자 예외는 로그에 남긴다. 입력 종료나 generator 닫기 시 새 작업 수락을 중지한다. 정상 종료에서는 수락한 마지막 작업이 끝날 때까지 기다린다.
7. 생성자에서 사용자 정의 내부 Step을 `Hotswap`으로 감싼다. 내장 Step과 이미 `Hotswap`인 Step은 그대로 사용한다. 작업자의 지속적인 반복자 경로를 통해 기존 코드 교체와 상류 구간 처리 로직을 재사용한다.

## 영향 파일

- 소스: `src/pipeworks/embedded/sink.py`만 수정한다.
- 문서: `specs/009-background-sink/` 산출물을 작성한다.

## 검증

- 5초 지연에 대응하는 이벤트 기반 확인으로 주 스트림 전달, 실행 중 건너뛰기, 완료 후 재수락을 검증한다.
- 동일 Step의 지속적 반복자 사용과 예외 후 주 스트림 유지를 확인한다.
- 내부 Step의 파일 변경을 작업 중 수행하고 다음 수락된 입력에서 새 구현 적용을 확인한다.
