# 기능 명세: 모델 배치 설정 단순화

작성일: 2026-10-17
상태: 검증 완료

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 모델 설정 단순화 (우선순위: P1)
개발자는 모델 YAML에 max_batch_size와 max_batch_wait_ms로 배치 수집을 설정한다. YAML을 통해 외부 플러그인을 로드하지 않는다.
인수 조건: 새 키가 모든 백엔드에서 밀리초로 해석되고 외부 라이브러리 로드 계약이 제거된다.

## 요구사항

- FR-001: 모델 YAML의 배치 대기 키를 max_batch_wait_ms로 변경한다. 기존 timeout 및 timeout_ms 키는 새 이름을 안내하는 오류로 처리한다.
- FR-002: 모델 plugins 해석·검증·경로 변환·인자 전달·외부 라이브러리 로드 및 핸들 보관 코드를 제거한다.
- FR-003: TensorRT 자체 표준 플러그인 초기화와 엔진·프로파일 실행은 유지한다.
- FR-004: 무설정 배치 크기 1·대기 0, 밀리초 단위와 기존 수치 검증은 유지한다. RTSP와 CudaAsync의 timeout_ms는 변경하지 않는다.
- FR-005: 예제 모델 YAML, 관련 테스트 및 사용자 문서를 갱신한다.

## 성공 기준

- SC-001: 새 키 적용·이전 키 거부·유효 범위 검증이 통과한다.
- SC-002: 사용자 외부 플러그인 로드 경로가 소스에서 제거된다.
- SC-003: TensorRT·공유 배치·중앙 프로세스 회귀 검사가 통과한다.

## 경계 조건과 가정

config_path 선택 규칙과 캐시 격리는 유지한다. 알 수 없는 YAML 키를 전반적으로 거부하는 기능은 추가하지 않는다. 제거된 plugins는 해석하거나 로드하지 않는다. TensorRT 표준 플러그인은 라이브러리 실행의 일부이므로 유지한다.

## 명확화 검토

기능, 데이터, 오류, 의존성, 범위 및 완료 조건을 검토했다. 중대한 불명확성은 없으며 질문은 0건이다. 헌법은 미작성 템플릿이다.

## 명칭 확정

사용자가 max_batch_wait_ms 명칭을 선택했다. 첫 요청의 도착 시점부터 추가 요청을 모으는 최대 대기 시간을 뜻하며 배치가 가득 차면 즉시 실행한다. 큐 적체와 GPU 실행을 포함한 전체 지연 상한은 아니다. 이전 batch_timeout_ms도 새 이름을 안내하는 오류로 처리한다. 추가 질문은 없다.
