# 기능 명세: 인코더 자동 복구

**작성일**: 2026-10-15
**상태**: 명세 검증 완료
**입력**: 인코더도 사용자 개입 없이 복구가 가능하게 만든다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 오류 후 영상 자동 재개 (우선순위: P1)

운영자는 인코더의 일시적인 오류 때문에 파이프라인을 다시 실행하지 않아도 된다.
**우선순위 이유**: 영상 처리의 지속성이 핵심 요청이다.
**독립 검증**: 정상 프레임, 인코딩 오류, 후속 정상 프레임을 전달하여 새 영상 출력과 시간 순서를 확인한다.

1. 인코딩 중 복구 가능한 오류가 발생하면 오류 프레임을 버리고 자동 복구를 시도한다.
2. 인코더 생성이 반복 실패해도 입력을 계속 소비하고 1초 간격을 두어 새 입력에서 재시도한다.
3. 정상 입력으로 돌아오면 사용자 개입 없이 재생 가능한 영상 출력을 재개하며 출력 타임스탬프가 역행하지 않는다.
4. 입력 종료 처리 중 복구 가능한 오류가 발생하면 잔여 출력을 버리고 정상 종료한다.

### 사용자 이야기 2 — 입력 변경과 종료 처리 (우선순위: P2)

재연결이나 영상 형식 변경 이후 새 입력에 맞는 인코딩을 진행하고 중지 요청에 응답한다.
**우선순위 이유**: 디코더 자동 복구와 함께 연결해 사용하려면 필요하다.
**독립 검증**: 입력 스트림·해상도·픽셀 형식·처리 스트림 변경과 재시도 대기 중 중지를 검증한다.

1. 입력 스트림이나 인코딩에 필요한 형식이 바뀌면 최신 입력에 맞게 인코더를 다시 생성한다.
2. 복구 대기 중에도 입력을 소비하며 중지 요청이 있으면 새 인코더 생성 없이 종료한다.
3. 설정 오류나 소스 및 후속 처리의 오류는 자동 복구로 숨기지 않는다.

### 경계 조건

- 복구 중 프레임 손실과 잠깐의 영상 정지는 허용한다. 실패한 프레임은 다시 처리하지 않는다.
- 출력이 없는 정상 인코딩 결과는 복구 성공으로 기록하지 않는다.
- 오류 인코더에 남은 지연 출력은 재사용하지 않는다. 정상 인코더 교체에서는 가능한 잔여 출력을 교체 전 메타데이터로 전달한다.
- 운영체제 수준의 네이티브 프로세스 충돌과 복구 불가능한 GPU 장애는 보장 범위 밖이다.

## 요구사항

### 기능 요구사항

- **FR-001**: 복구 가능한 인코더 생성·프레임 처리 오류가 전체 파이프라인을 종료하지 않도록 자동 복구한다.
- **FR-002**: 실패한 인코더와 프레임은 버리고 재생성을 실패 후 최소 1초 간격으로 무제한 재시도한다. 대기 중 입력은 저장하지 않는다.
- **FR-003**: 복구 후 영상이 독립적으로 재생 가능한 시작 프레임과 필요한 헤더를 포함하고 출력 PTS/DTS가 초기화되거나 역행하지 않도록 한다.
- **FR-004**: 입력 스트림·해상도·코덱·픽셀 형식·처리 스트림 변경을 감지하여 최신 정보로 인코딩한다.
- **FR-005**: 종료 요청에 응답하고 입력 종료 시 복구 가능한 잔여 출력 오류는 버린다. 사용 중인 프레임 자원을 조기 해제하지 않는다.
- **FR-006**: 복구 원인과 실제 출력 재개를 기록하며 설정·지원 불가·입력 소스·후속 처리 오류의 기존 전달 정책을 유지한다.
- **FR-007**: 인코더·연계 디코더의 복구, 입력 교체 및 종료에서 사용 중인 작업 완료를 기다린 뒤 코덱과 실행 자원을 순서대로 해제한다. 디코더 출력 풀이 생기기 전의 오류도 포함한다.
- **FR-008**: 복구 예외가 이전 세대 자원을 불필요하게 보유하지 않게 하며 외부에 전달한 프레임은 마지막 참조와 처리 완료까지 유효하게 유지한다.

### 주요 개체

- 인코딩 세대: 입력 스트림과 해당 코덱·영상 형식·처리 스트림의 인코더.
- 복구 상태: 정상, 재시도 대기, 재생성, 출력 재개.
- 출력 시간: 성공적으로 게시한 패킷마다 증가하며 세대 교체와 무관하게 유지하는 시간 정보.

## 성공 기준

- **SC-001**: 단일 오류와 반복 생성 실패 시험에서 1초 대기 경계 이후 후속 입력으로 자동 재개한다.
- **SC-002**: 복구 후 첫 영상 구간을 이전 구간 없이 디코딩할 수 있고 전체 출력 PTS/DTS 역행이 0건이다.
- **SC-003**: 입력 변경 시 최신 영상 정보가 출력에 반영되며 복구 대기 중 중지 시험은 2초 안에 종료한다. 입력 수신 대기는 기존 수신 제한 시간을 따른다.
- **SC-004**: 정상 패킷 변환·종료·통계·송출 및 디코더 연계 회귀 시험을 통과한다.
- **SC-005**: 오류·입력 변경·중도 종료 시험에서 작업 완료 전 자원 해제와 실행 자원보다 늦은 코덱 해제가 0건이며 이전 프레임의 유효성을 유지한다. 자동 회귀 시험에 해제 순서 검증을 포함한다.

## 가정과 명확화

- 2026-10-15 명확화: 앞선 디코더 요청과 동일한 자동 복구 우선 정책이며 추가 질문이 필요한 중대한 모호성은 없다.
- 기존 공개 생성자와 설정 키를 유지한다. 1초 재시도 간격은 반복 오류의 자원 소모와 로그 폭주를 줄이기 위한 기본 정책이다.
- 기존 정수 FPS 시간 기준과 패킷 단위 시간 증가 계약을 유지한다. 실패 프레임의 실제 경과 시간을 타임스탬프에 추가하는 기능은 범위 밖이다.
- 자동 회귀 테스트와 실제 GPU 생성·재생성 시험으로 검증한다.
- 2026-10-16 명확화: 사용자 지적에 따라 FR-005의 수명 보장을 복구와 교체의 모든 정리 경로로 구체화한다. 프로세스 재시작 구조 추가는 범위 밖이며 실제 보고된 충돌의 원인 확정과는 구분한다. 추가 사용자 결정이 필요한 모호성은 없다.
