# 기능 명세: 중앙 프로세스 그룹 분리

**작성일**: 2026-10-11
**상태**: 명세 확정
**요청**: 운영용 중앙 프로세스를 유지하면서 개발용 중앙 프로세스를 별도로 선택하는 옵션을 제공한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 운영과 개발 분리 (우선순위: P1)

운영자는 Pipeline 생성자의 development 불리언 옵션으로 개발 영상이 운영 영상과 다른 중앙 실행 공간을 사용하게 한다.
독립 검증: 운영과 개발 영상을 동시에 실행하여 서로 다른 실행 식별자를 확인한다.

1. development 생략과 development=False는 같은 운영 중앙 실행 공간을 사용한다.
2. 개발 그룹의 두 영상은 같은 공간을 사용하고 운영 그룹과는 분리된다.
3. 개발 실행 공간을 강제 종료해도 운영 영상은 계속 처리되고 운영 연결은 유지된다.

### 사용자 이야기 2 — 그룹별 수명 관리 (우선순위: P2)

사용자는 그룹마다 자동 시작과 마지막 영상 종료 후 자동 종료를 독립적으로 사용한다.
독립 검증: 개발 그룹의 마지막 영상을 종료해도 실행 중인 운영 영상은 영향을 받지 않는다.

1. 동일 그룹을 동시에 요청해도 중앙 실행 공간은 하나만 시작된다.
2. 개발 그룹 종료 후 다시 실행하면 개발 공간만 새로 시작된다.

### 경계 조건

- development는 bool만 허용한다. 정수·문자열·None은 생성 시 거부한다.
- run은 중앙 그룹 선택 인자를 받지 않는다. 선택 상태는 직렬화 후에도 유지된다.
- 운영과 개발은 동일 GPU를 사용할 수 있으나 장치 전체 장애와 자원 경쟁은 공유한다.

## 요구사항

### 기능 요구사항

- **FR-001**: Pipeline 생성자의 development 불리언 옵션으로 중앙 프로세스를 선택해야 한다. 기본값 False는 운영, True는 개발이다. run은 선택 인자를 받지 않는다.
- **FR-002**: 같은 설치·사용자·그룹의 영상은 하나의 중앙 프로세스를 공유하며 서로 다른 그룹은 다른 프로세스를 사용한다.
- **FR-003**: 그룹마다 연결 대상과 시작 잠금을 분리하여 동시 시작에서 서로 간섭하지 않아야 한다.
- **FR-004**: 자동 시작, 연결 유지, 출력 전달, 오류 전달, 유휴 종료는 선택한 그룹 안에서 동작해야 한다.
- **FR-005**: development는 bool만 허용하며 잘못된 자료형은 Pipeline 생성 시 TypeError로 거부한다. 선택 상태는 Pipeline 직렬화 시 보존한다.
- **FR-006**: 운영·개발 사용 예와 GPU 자원 공유 한계를 문서화한다.

### 핵심 개체

- 중앙 프로세스 그룹: 영상과 모델 작업자를 공유하는 독립 실행 공간의 이름.
- 파이프라인 실행 모드: 생성 시 저장된 development 값으로 운영·개발 실행 대상을 정한다.

## 성공 기준

- **SC-001**: 동시 운영·개발 실행에서 같은 그룹의 영상은 같은 실행 식별자를, 다른 그룹은 다른 식별자를 가진다.
- **SC-002**: 개발 공간의 강제 종료와 유휴 종료 이후에도 운영 영상 처리가 계속된다.
- **SC-003**: 기존 옵션 없는 실행과 출력·오류 전달 검증이 통과한다.

## 가정

- 공개 API는 운영·개발 두 모드만 제공한다. 내부 그룹 주소·잠금 및 서버 수명 구현은 유지한다.
- 모드는 생성자에서 선택하며 영상 설정 파일의 실시간 변경 대상이 아니다.
- 별도 GPU 할당과 하드웨어 장애 격리, 지속 상주 서비스는 범위 밖이다.
- 프로세스 분리와 기존 계약을 실제 Windows 연결로 검증한다.
