# 기능 명세: 분기 컨텍스트와 핫스왑 상태 분리

**작성일**: 2026-10-16
**상태**: 명세 검증 완료
**요청**: 한 파이프라인의 두 분기에서 한쪽 핫스왑이 다른 쪽 상태까지 초기화하는 문제를 해결한다.

## 사용자 시나리오 및 검증

### 사용자 스토리 1 — 분기별 핫스왑 독립성 (P1)

운영자는 배경 처리 코드만 변경했을 때 주 처리의 누적 상태가 유지되기를 원한다.
우선순위 이유: 관련 없는 경로의 처리 상태 손실을 방지한다.
독립 검증: 주 경로 누적 중 배경 코드만 교체해 결과가 1, 3으로 유지되고 1, 2로 초기화되지 않는지 확인한다.

1. 배경 분기의 코드 변경은 주 경로의 핫스왑 상태를 바꾸지 않는다.
2. 분기 후 주 경로의 컨텍스트 속성 변경도 이미 수락한 배경 입력에 반영되지 않는다.
3. 두 분기에 공통인 상류 변경 정보는 각 분기에 전달한다.

### 사용자 스토리 2 — 버퍼 공유와 기존 처리 유지 (P2)

운영자는 분리 때문에 매 프레임 영상 복사나 지연이 추가되지 않기를 원한다.
우선순위 이유: 기존 무복사 처리와 배경 작업 생략 정책을 유지한다.
독립 검증: 주 출력의 객체 동일성과 영상·GPU 스트림·디코더 소유자 참조 동일성을 확인한다.

1. 주 출력은 기존 원본 컨텍스트다. 배경 입력은 별도의 컨텍스트다.
2. 영상 버퍼·패킷·GPU 스트림·불변 메타데이터·디코더 버퍼 소유자는 참조를 공유한다.
3. 배경 작업자가 바쁘면 새 작업은 생략하며 대기열을 늘리지 않는다.

### 경계 조건

- 배경 경로의 속성 추가·삭제·재할당과 오류 복구는 주 경로 속성을 변경하지 않는다.
- 중첩 사전과 텐서 데이터 자체는 여전히 공유하므로 배경 경로가 읽기 전용으로 사용한다.
- 두 경로가 같은 소스 파일을 명시적으로 감시하는 경우 파일 변경을 각각 적용하는 기존 동작은 유지한다.
- 정상 입력 종료 대기와 조기 종료 동작은 유지한다.

## 요구사항

### 기능 요구사항

- **FR-001**: 배경 작업으로 수락한 입력은 주 경로와 별개의 컨텍스트 속성 사전을 갖는다.
- **FR-002**: 배경 핫스왑 변경 정보가 주 경로로 유출되지 않으며 분기 후 주 경로의 정보 변경도 배경 입력에 영향을 주지 않는다.
- **FR-003**: 분기 시점의 공통 상류 변경 정보와 기존 입력 필드는 배경 입력에 보존한다.
- **FR-004**: 영상·GPU 버퍼·패킷·스트림·메타데이터·디코더 소유자는 복사하지 않고 참조를 공유하며 주 출력은 원본 컨텍스트를 유지한다.
- **FR-005**: 사용 중 입력 생략·정상 종료 대기·오류 및 조기 종료의 기존 계약을 보존하고 수락하지 않은 입력의 분리 작업을 생략한다.
- **FR-006**: 실제 코드 교체와 속성 격리·참조 공유를 회귀 검증하고 분리 범위와 읽기 전용 사용 계약을 문서화한다.

### 주요 엔터티

- 주 컨텍스트: 기존 입력 객체이며 주 경로를 따라 전달한다.
- 배경 컨텍스트: 수락 시점의 속성을 가진 별도 객체다. 내부 영상 데이터와 자원 참조는 주 컨텍스트와 공유한다.
- 핫스왑 변경 정보: 컨텍스트별 독립 속성으로 관리하되 분기 이전 공통 정보는 보존한다.

## 성공 기준

- **SC-001**: 배경 코드 교체 시 주 경로 누적 결과가 1, 3으로 유지된다.
- **SC-002**: 주·배경 컨텍스트가 다른 객체이고 공유 자원은 모두 같은 객체임을 확인한다.
- **SC-003**: 분기 전 정보 전달·분기 후 속성 변경 격리·사용 중 생략 및 관련 회귀 검증이 모두 통과한다.

## 가정 및 명확화

2026-10-16: 사용자는 한 파이프라인의 분기라고 명확히 답변했고 컨텍스트만 분리하고 영상·GPU 버퍼는 공유하는 방향을 승인했다. 추가 질문과 미해결 모호성은 없다. 범위는 TapSkipIfBusy 분기 경계이며 임의 사용자 정의 분기나 같은 파일의 감시 자체를 비활성화하지 않는다.
