# 연구 결과

## 결정: 수락 시점의 최상위 컨텍스트 분리

원인: TapSkipIfBusy가 동일 입력 객체를 배경 슬롯과 주 경로에 전달하며 Hotswap.process가 _pipeworks_hotswap_epoch를 그 객체에 기록한다. 배경 코드만 바꿔도 주 경로 Hotswap이 상류 변경으로 판단해 상태를 초기화함을 재현했다.

기존 CudaAsync도 PipelineContext(**fields)로 속성 사전을 분리하고 버퍼는 공유한다. Tap의 수락 경계에 같은 값 참조 방식의 분리를 적용한다. closed·busy 검사 후 생성하므로 생략한 입력에는 추가 객체가 없다. 기존 디코더 소유자는 참조를 공유해 GPU 수명을 유지한다.

대안: deepcopy와 영상 clone은 성능·수명 계약을 해치므로 제외한다. epoch만 지우면 공통 상류 변경이 유실되고 공유 속성 복원 경쟁은 남는다. 배경 실행 후 원래 epoch 복원은 동시 실행 도중의 유출을 막지 못한다. 전역 핫스왑 정책 변경은 필요하지 않다.

기존 표준 자료구조와 확인된 로컬 코드만 사용하므로 기술적 미해결 사항이나 추가 연구 위임은 없다.
