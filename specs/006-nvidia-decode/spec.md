# 기능 명세: NVIDIA 비디오 디코딩

**작성일**: 2026-10-03

**상태**: 현행 구현 명세

**입력**: `NvidiaDecode`가 수신 패킷을 디코딩하고 다음 단계에 프레임 컨텍스트를 전달한다.

## 사용자 시나리오와 검증

### 시나리오 1: 수신 패킷 디코딩

사용자는 RTSP 소스의 압축 패킷을 GPU에서 디코딩해 후속 인코딩 단계에 프레임을 전달한다.

**인수 조건**:

1. 첫 패킷의 비디오 스트림 코덱과 설정된 GPU 번호로 디코더와 CUDA 스트림을 만든다.
2. 패킷 바이트와 가능한 경우 PTS를 디코더 입력에 넣는다.
3. 디코더가 반환한 프레임마다 별도 `PipelineContext`를 만든다.
4. 출력 컨텍스트에는 프레임, 비디오 스트림, CUDA 스트림, 픽셀 형식이 들어 있다.

### 시나리오 2: 패킷과 프레임의 개수 차이

압축 패킷과 디코딩 프레임의 개수가 같지 않아도 실제로 반환된 프레임 수에 맞춰 전달한다.

**인수 조건**:

1. 디코더가 빈 목록을 반환하면 출력 컨텍스트가 없다.
2. 한 패킷에서 프레임 여러 개가 반환되면 프레임마다 컨텍스트 하나가 나온다.
3. 출력 컨텍스트는 원본 패킷 컨텍스트와 다른 새 객체다.

## 기능 요구사항

- **FR-001**: `NvidiaDecode`는 단계 설정에서 GPU 번호를 읽어야 한다. 설정이 없으면 기본 GPU 번호를 사용한다.
- **FR-002**: 첫 입력의 비디오 스트림 코덱을 NVIDIA 디코더가 받는 코덱 값으로 바꾸고 CUDA 스트림을 생성해야 한다.
- **FR-003**: 패킷의 압축 바이트와 존재하는 PTS를 디코더 입력에 전달해야 한다.
- **FR-004**: 지정한 CUDA 스트림에서 디코딩하고 반환된 각 프레임을 각각의 컨텍스트로 전달해야 한다.
- **FR-005**: 각 출력 컨텍스트에는 `frame`, `video_stream`, `cuda_stream`, `pixel_format` 속성이 있어야 한다.
- **FR-006**: 디코딩 결과가 비어 있으면 출력하지 않아야 한다.
- **FR-007**: 입력 반복자가 끝나면 디코더의 지연 프레임을 회수하고 기존 프레임 컨텍스트 계약으로 전달해야 한다.

## 성공 기준

- **SC-001**: 지원 코덱의 첫 패킷으로 디코더가 한 번 생성되고 설정 GPU 번호가 적용된다.
- **SC-002**: 패킷 PTS가 있으면 디코더 입력에 전달된다.
- **SC-003**: 모의 디코더가 프레임 0개, 1개, 여러 개를 반환할 때 출력 컨텍스트 수가 각각 일치한다.
- **SC-004**: 출력 컨텍스트마다 프레임과 비디오 스트림, CUDA 스트림, 픽셀 형식을 읽을 수 있다.
- **SC-005**: 모의 디코더가 일반 디코딩 결과를 보류하고 종료 시 프레임 하나를 반환하면 그 프레임이 후속 단계에 전달된다.

## 가정과 범위

- 입력 컨텍스트에는 `packet`과 `video_stream`이 있다. 이 입력은 [RTSP 패킷 수신 명세](../002-rtsp-packet-source/spec.md)에서 다룬다.
- 한 입력 구간에서 첫 패킷으로 만든 디코더를 계속 사용한다. [핫스왑](../007-step-hotswap/spec.md)이 상류 변경으로 입력 구간을 끝내면 지연 프레임을 회수한 뒤 다음 구간에서 새 디코더를 만든다.
- RTSP 네트워크 재연결만 일어나고 소스 구현이 변경되지 않으면 입력 구간 경계가 생기지 않는다. 이 경우 디코더 상태를 새로 만드는 동작은 아직 구현되지 않았다.
- 출력의 후속 사용은 [NVIDIA 인코딩 명세](../005-nvidia-encode/spec.md)에서 다룬다.
- 실제 GPU 디코딩 검증에는 NVIDIA 장비와 해당 라이브러리가 필요하다.

## 현행 검증 상태

- 저장소에 디코더 반환 프레임 개수와 출력 속성을 직접 검증하는 모의 테스트가 없어 SC-001~SC-004는 확인되지 않았다.
- 종료 시 지연 프레임 전달은 모의 디코더 테스트로 확인했다. (SC-005)
- 입력 컨텍스트가 그대로 반환된다고 가정한 과거 테스트는 제거했다. 프레임마다 새 컨텍스트가 생성되는 동작의 직접 검증은 T006에 남아 있다.
