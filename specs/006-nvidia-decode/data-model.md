# 자료 모델: 최신 프레임 디코딩

압축 입력은 PyAV 패킷이 소유하는 버퍼 주소·바이트 크기·PTS로 구성한다. PacketData는 주소를 빌리며 패킷 강한 참조는 디코더 호출 반환까지 유지한다. 별도 압축 데이터 저장소를 만들지 않는다.

입력은 packet, video_stream을 가진 기존 컨텍스트다. 생산자 상태는 디코더와 디코딩 스트림, 취소 Event 및 실행 맥락이다.

슬롯은 잠금·Condition, 최대 30개 대기 컨텍스트 deque, 종료 여부, 오류 및 누적 폐기 건수를 가진다. 가득 찬 큐에 새 게시를 할 때 가장 오래된 대기 컨텍스트를 제거한다. 처리 중 컨텍스트는 슬롯이 소유하지 않는다.

출력은 잠금 디코더 버퍼를 공유하는 GPU tensor인 frame, video_stream, 별도 소비 cuda_stream, pixel_format, decoded_at, processing_started_at, decode_dropped_frames를 가진다. decoded_at은 디코딩 출력을 게시한 시각이며 GPU 준비 완료 시각은 아니다. processing_started_at은 소비 전달 시각이다. 폐기 건수는 해당 실행에서 전달하지 않은 디코딩 프레임의 누적 수다.

버퍼 뷰는 잠금 주소, 픽셀 레이아웃, 디코더 반환 관리자, 준비 이벤트와 소비 완료 이벤트를 가진다. 출력 컨텍스트와 텐서 저장소가 뷰를 공유한다. 마지막 참조 해제 → 이벤트 완료 대기 → UnlockFrame 순서다. 반환 관리자는 잠긴 주소 집합과 반환 예약 목록을 가지며 전체 잠금 상한은 34개다.

정상 EOF → 남은 대기 프레임 FIFO 전달 → 종료 순서다. 오류는 호출자에 우선 전달한다. 취소 시 대기 프레임을 해제하고 작업자에서 입력을 정리한다.
