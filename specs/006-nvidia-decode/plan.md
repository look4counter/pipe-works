# 구현 계획: NVIDIA 비디오 디코딩

**명세**: [기능 명세](spec.md)

## 기술 배경

- `RTSPSource`는 `packet`, `video_stream`이 있는 `PipelineContext`를 만든다.
- `NvidiaDecode.process()`는 입력 반복자를 읽어 프레임별 새 컨텍스트를 반환한다.
- 현재 구현은 PyNvVideoCodec과 PyTorch CUDA 스트림을 사용한다.

## 설계

1. 설정에서 GPU 번호를 읽는다. 첫 입력에서 H.264와 HEVC 계열 코덱을 선택하고 CUDA 스트림 및 디코더를 만든다.
2. 입력 패킷을 바이트열로 복사해 디코더 입력 구조의 버퍼 주소와 길이를 채운다. PTS가 있으면 함께 넣는다.
3. CUDA 스트림 안에서 디코더를 호출한다. 반환된 프레임마다 새 `PipelineContext`를 만들어 비디오 스트림과 CUDA 스트림, 픽셀 형식을 포함한다.
4. 프레임이 없는 디코딩 호출은 출력하지 않는다.
5. 입력 반복자 종료 시 `Flush()`가 반환한 프레임을 같은 컨텍스트 계약으로 전달한다. 핫스왑 구간 경계에서 다음 디코더 실행이 새로 시작된다.

## 단계 계약

- **입력**: [입력 자료 모델](data-model.md)에 기술한 패킷 컨텍스트.
- **출력**: 프레임 단위 컨텍스트. [NVIDIA 인코딩 명세](../005-nvidia-encode/spec.md)의 입력 계약에 연결된다.

## 영향 파일

- `src/pipeworks/embedded/nvidia_decode.py`

## 검증

- 모의 디코더로 코덱 선택, PTS 전달, 프레임 개수별 출력, 출력 필드를 확인한다.
- 모의 디코더로 종료 시 지연 프레임 전달을 확인한다. 실제 GPU 동작과 네트워크 재연결 경계는 별도 실행 환경과 개선 작업이 필요하다.
