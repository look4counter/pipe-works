# 기능 명세: 감지 성능 리포트

**작성일**: 2026-10-09
**상태**: 명세 확정
**입력**: YoloDetectReport와 TensorRTReport를 만들어 두 감지 경로의 병목 구간을 확인한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 같은 기준으로 감지 경로 비교 (우선순위 P1)

운영자는 파이프라인에 해당 Report를 추가하고 전처리, 배치 큐 대기, 입력 결합, 모델 실행, 출력 복사, 후처리, 전체 감지 시간을 확인한다.

**독립 검증**: 알려진 구간 시간을 입력하여 각 Report의 평균과 단위가 일치하는지 확인한다.

**인수 시나리오**:

1. 단일 감지 실행 시 모델 실행과 NMS를 구분하여 출력한다.
2. 배치 감지 실행 시 큐 대기와 복사를 모델 실행 시간에 합산하지 않는다.
3. 샘플이 없는 구간은 0으로 오인하지 않도록 없음으로 출력한다.

### 사용자 이야기 2: 비동기 실행에서도 진단 유지 (우선순위 P2)

운영자는 감지 결과가 타임아웃되거나 입력이 건너뛰어져도 처리 상태와 작업자 완료 시간을 확인한다.

**독립 검증**: 별도 실행 범위와 작업자에서 기록한 값이 해당 리포트에만 표시되는지 확인한다.

**인수 시나리오**:

1. 완료, 간격 건너뜀, 작업자 바쁨, 타임아웃, 오류 건수를 구분한다.
2. 입력이 중단되어도 주기적으로 출력하고 종료 시 리포트 스레드를 정리한다.

### 경계 상황

GPU 완료 전 이벤트는 기다리지 않고 보류한다. 오류와 타임아웃은 성공으로 계산하지 않는다. 최근 기록은 시간과 개수로 제한한다. 여러 실행 및 두 종류 리포트의 통계는 분리한다.

## 요구사항

### 기능 요구사항

- FR-001: YoloDetectReport와 TensorRTReport는 입력 객체와 순서를 보존하는 공개 Step이어야 한다.
- FR-002: 두 경로는 전처리, 큐 대기, 입력 결합, 모델 실행, 출력 복사, 후처리, 전체를 동일한 의미로 측정한다. 해당하지 않는 구간은 없음으로 표시한다.
- FR-003: 구간별 CPU 경과 시간과 GPU 실행 시간을 구별하고 GPU 측정 때문에 추가 대기를 넣지 않는다.
- FR-004: 기본 1초 주기로 직전 구간 및 최근 10초 평균과 구간별 표본 수를 출력한다.
- FR-005: 완료, 간격 건너뜀, 작업자 바쁨, 타임아웃, 오류 건수를 출력한다. 타임아웃 후 작업 완료는 작업자 완료와 별도 상태임을 문서화한다.
- FR-006: 파이프라인 실행 범위별로 통계를 분리하고 공유 배치 작업자의 측정을 원래 호출 범위에 전달한다.
- FR-007: Report가 없는 경우 추가 GPU 이벤트를 생성하지 않는다. 기록은 제한된 메모리를 사용하고 처리 의미와 기존 StreamReport 통계를 보존한다.
- FR-008: 공개 가져오기, 예제 및 한글 사용 문서를 제공하고 모의 시간·이벤트 및 가능한 기존 테스트로 검증한다.

### 주요 개체

- 구간 표본: 경로, 구간, 완료 시각, CPU 시간, 선택적인 GPU 이벤트 쌍.
- 실행 통계: 경로별 활성 리포트 수, 제한된 최근 표본, 상태 건수.
- 배치 측정: 요청별 큐 대기와 배치 공통 구간 시간. 배치 시간은 요청별 지연이며 처리량당 비용이 아니다.

## 성공 기준

- SC-001: 알려진 전처리·추론·후처리 시간을 출력에서 각각 식별할 수 있다.
- SC-002: 두 실행의 표본과 상태가 서로 섞이지 않는다.
- SC-003: 완료되지 않은 GPU 작업 때문에 리포트가 기다리지 않는다.
- SC-004: 입력 전달과 기존 감지 결과가 유지되고 Report 종료 후 추가 출력이 없다.

## 가정과 명확화

기존 대화에서 측정 항목과 1초·10초 평균이 합의되었다. 추가 질문이 필요한 중대한 모호성은 없다. 모델 변경이나 병목 최적화는 이번 범위가 아니다. CPU 전체 시간은 감지 작업자의 시작부터 결과 완료까지이며 CudaAsync 대기 제한과 별도이다. GPU 구간은 CPU 구간에 포함되는 관측치이므로 합산하지 않는다.
