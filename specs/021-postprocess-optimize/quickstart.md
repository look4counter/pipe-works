# 검증 방법

`python -m unittest discover -s tests -p test_tensor_rt_postprocess_optimized.py`와 `python -m unittest discover -s tests -p test_tensor_rt_processing.py`를 실행한다.

CUDA 환경에서 `python tools/benchmark_postprocess.py --baseline 9d7a65ecd6f8f4ecbe9cc240a1c0edf5d2b8615e`를 실행한다. 기준 코드는 변경 전 Git 리비전의 예제 후처리를 사용한다.

## 성능 결과

2026-10-10, RTX 4070 Laptop GPU, Torch 2.2.1+cu121. 입력 (1,84,8400), 준비 10회, 측정 50회 중앙값, 실행 순서를 바꾼 3라운드 중앙값이다. 입력 복사는 제외하고 후보 선택·NMS·좌표 복원·래퍼 생성·완료 대기 전체를 측정한다.

| 합성 입력 | 클래스 설정 | 기존 경과 시간 | 변경 경과 시간 |
| --- | --- | --- | --- |
| 희소 점수 | [2] | 1.143 ms | 0.601 ms |
| 희소 점수 | 전체 | 0.910 ms | 0.529 ms |
| 밀집 점수 | [2] | 1.161 ms | 0.614 ms |
| 밀집 점수 | 전체 | 12.573 ms | 10.385 ms |

CUDA 이벤트도 유사한 시간을 보였으나 CPU 제출 공백·동기화가 포함되므로 순수 커널 계산 시간은 아니다. 실제 영상의 후보 수·GPU 경쟁·클럭에 따라 결과는 달라지며 기존 로그의 7.8ms가 동일 비율로 줄어든다는 보장은 없다.

기존 통합 테스트의 오래된 전처리 import를 현재 공개 클래스로 수정하여 좌표·NMS·GPU 입력 보존·오류 정리·실제 엔진 처리 검증을 재사용한다.

최종 검증: 신규 참조 테스트 4개(CPU/CUDA·클래스 필터·빈 결과·최대 후보·임계값·동점·좌표), 통합 테스트 6개, 리포트 테스트 14개가 모두 통과했다. 리포트 테스트도 같은 오래된 import를 현재 공개 클래스로 갱신했다. 오류 처리 테스트에서 의도적으로 출력되는 로그는 테스트 실패가 아니다. `git diff --check`도 통과했다.

수렴 재검토: FR-001~005, SC-001~003과 설계 결정의 미완료 작업은 없다.
