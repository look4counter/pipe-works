# 조사 기록: Conductor 콘솔 및 프로세스 관리

- **현재 관찰**: 정적 UI와 FastAPI가 프로세스 설정 CRUD와 일괄 상태 조회를 제공하며, `Database`는 SQLite에 정의를 저장한다. `Supervisor`는 psutil로 OS 명령행을 조회하고 일치 프로세스 트리를 `taskkill`로 종료한다.
- **결정**: DB에는 프로세스 정의만 저장하고 PID를 실행 상태의 근거로 사용하지 않는다. **근거**: Conductor 재시작 뒤에도 OS 프로세스의 `process_id` 인자를 기준으로 재탐색한다.
- **결정**: 관리 대상은 `python.exe` 또는 `pythonw.exe`에서 `-m pipeline.cli --process-id <id>` 형태로 실행된 프로세스다. **근거**: 관련 없는 Python 프로세스를 종료하지 않도록 명령행 인자를 확인한다.
- **결정**: 기본 제공은 Windows 로컬 단일 사용자 환경이다. **근거**: 프로세스 트리 종료에 `taskkill`을 사용하고 인증 기능은 없다.
- **결정**: 자동 복구는 사용자가 시작한 프로세스만 대상으로 한다. **근거**: Conductor 시작만으로 프로세스를 띄우지 않으며, `auto_start`는 실행 중인 프로세스의 재시작 여부만 제어한다.
- **결정**: 파이프라인 로그와 프레임 통계는 별도 WebSocket 경로로 전달한다. UI 구독자는 프로세스별 로그 최근 기록과 통계를 받으며, 파이프라인 로그 네트워크 송신은 bounded queue를 쓰는 전용 스레드에서 수행한다.
