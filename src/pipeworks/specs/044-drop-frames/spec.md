# 기능 명세: 프레임 선택 및 폐기

작성일: 2026-10-18

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 공통 앞단에서 프레임 선택 (우선순위: P1)

사용자는 추론과 인코딩 앞에 `DropFrames(keep_every=2)`를 배치하여 두 단계가 동일한 프레임을 처리하도록 한다.
독립 검증: 입력 0~5에서 출력 0, 2, 4만 같은 객체로 전달된다.

인수 시나리오:
1. 간격 2에서 입력 6개를 처리하면 첫 프레임부터 3개만 전달한다.
2. 기본 간격 1에서는 모든 입력을 그대로 전달한다.
3. 같은 인스턴스의 새 처리 호출은 다시 첫 프레임부터 선택한다.

### 경계 조건

빈 입력은 빈 출력이며 입력 수보다 큰 간격은 첫 프레임만 남긴다.
간격으로 0, 음수, 소수, 불리언, 문자열은 허용하지 않는다.

## 요구사항

- FR-001: `pipeworks.embedded`에서 `DropFrames`를 가져올 수 있어야 한다.
- FR-002: `keep_every`는 기본값 1인 양의 정수이며 생성자와 공통 설정 방식으로 지정할 수 있어야 한다.
- FR-003: 0부터 센 입력 순번이 간격의 배수인 프레임만 전달하고 나머지는 폐기해야 한다.
- FR-004: 선택된 입력의 객체, 순서, 메타데이터를 보존하며 새 처리 호출에서 순번을 초기화해야 한다.
- FR-005: 잘못된 간격은 처리 전에 한국어 메시지의 `ValueError`로 거부해야 한다.

## 성공 기준

- SC-001: 간격 2, 입력 6개에서 정확히 0, 2, 4번이 전달된다.
- SC-002: 기본값에서는 입력 수와 출력 수 및 객체가 동일하다.
- SC-003: 선택된 프레임은 이후 모든 단계에 같은 순서로 전달된다.

## 가정 및 명확화

대화에서 이름, 첫 프레임 선택, 간격의 의미가 확정되어 추가 질문이 필요하지 않다.
이 단계는 시간 정보와 FPS를 수정하지 않는다. 출력 FPS 설정은 사용자가 맞춘다.
NvidiaEncode 및 EveryNFrames 변경은 범위에 포함하지 않는다.
실행 검증에는 자동 회귀 검증을 포함한다.
